# 第1章\_全仓教材重构执行记录

2026-09-21，开发者把原 Linux 正文分批重构扩展到整个仓库，允许按已确认的教材标准持续推进，不因文件数量增加而降低深度。近期已讲清楚的文档作为质量参照，实际审查后保留；不能为了显示修改量把它们重新生成。

## 1.1\_范围与恢复入口

逐文件工作清单保存在 [textbook_refactor_inventory.json](textbook_refactor_inventory.json)，初始覆盖 471 篇当前 Markdown，包括本轮未提交的正文和 skill 同步成果。`baseline_sha256` 对应本轮开始时的工作文件，不能以 Git HEAD 覆盖此前未提交成果。原始工作文件快照位于被 Git 忽略的 `.cache/repository_textbook_refactor/baseline/`，只用于核对内容去向，不是第二套正文。

清单状态只表示 AI 工作进度：`pending` 为尚未完成本轮逐篇审查与必要重构，已经局部冷读或修复的范围写入该项 reason；`supporting_pending` 为须按导航、治理、运行规则或出版职责审查，`rewritten_pending_validation` 为改写后尚待验证，`validated` 为完成本轮适用检查，`retained` 为逐篇审查后保留并说明依据。这些状态不表示人工评审完成；人工结论仍只在 [阅读评审地图](../../atlas/maps/knowledge_review_map.md)中维护。

Linux 主线继续使用 [阅读依赖与批次](../../atlas/roadmaps/linux_textbook_refactor.md#1.2_全量阅读依赖与批次)。全仓扩展还覆盖基础、工程、平台、实验、研究和工具文档：先建立其读者任务，再决定教材重写、实验解释补足、证据校正或入口维护。源码副本、图片与已发布电子书不是可随意改写的正文；只有真实受影响时才同步支持材料。外部 Linux 树始终只读，官方固定提交与本地实验提交分开。

每次续接先检查工作树、Codex skill 主源差异、本记录和清单中的进行项。不要反复从全仓搜索开始，也不要把批量脚本发现的候选问题直接等同于实际缺陷。完成一组后记录正文变化、信息去向、检查范围、局限与下一组，再推进。

## 1.2\_本轮标准与保护范围

实际正文必须形成可连续阅读的解释：场景、旧认识、需要增加的新概念、运行过程、实例、观察、练习与解答各自承担清楚职责。完整性按全书前置关系保证，避免每篇重新教授所有前提。查询页、规范与工作记录不强制套用教学故事。

有效知识点、用户批注、代码的关键行为和版本边界先盘点再处理。合并重复教程时标明唯一目的位置；不能因为两个标题相似就删除。源码导航与知识正文承担不同阅读任务，不做跨层压缩。保持 Markdown 身份和相对链接；必要的迁移同步真实调用方、地图和编排清单。无人回复不阻止已经授权的批次继续。

2026-09-22 开发者更新交付授权：每完成一个完整批次，先全量同步真实受影响的信息并验证，再提交、普通推送远端，随即继续下一批，直到全仓处理完成。下文早期批次中的“不暂存、不提交、不推送”保留为当时执行记录，不再作为后续限制。`.obsidian/workspace.json` 是任务开始前已有的末尾换行差异，不属于本轮链接变更，继续保留且不夹入教材提交。
