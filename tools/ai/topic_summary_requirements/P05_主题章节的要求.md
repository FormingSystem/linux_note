# 第5章\_主题章节的要求

## 5.1\_当前阅读与写作边界

本仓库不默认读者懂专题中的模块、分类、平台、架构和代际。每个对象进入讲解时，先说明它是什么、为何需要、与谁相连、处于哪一层，以及和相邻对象按什么依据区分；第一套实现先独立讲通，后续实现由新问题引出，最后才比较。只补英文全称或开篇放一张代际表，不算完成从零铺垫。

专题应当既是 **独立的概念讲解**，也是 **官方文档的阅读指导**：不打开手册，仍能从正文理解设计、过程与边界；需要深挖时，能从关键解释旁的引用找到官方文档的名称、版本、章节号和原文目录标题，并知道该去核对什么。不能只在文末列一份资料清单，也不能用链接替代本地解释。具体方法与双路径验收见 [独立讲解与官方资料溯源](../codex/skills/build-linux-note-topic/references/topic-design.md#13-独立讲解与官方资料溯源)。

面向读者的章节文件使用 `PXX_中文主题.md`，便于直接从文件列表辨认内容，保留必要技术标识，不翻译稳定 ID、英文目录或官方文件名。每篇可独立阅读章节的术语首次定义整体突出为 **中文名（English Full Name，ABBR）**；没有通行缩写时省略缩写项，产品型号和源码标识符不编造全称。后续不必每次重复展开或加粗，排版操作不得改变代码与图表语法。

当前通用方法见[专题结构从零建立](../codex/skills/build-linux-note-topic/references/topic-design.md#12-让专题结构本身也从零建立)，题型裁剪和历史条款的适用范围见[仓库专题要求](../codex/skills/build-linux-note-topic/references/repository-topic-requirements.md#11-不应提升为通用硬规则的历史要求)。下节保留原书稿模板供对应场景选择，固定结构、示例节点和工具版本不作为所有新专题的默认前提。

### 5.1.1\_按题型选择的书稿模板

1. **分批输出原则**
   - 如果内容一次写不完，必须分批次输出。
   - 每一批都要是“完整的小节”，不能只给提纲。
   - 批次末尾标注“（未完待续）”或说明后面还有 12.x。
2. **结构固定（书稿级）**
    每一章/大节按这个顺序写：
   1. 章节引入 / 背景 / 本章目标
   2. 数据结构视角（内核里是哪几个 struct / 域 / 描述符）
   3. 开发者视角（驱动怎么写、probe 怎么下、exit 怎么退、devm 版本要写）
   4. 用户/平台视角（DTS/ACPI 怎么配、不写的后果、常见错误）
   5. 可视化图示（Mermaid 必须可在 Typora 渲染）
   6. 示例代码（能直接粘到驱动/内核里跑的模板，C 为主）
   7. 调试与验证（dmesg、/proc/interrupts、sysfs、常见坑）
   8. 小结（和前后章节的勾连：比如和层级中断/PM/多核的关系）
3. **Mermaid 特殊要求**
   - 保证能在 Typora (11.9+) 渲染。
   - 若语句复杂，用 `"` 包外层，内部统一用 `"`。
4. **语法讲解必须“四连问”**
    每遇到一个 DTS 属性 / 一个内核接口 / 一个语法，必须说明：
   - 它的**作用**是什么；
   - **使用场景**是什么；
   - **不写/写错的后果**是什么；
   - **在驱动里的使用逻辑/落点**是什么。
5. **devres 必须带上**
   - 讲中断、GPIO、clk、pinctrl、MSI、irq_domain 时，都要同时说非 devm_ 和 devm_ 的版本；
   - 要说明 devm_ 的释放逻辑、适用场景、和老接口的区别；
   - 不是让一律用 devm_，而是必须“讲到”。
6. **不要用比喻**
   - 解释要用严格技术表述：定义、流程、边界、示例；
   - 不用生活类比、不用形象化说法。
7. **和前面章节保持口径**
   - 中断相关要能和你前面第3章（irq_domain）、第5章（GPIO/触发）、第9章（层级域）、第11章（PM/唤醒）对上；
   - 中断类内容按本次目标分别确认芯片、控制器实现、架构版本和软件基线，不设跨专题通用的平台默认值；当前独立 GIC 专题按 [RK3588 优先路线](../../../atlas/roadmaps/gic_learning_plan.md#1.2_从零开始的阅读地图)先学习 GIC-600 r1p6 / GICv3.0，不把 i.MX6ULL、GICv2 或 GICv4 当作前置；
   - 举 DTS 例子时优先用你之前说的 `demo_led_key_int@0` 那个节点做参考。
8. **可直接入书**
   - 用出版风格中文标题：`第12章 …` → `12.1 …` → `12.1.1 …`
   - 段落完整、表格清晰、代码高亮、可以直接贴进 Typora/WPS。
