# 专题审查清单

## 编辑权限与内容保护

- [ ] 已选择仅排版、保留内容的结构调整或内容修改/重写模式，并且与用户本次授权一致。
- [ ] 没有让单独出现的“重构”自动决定编辑模式；已结合“已审稿、只排版”或“补充、重写”等限定语判断。
- [ ] 已把任务开始时的工作树作为内容基线，其中包括目标范围内未提交的修改。
- [ ] 仅排版任务中，每个原有 H2/H3 章节、代码块、Mermaid 图、表格、实验、检查清单和链接都有记录好的目的位置。
- [ ] 仅排版工作保留技术语义和全部信息单元；编号、空白、列表、表格、导航和锚点等机械变化已经记录，统计量没有无法解释的减少。
- [ ] 没有把严格行级审计警告直接当成内容丢失，也没有把审计警告当成修改技术语义的权限；已逐项核对差异。

## 信息架构

- [ ] 已依据仓库 AI 专题要求判断题型并选择章节骨架，没有叠加互相冲突的历史模板。
- [ ] 创建、扩写或重写时先完成专题设计账本，再生成正文；仅排版时使用内容账本而不重新推导技术模型。
- [ ] 章节角色依据证明边界和阅读连续性选择，没有复制 RCU 的篇数或为空缺职责建立章节。
- [ ] 大纲呈现因果学习链，而不是名词索引。
- [ ] 每章都有前置结论、本章问题、新增模型、输出结论、证据和下一个未决问题。
- [ ] 章节之间由未决问题继续推动，不是只按文件编号并列。
- [ ] 稳定知识、带版本的源码证据、实验、平台内容和导航保持分离。
- [ ] 每种可复用机制只有一份权威正文。
- [ ] 通用硬件或编译器材料链接到独立的权威专题。
- [ ] 拆分或移动内容遵循已授权模式；只有用户明确要求时才清理重复内容。

## 场景与解释

- [ ] 章节明确了真实负载、参与者、共享状态和约束。
- [ ] 语法、接口或配置项适用时，已说明作用、场景、错误或省略后果以及实现落点。
- [ ] 在说明旧方案局限前，先解释它的正确性价值。
- [ ] 故障以有序因果链或交错过程展示。
- [ ] 每轮推演只增加解决当前反例所需的状态、通信路径或约束，没有提前倾倒成熟实现的全部术语。
- [ ] 章节开头回收已有结论并提出新缺口，结尾给出本章新结论和下一步未决问题。
- [ ] 问题章用足以固定现场的代码支撑推演；完整应用代码覆盖分配、发布、失败、清理和拆除。
- [ ] 除明确标记为源码引用的代码块外，示例代码注释均为中文。
- [ ] 性能结论明确缓存行、所有者、操作、传播过程和可观察后果。
- [ ] 不把安全性、活性、内存压力和时延压缩成一个“性能”结论。
- [ ] 替代方案使用同一场景比较，并以可操作的选择条件结束。

## 状态与通信

- [ ] 文档说明机制是单一状态机还是多个正交状态轴。
- [ ] 当前状态、锁存事件、代际证据和等待债务没有混为同一个状态。
- [ ] 正文、表格、图、分支和源码证据复用同一组 S0…Sn 周期。
- [ ] 每项状态都有存储地址、所有者、写入者、读取者、触发条件和退出条件。
- [ ] 任务或设备存在、进入路径、取得入口、持有对象和退出保护范围等阶段已经区分。
- [ ] 当前周期的参与集合具有明确时间边界，未来参与者为何不进入旧集合已有证明。
- [ ] 明确说明本地状态如何转为共享状态。
- [ ] 明确说明局部证据如何汇聚为全局结论。
- [ ] 明确说明完成结论如何传递给等待者或回调。
- [ ] 已区分直接登记/通知与通过不变量和已观察事件形成的间接证明。
- [ ] 区分正常、特殊、延迟/强制和诊断路径。
- [ ] 至少有一张角色关系图和一张端到端时序图，且箭头带有说明。
- [ ] 图中实际调用、异步状态传播和逻辑因果没有伪装成同一种函数调用。
- [ ] Mermaid 使用 `<br/>`，不使用 `\n`。

## 源码证据

- [ ] 已记录内核版本和相关配置。
- [ ] 关键结论能够串起抽象不变量、源码落点、边界标签和可观察证据四层证据链。
- [ ] 正确标记通用结论、配置特有结论、体系结构特有结论和厂商结论。
- [ ] 每个重要字段都检查了声明、初始化、写入者和读取者。
- [ ] 没有把函数存在误认为当前配置中存在有效调用路径。
- [ ] 保留异步窗口，没有将其压缩。
- [ ] 旧版本差异明确指出变化的字段、状态位置或调用链。
- [ ] 外部源码树保持只读。
- [ ] 保存的源码副本与声明来源一致。

## 生命周期与拆除

- [ ] 已枚举正式发布入口，并全部撤销。
- [ ] 临时访问、长期引用、宽限期、回调完成和最终释放彼此区分。
- [ ] 每次分配只有一个最终销毁协议。
- [ ] 独立机制之间通过明确的模块回调或所有权转移连接。
- [ ] 覆盖指针逃逸、工作线程生命周期、回调和模块卸载。
- [ ] 错误清理不会对从未发布的对象使用退休路径。

## 仓库完整性

- [ ] 文件和目录名符合仓库规范。
- [ ] Front Matter 具有稳定的 `id`、`title`、`kind`、`status` 和 `domains`。
- [ ] H1/H2/H3 编号正确，标题中的下划线已转义。
- [ ] 大纲以及上一篇/下一篇导航与真实顺序一致。
- [ ] 适用时已更新 Atlas、出版清单、Obsidian 产物、源码映射和外部专题链接。
- [ ] 旧文件名和废弃 ID 不再有残留调用方。
- [ ] 相对链接均可解析。
- [ ] 不存在重复文档 ID。
- [ ] Mermaid 能通过仓库渲染器解析。
- [ ] 所需目标环境存在时，实验能够编译并运行；否则已说明缺少的验证。
- [ ] 仓库检查和 `git diff --check` 通过。
- [ ] 无关脏文件保持不变。
