# 重构、验证与交付

本技能的每项任务交付前都必须完整阅读并执行本文件。路径调整、仅排版守恒、源码哈希、构建与实验仍按各条明确的适用条件执行；未触发的条件不额外扩大任务。

## 干净重构

章节顺序或路径发生变化时：

1. 先记录所选编辑模式和内容基线；
2. 移动前盘点每个 H2/H3 章节、代码块、图表、表格、实验、检查清单和链接；
3. 将每个属于保留范围的内容单元映射到一个目的位置，不得因为另一段内容看起来相似就删除；
4. 仅排版模式保留文件身份、技术语义和全部信息单元；允许记录在案的机械排版变化，不要求字节或正文行绝对不变；
5. 保留内容的结构调整模式完整移动单元，除非桥接内容必须变化，否则保留原措辞；
6. 内容修改或重写模式只修改明确授权的内容；
7. 更新专题大纲和上一篇/下一篇导航链；
8. 更新 Markdown、Obsidian、Atlas、出版清单、源码映射和其他真实调用方；全量信息同步时使用 [源码与正文入口的分层审计要求](source_documentation_workflow.md#用模块概念导读和唯一实现讲解关联正文)，并记录不存在的调用方为无须修改；
9. 全仓搜索旧文件名和旧 ID；
10. 确认没有覆盖无关脏文件或已审内容。

编辑使用 `apply_patch`。除非用户明确要求，不得暂存、提交，也不得修改外部源码树。

## 交付前验证

先统计本轮 Markdown 文档长度，超过阈值的逐篇审查；按 [主入口的长度规则](../SKILL.md#以讲清楚为完成条件)，结合完整实验、必要代码、连续推导或轻微超出等实际情况决定保留或拆分，并记录理由。脚本的 OVER 表示待判断，不自动等于交付失败：

```text
python <skill-dir>/scripts/audit_document_length.py <file-or-directory> ...
```

先运行内置结构审计：

```text
python <skill-dir>/scripts/audit_topic.py <topic-directory> --repo-root <repository-root>
```

对本次创建、扩写或重写的每篇章节运行连续阅读风险审计：

```text
python <skill-dir>/scripts/audit_reader_continuity.py <chapter.md> --strict
```

该脚本只能发现链接主导、标题回声、空小节、源码标题失约和超长模块等可机械观察的风险，**脚本通过不能替代 [正文冷读硬门禁](reader_first_writing.md#执行反形式主义与连续阅读硬门禁)**。严格模式报告的问题必须修改，或者在交付说明中给出与读者任务直接相关的具体保留理由；不能以“规则要求链接完整”作为理由。

随后运行术语首次出现审计，取得缩写、配置名和反引号源码标识符的候选账本：

```text
python <skill-dir>/scripts/audit_terminology_onboarding.py <chapter.md> --strict
```

该脚本只检查可机械识别的候选词、首次出现位置和附近是否具有中英文展开或名称类型信号；它看不懂术语是否解释正确，也无法发现所有专题私有昵称。严格模式报告的问题必须补齐，或者逐项给出“为何不是术语、为何当前窗口已经完成解释、为何属于明确建立并已回顾的前置知识”的具体理由。不可为消除窗口式警告，在每章重塞全称和定义而破坏阅读。脚本通过以后仍要人工检查新概念是否依赖未解释的词，以及读者是否获得当前推理所需的认识。

对具有干净 Git 基线的仅排版任务，还要运行内置内容守恒审计：

```text
python <skill-dir>/scripts/audit_content_conservation.py <topic-directory> --repo-root <repository-root> --baseline <baseline-ref>
```

如果任务开始时已有未提交的审定材料，应另行保存修改前快照或内容账本，因为仅使用 `HEAD` 不能代表该基线。记录修改前后的行数、标题数、代码围栏数、表格数和 Mermaid 图数，并证明每个属于保留范围的内容单元都有目的位置。内容守恒脚本执行严格的行级对比：失败表示存在需要人工核对的差异，不自动等同于技术内容丢失。排版必需的机械变化可以逐项说明并接受；超出授权的语义变化、无法解释的信息减少或遗漏才视为错误。随后在运行环境可用时，执行仓库自身的格式化、元数据/链接检查、针对性构建或实验编译，以及 `git diff --check`。条件允许时使用仓库渲染器解析 Mermaid。只有源码证据属于本次范围时才检查源码副本哈希。

所需环境不可用时，完成全部安全的静态检查，并准确报告未执行验证及其原因。不得把未编译的实验或未渲染的图表描述为已执行。

## 按结果交付

报告：

- 新的因果阅读路径；
- 零基础读者入口、术语依赖顺序和仍需人工确认的私有命名；
- 所选编辑模式和内容守恒计数；
- 本次范围内实际发生的场景、状态机、源码和实验变化；
- 本轮涉及外部图表时，图表覆盖台账、正文落点与未覆盖项；
- 移动或重命名后的权威位置以及已更新的调用方；
- 已通过的验证；
- 未执行的验证及其原因；
- 是否进行了暂存或提交。

最终回复应短于专题本身。链接到大纲和少量代表性文件，不要罗列每个修改文件。
