# 专题审查清单

## 编辑权限与内容保护

- [ ] 已选择仅排版、保留内容的结构调整或内容修改/重写模式，并且与用户本次授权一致。
- [ ] 没有让单独出现的“重构”自动决定编辑模式；已结合“已审稿、只排版”或“补充、重写”等限定语判断。
- [ ] 已把任务开始时的工作树作为内容基线，其中包括目标范围内未提交的修改。
- [ ] 仅排版任务中，每个原有 H2/H3 章节、代码块、Mermaid 图、表格、实验、检查清单和链接都有记录好的目的位置。
- [ ] 仅排版工作保留技术语义和全部信息单元；编号、空白、列表、表格、导航和锚点等机械变化已经记录，统计量没有无法解释的减少。
- [ ] 没有把严格行级审计警告直接当成内容丢失，也没有把审计警告当成修改技术语义的权限；已逐项核对差异。

## 信息架构

- [ ] 已依据仓库 AI 专题要求判断题型并选择章节骨架，没有叠加互相冲突的历史模板。
- [ ] 创建、扩写或重写时先完成专题设计账本，再生成正文；仅排版时使用内容账本而不重新推导技术模型。
- [ ] 工作型专题蓝图已经覆盖完整章节依赖和每章契约；仓库正式大纲只链接已经落地的真实文件。
- [ ] 已明确读者起点、默认误解、完成结果和主题在系统中的上下游位置。
- [ ] 专题同时具有公共契约和多个家族/配置/执行模型时，已先区分保护域、实现家族、执行模型、运行策略与诊断等正交分类轴。
- [ ] 分类坐标和公共端到端骨架早于第一个变体内部实现；读者能够先说清“什么不变”，再进入“哪里不同”。
- [ ] 已建立模块 × 变体矩阵，并说明为何选择按模块比较或按变体纵切；公共执行者、状态载体和完整周期没有跨变体重复讲解。
- [ ] 只有改变大部分参与者集合、证明方式、控制流和完成条件的变体才独立纵切；局部配置差异留在对应模块内并列比较。
- [ ] 每个实验能够回指一个明确的模块结论、变体差异或证明义务，实验目录没有与正文推理脱节。
- [ ] 章节角色依据证明边界和阅读连续性选择，没有复制 RCU 的篇数或为空缺职责建立章节。
- [ ] 大纲呈现因果学习链，而不是名词索引。
- [ ] 每章都有前置结论、本章问题、新增模型、输出结论、证据和下一个未决问题。
- [ ] 章节之间由未决问题继续推动，不是只按文件编号并列。
- [ ] 稳定知识、带版本的源码证据、实验、平台内容和导航保持分离。
- [ ] 每种可复用机制只有一份权威正文。
- [ ] 通用硬件或编译器材料链接到独立的权威专题。
- [ ] 拆分或移动内容遵循已授权模式；只有用户明确要求时才清理重复内容。

## 连续阅读与反形式主义硬门禁

以下各项是语义验收，不得因为结构审计、链接检查或源码覆盖账本通过而跳过：

- [ ] **标题契约已经兑现：** 标题承诺的读者任务与正文职责一致；标题包含“源码实现、源码讲解、源码机制”时，当前文件确实逐模块讲解实现原理、输入输出、关键状态和本地源码证据，而不是链接导航。
- [ ] **首屏已经建立任务：** 在源码文件清单、版本台账和密集链接以前，读者已经知道前置结论、当前现场、剩余问题、本章边界和读完后的可检验结果。
- [ ] **断链阅读能够成立：** 不点击任何链接时，读者仍能从当前正文理解基础概念、背景问题、解决方案、关键状态转换、完成条件和本章结论；链接只增加证据或纵深。
- [ ] **链接没有承担首次解释：** 每个外链概念、模块或源码符号在链接以前已经完成当前场景所需的最小本地解释，没有使用“详见”“统一见”“先进入另一篇”替代主叙事。
- [ ] **每个主要模块已经局部闭环：** 依次建立概念与类型、当前问题、解决方案和状态通信、读者预测或反例、实现验证或源码证据，并把新结论交给下一个模块。
- [ ] **术语已经按类型分层：** 抽象概念、请求对象、执行角色、状态载体、流程阶段、配置变体、优化分支和诊断机制没有在同一层并列倾倒。
- [ ] **默认主线先于分支：** 一个明确配置下的正常路径已经完整闭合；优化、版本差异、慢路径、诊断和其他执行模型没有穿插打断主线，也没有提前公布下一章的模型增量。
- [ ] **每种表示都有独立任务：** 关系图、时序图、状态表、源码摘录和证据索引分别回答不同问题；没有把同一流程重复改写成多套表图以满足形式数量。
- [ ] **标题层级承担真实任务：** H2 没有复述 H1，也没有在缺少承上启下正文时直接进入下一个标题；不存在空标题或只为凑层级建立的伞形小节。
- [ ] **冷读者能够复述：** 不看工作蓝图、不点击链接，可以用五到八句话复述“前置结论 → 本章问题 → 模块增量 → 完成条件 → 后续缺口”；复述结果不是文件名、字段名或链接列表。
- [ ] **要素齐全没有被当作完成证据：** 场景、S0～Sn、Mermaid、源码链接、版本边界和核对表的存在，只证明材料存在，不单独证明讲解合格。

## 零基础术语与名称对齐硬门禁

以下任一项失败，都表示读者还没有获得进入概念所需的语言，不能继续用分类表、图或源码纵深掩盖：

- [ ] **读者基线明确：** 默认读者具备一般计算机基础，但不认识当前专题的缩写、源码黑话、实现家族名、配置私称和历史昵称；没有把“前章讲过”“官方这样写”或“开发者都知道”当作免解释理由。
- [ ] **术语依赖账本已闭合：** 已记录原始写法、中英文名称或名称性质、类型、朴素定义、当前职责、前置词、易混项、边界、首次出现和精确入口，并按依赖顺序进入正文。
- [ ] **首次出现范围完整：** H1/H2、可见导航、正文、脚注、表格、Mermaid、图片说明、代码与注释、配置、命令、日志和错误消息均已检查；没有任何名称先使用、后解释。
- [ ] **每章中英文对齐：** 每篇可独立阅读章节中，英文缩写第一次出现时都给出正式 English Full Name 和准确中文名；命令、项目、实现家族、历史昵称和源码标识符则明确为专名/标识符，不杜撰全称。
- [ ] **术语类型对齐：** 已说明名称属于概念、契约、角色、状态、阶段、实现家族、执行模型、策略优化、诊断设施、配置项、源码宏/函数/字段、语法、格式、产物还是工具；不同轴名称没有直接并列比较。
- [ ] **朴素定义先于精确定义：** 首先使用已经对齐的普通语言回答“它到底是什么”，没有用更多未解释缩写、内部字段或专题黑话循环定义。
- [ ] **当前职责和状态落点清楚：** 已说明该词在贯穿场景中为何出现、由谁拥有或使用、接收/读取什么、修改/输出什么、何时生效；涉及专题私有状态时还说明了保存位置和所有权。
- [ ] **边界和易混项清楚：** 已说明不能保证什么、最容易与谁混淆、按哪条分类轴区分，以及版本、架构和 Kconfig 边界。
- [ ] **私有命名已经解码：** 普通英文词一旦被子系统赋予特殊含义，已说明命名主体、作用域、对应概念或实现对象，以及它与通用词义的关系。
- [ ] **本地解释与链接各守职责：** 当前章节已经提供不断线的最小解释，完整教程或版本证据使用相对路径和完整标题锚点；没有用模糊文件链接代替首次解释，也没有用一句本地释义冒充权威纵深。
- [ ] **密集术语先集中进入：** 同一小节连续引入多个陌生词时，术语入口位于第一个词以前并按依赖分组；表格和图内私有名称已经在紧邻正文对齐或直达完整解释标题。
- [ ] **冷读抽查通过：** 随机指向标题、表格、图、代码或日志中的名称，读者无需外部搜索即可说出中英文名称或名称性质、所属类型、当前职责、边界和深入入口，解释过程中不会继续追问一串新词。

## 场景与解释

- [ ] 专题开端先回答“是什么、解决什么、位于何处、与谁交互”，没有一开始陷入 API、寄存器或源码。
- [ ] 说明型章节先回收前置结论，再用结构完整的代码、配置、日志、调用路径或操作现场固定读者的实际遭遇，没有从标题直接跳入定义、字段、API 或分类表。
- [ ] 章节背景已经暴露现有模型仍无法回答的具体问题，定位本章所在层次，限定讲解边界，并用读者完成后可执行的动作声明结果；背景不是术语摘要或空泛的重要性说明。
- [ ] 本节使用的术语已经通过上面的“零基础术语与名称对齐硬门禁”，场景解释没有重新引入未登记的私有名称。
- [ ] 章节明确了真实负载、参与者、共享状态和约束。
- [ ] 语法、接口或配置项适用时，已说明作用、场景、错误或省略后果以及实现落点。
- [ ] 在说明旧方案局限前，先解释它的正确性价值。
- [ ] 故障以有序因果链或交错过程展示。
- [ ] 每轮推演只增加解决当前反例所需的状态、通信路径或约束，没有提前倾倒成熟实现的全部术语。
- [ ] 章节开头回收已有结论并提出新缺口，结尾给出本章新结论和下一步未决问题。
- [ ] 问题章用足以固定现场的代码支撑推演；完整应用代码覆盖分配、发布、失败、清理和拆除。
- [ ] 标为完整实例的内容已经闭合需求背景、环境边界、输入与初始化、正常与失败路径、清理/退出、逐步过程、执行或观察方法、预期结果和证明边界；不完整材料明确标为现场片段或裁剪示例。
- [ ] 除明确标记为源码引用的代码块外，示例代码注释均为中文。
- [ ] 性能结论明确缓存行、所有者、操作、传播过程和可观察后果。
- [ ] 不把安全性、活性、内存压力和时延压缩成一个“性能”结论。
- [ ] 替代方案使用同一场景比较，并以可操作的选择条件结束。
- [ ] 容易误解的关键结论完成“错误模型为何看似成立 → 具体反例与矛盾 → 最小修正 → 正确模型 → 剩余缺口”的闭环。
- [ ] 选择了主题所需的概念、数据结构、状态机、时序、CPU/线程、调用者、源码、硬件或部署视角，并让各视角复用同一组对象、阶段和事件。
- [ ] 已明确区分定义与实现、API 与内部机制、逻辑状态与具体字段、软件同步与硬件能力、稳定模型与版本实现，并解释层间映射。
- [ ] 关键机制展示了转换前、触发动作、中间传播、完成条件、转换后和失败分支，没有只罗列静态定义。
- [ ] 数据结构/API 题型在最小契约成立后先给出正确使用闭环，再进入内部算法；算法题按需包含朴素方案、选择理由、复杂度、隐藏边界和变形。
- [ ] 硬件/协议题型围绕一次完整事务连接信号、时序、寄存器、驱动与板级约束，没有照手册目录复述。
- [ ] 工程题型已纳入资源预算、构建或镜像布局、部署、故障恢复、可观测性和目标环境限制。

## 状态与通信

- [ ] 文档说明机制是单一状态机还是多个正交状态轴。
- [ ] 当前状态、锁存事件、代际证据和等待债务没有混为同一个状态。
- [ ] 正文、表格、图、分支和源码证据复用同一组 S0…Sn 周期。
- [ ] 每项状态都有存储地址、所有者、写入者、读取者、触发条件和退出条件。
- [ ] 任务或设备存在、进入路径、取得入口、持有对象和退出保护范围等阶段已经区分。
- [ ] 当前周期的参与集合具有明确时间边界，未来参与者为何不进入旧集合已有证明。
- [ ] 明确说明本地状态如何转为共享状态。
- [ ] 明确说明局部证据如何汇聚为全局结论。
- [ ] 明确说明完成结论如何传递给等待者或回调。
- [ ] 已区分直接登记/通知与通过不变量和已观察事件形成的间接证明。
- [ ] 区分正常、特殊、延迟/强制和诊断路径。
- [ ] 至少有一张角色关系图和一张端到端时序图，且箭头带有说明。
- [ ] 图中实际调用、异步状态传播和逻辑因果没有伪装成同一种函数调用。
- [ ] Mermaid 使用 `<br/>`，不使用 `\n`。

## 源码证据

- [ ] 已记录内核版本和相关配置。
- [ ] 关键结论能够串起抽象不变量、源码落点、边界标签和可观察证据四层证据链。
- [ ] 正确标记通用结论、配置特有结论、体系结构特有结论和厂商结论。
- [ ] 每个重要字段都检查了声明、初始化、写入者和读取者。
- [ ] 已建立源码符号覆盖账本；源码摘录、调用链、阶段表和图中影响控制流、状态、同步、配置或生命周期的符号均有当前讲解、精确权威链接或有理由的裁剪说明。
- [ ] 交叉专题先判定了实现所有权：通用框架只展开一次，子系统实例、参数、接入时序、配置退化和消费场景在子系统专题完整说明并回链框架实现。
- [ ] `extern` 声明、全局实例、静态 key、初始化器、辅助包装、关键参数、配置退化分支和回调上下文标记没有成为只出现不解释的沉默符号。
- [ ] 没有把函数存在误认为当前配置中存在有效调用路径。
- [ ] 保留异步窗口，没有将其压缩。
- [ ] 演示代码附近具有接口或检查点清单，并说明作用、上下文、误用后果和版本化源码讲解。
- [ ] `navigation/` 包含一个总阅读索引和按子功能/模块组织的源码概念导读，`source_explanations/` 只放具体宏、函数和字段的实现讲解。
- [ ] 总阅读索引链接全部真实存在的模块概念导读；模块导读讲清职责、状态、调用链和阅读顺序，但没有逐段展开上游宏体或函数体。
- [ ] 同一版本的同一宏、函数、字段或配置分支只有一个权威源码讲解标题，其他正文和调用链只链接它。
- [ ] 知识正文进入源码材料时依次链接总阅读索引和相关模块导读，遇到具体接口时直接链接唯一源码实现标题。
- [ ] 每个接口使用 `相对路径.md#完整标题` 直接跳到对应源码小节，没有只链接文件让读者二次查找。
- [ ] 源码实现讲解使用关联入口表精确回链总索引、所属模块导读、知识场景和调用链，标题片段与目标标题渲染文字完全一致。
- [ ] 源码实现讲解逐项链接仓库保存的上游相对文件，具有仓库补充的中文 Doxygen 注释、中文行内注释和“实现原理”，且源码摘录没有改变代码语义。
- [ ] 每个实现簇具有具体对象/状态地址关系图和端到端函数时序图，或精确复用已经覆盖当前符号的上级图；图、源码、表格和文字使用同一组符号。
- [ ] 每个实现簇说明了可修改性边界：应保持的不变量、最小安全修改面、配对/回滚动作、受影响的 Kconfig 分支、调用方和验证方法。
- [ ] 嵌入公共 API 的功能路径与检查路径已经分开，检查开启/关闭分支和静态/动态覆盖边界说明清楚。
- [ ] 动态验证器已分开真实功能状态、当前影子状态、跨时间历史和检查器生命状态，没有把诊断账本写成功能状态。
- [ ] 检查事件与功能尝试、成功、失败回滚和释放的真实时序已核对，没有仅从函数名推断。
- [ ] “未告警”结论同时记录配置、检查器有效性、原语接入和路径覆盖，并显式处理容量耗尽、递归抑制或错误后停检。
- [ ] 旧版本差异明确指出变化的字段、状态位置或调用链。
- [ ] 外部源码树保持只读。
- [ ] 保存的源码副本与声明来源一致。

## 生命周期与拆除

- [ ] 已枚举正式发布入口，并全部撤销。
- [ ] 临时访问、长期引用、宽限期、回调完成和最终释放彼此区分。
- [ ] 每次分配只有一个最终销毁协议。
- [ ] 独立机制之间通过明确的模块回调或所有权转移连接。
- [ ] 覆盖指针逃逸、工作线程生命周期、回调和模块卸载。
- [ ] 错误清理不会对从未发布的对象使用退休路径。

## 仓库完整性

- [ ] 文件和目录名符合仓库规范。

## 可迁移心智模型

- [ ] 读者能够不看原文画出系统位置、关键对象和完整动态过程。
- [ ] 读者能够用已建立模型解释一个未逐字讲过的负载、配置、平台或失败条件。
- [ ] 读者能够指出推论成立所需的约束，以及需要什么源码、实验、日志、trace 或波形才能验证。
- [ ] 专题完成标准基于定义、因果链、自洽性、边界和继续推理能力，而不是篇幅、知识点、源码或图表数量。
