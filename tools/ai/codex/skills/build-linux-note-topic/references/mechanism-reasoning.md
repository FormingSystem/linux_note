## 1. 来源与本土化边界

本参考吸收开发者提供的《Technical Mechanism Deep-Dive Skill》草案中关于参与者、状态归属、当前状态与历史事件、安全性与活性、极端反例和间接证明的方法。草案是方法来源，不是可直接复制的仓库模板。

最终规则以当前仓库 `AGENTS.md`、信息架构和 `knowledge/linux/synchronization_and_asynchrony/synchronization/rcu/大纲.md` 校正：

- 使用仓库的因果学习链、章节编号、元数据和权威正文位置；
- 将稳定机制、版本源码、实验和导航分别放入 `knowledge/`、`research/`、`labs/` 和 `atlas/` 或专题大纲；
- 把 RCU 的布局抽象为可裁剪的章节角色，不复制它的 28 篇文件、字段名或实现变体；
- 只有适用的机制才使用参与者集合、代际事件、分层汇聚或生命周期模型，不为套模板制造不存在的状态。

## 2. 先设计模型再生成正文

新建、扩写或重写专题时执行两遍生成。

第一遍只建立专题设计账本，不立即生成长篇正文：

| 设计项 | 必须回答的问题 |
| --- | --- |
| 读者结果 | 读完后能重建哪条过程、证明哪项性质或完成什么选择？ |
| 贯穿场景 | 哪个真实负载能够同时承载旧方案、新机制和替代方案？ |
| 被保护对象 | 保护的是对象、入口、请求、状态、资源还是硬件事务？ |
| 旧方案价值 | 旧方案已经提供什么正确性保证？ |
| 具体缺口 | 哪个参与者按什么时间顺序触发错误、停顿或扩展性问题？ |
| 证明义务 | 必须证明安全性、活性、顺序、生命周期还是隔离性质？ |
| 执行模型 | 哪些配置或上下文会改变参与者定义和证明方式？ |
| 状态轴 | 机制是单一状态机，还是多组正交状态共同推进？ |
| 证据 | 需要哪一版本源码、配置、trace、实验或基准？ |

根据设计账本选择章节角色并建立依赖图。第二遍才按依赖图编写正文。设计过程中发现证据不足时，先缩小结论或标记待核对，不用想象补齐。

## 3. 建立参与者清单

先区分能够独立执行或独立持有状态的角色，再描述流程。不得用“内核”“系统”或机制名称代替真实参与者。

| 类别 | 需要识别的事实 |
| --- | --- |
| 任务或线程 | 当前执行什么路径，能否阻塞、抢占或迁移？ |
| CPU 与执行上下文 | 状态是否为 per-CPU，发生在进程、中断、软中断还是 NMI？ |
| 共享数据结构 | 哪个地址承载入口、等待集合、队列、代际或聚合结果？ |
| 协调者 | 谁启动周期、检查完成条件或升级慢路径？ |
| 延迟执行者 | 谁执行回调、唤醒等待者、归还引用或最终释放？ |
| 外部调用方 | 谁能够新建入口、取得对象、撤销发布或触发拆除？ |

同一任务和它当前运行的 CPU 是不同参与者；数据结构是状态载体，不是主动执行者。

## 4. 建立状态账本

每项关键状态至少记录：

| 字段 | 问题 |
| --- | --- |
| 语义与所有者 | 状态表示什么，逻辑上归谁所有？ |
| 存储位置 | 位于对象、任务、per-CPU 区域、节点还是全局结构？ |
| 创建与初始化 | 谁在什么边界建立初值或新代次？ |
| 写入者 | 哪条执行路径在什么事件上修改？ |
| 读取者 | 哪条路径随后消费它？ |
| 传播方式 | 本地写、共享内存、锁、轮询、回调、唤醒、IPI 还是分层汇聚？ |
| 周期关系 | 它属于哪个 S0…Sn 阶段，旧值何时失效？ |

明确区分：

- **当前状态：** 现在是否处于某状态；
- **锁存事件：** 某个边界以后是否发生过一次事件；
- **代际证据：** 该事件属于哪一轮操作，能否被下一轮误用；
- **债务或等待集合：** 当前周期仍欠哪些参与者的证明。

不得把“当前已经安全”和“本轮已经观察到一次足以证明安全的事件”混写成同一个布尔概念。

## 5. 封闭时间边界和参与集合

任何等待、更新或销毁机制都要确定集合边界：等待的是边界以前的参与者、边界时已经持有状态的参与者，还是未来参与者。

至少区分：

```text
任务或设备已经存在
→ 已经进入相关执行路径
→ 已经取得共享入口或旧状态
→ 正在使用受保护对象
→ 已经退出临时保护范围
→ 长期所有权或延迟工作是否仍然存在
```

对象生命周期适用时，再建立：

```text
旧入口仍可取得
→ 撤销或替换入口，封闭未来取得
→ 只剩边界以前的使用者
→ 等待已有使用者或引用结束
→ 等待必要的回调或异步工作完成
→ 唯一最终销毁出口
```

未来参与者为什么不重新进入旧集合，必须由入口、代际或协议边界证明，不能只写“晚到者不影响”。

## 6. 建立证明而不是转述现象

把关键结论写成可检查的因果式：

```text
机制保证某类执行不能跨越边界 B
    +
本轮已经观察到参与者跨越 B 的有效证据
    =
边界以前的相关执行已经结束
```

区分两种通信：

- **直接通知：** 参与者主动登记、上报、完成回调或唤醒等待者；
- **间接证明：** 系统观察一个只有在旧行为结束后才可能发生的事件，据此排除旧参与者。

分别回答：

- **安全性：** 什么条件阻止系统过早执行危险动作？
- **活性：** 哪个参与者或资源可能阻止最终完成，正常路径和强制慢路径如何处理？

证据不足时继续等待通常损害活性而不损害安全性；必须明确机制是否如此设计。

## 7. 用反例加固模型

按主题适用性测试以下条件：

| 反例 | 要检查的模型缺口 |
| --- | --- |
| 没有参与者 | 空集合是否能正确完成？ |
| 边界前已有参与者 | 既有状态是否被完整纳入？ |
| 边界后晚到参与者 | 为什么不会重新取得旧状态？ |
| 参与者永久不退出 | 系统选择等待、诊断、取消还是错误推进？ |
| 任务被抢占或迁移 | 状态是否必须从本地执行现场转为共享登记？ |
| 本地事件已发生但尚未传播 | 异步窗口是否仍保持安全？ |
| 多轮操作交叠 | 旧事件是否可能污染新代次？ |
| 中断、离线或拆除 | 参与集合和未完成工作怎样转移？ |
| 内存乱序或缓存传播延迟 | 源码顺序是否足以建立发布与观察关系？ |
| 对象或指针逃逸 | 临时保护结束后由谁继续提供生命期？ |

每个反例只允许产生四类结果：增加状态、增加通信路径、增加约束，或者明确不支持。不要用更多术语掩盖缺失的状态维度。

## 8. 把推理落实到章节

一个机制或子状态机适用时沿以下顺序展开：

```text
具体场景
→ 旧方案价值与失败链
→ 参与者和状态账本
→ 推导不变量
→ S0…Sn 周期
→ 正常通信和异步窗口
→ 源码映射
→ 异常与慢路径
→ 可观察验证
→ 成本与替代方案
```

这是推理顺序，不是所有文档都必须逐项建立同名小节。API 章、变体章和调试章只保留承担本章结论所需的部分。

控制揭示节奏，执行“一问一增量”：

```text
上一阶段已经成立的模型
→ 一个该模型无法回答的具体问题
→ 能击穿模型的最小反例
→ 识别缺失的状态维度
→ 只增加必要的状态、通信或约束
→ 用源码或实验验证新增部分
→ 留下自然产生的下一问题
```

不要先展示成熟实现的全部字段，再反向解释它们为什么存在。读者应当看见每个新状态是被哪个反例逼出来的。

章节开头可用三句认知桥接：“上一章已经证明……”“但是仍然无法解释……”“本章只解决……”。章节结尾对应使用：“现在可以证明……”“仍然不能解释……”“下一章继续追踪……”。根据正文自然表达，不把它们做成重复的装饰标题。

## 9. 让图表达真实关系

- 角色关系图回答状态保存在哪里、所有权怎样连接；
- 端到端时序图回答动作、状态流和异步窗口按什么顺序发生；
- 状态图回答一个实体怎样转换；
- 生命周期图回答入口何时开放、封闭和最终销毁。

一张图优先承担一个主要问题。图中区分实际函数调用、异步状态传播和逻辑因果；不能把逻辑证明画成不存在的直接调用。箭头和节点命名必须与正文、源码和阶段表一致，并遵守仓库当前 Mermaid 规范。

## 10. 让源码反过来校正模型

先根据抽象模型预测源码需要哪些状态、写入者、读取者和完成条件，再核对结构体、初始化、写路径、读路径、配置分支、锁和内存顺序。发现实现与预测不同，先判断是模型缺状态、配置边界不同，还是该字段只是实现细节，然后修正模型。

不得从函数名猜测存在锁、计数、通知或等待，也不得把逐函数翻译当成机制解释。

## 11. 清理模糊语言

出现“系统知道”“自动同步”“无需通知”“读侧零开销”“等一会儿”“性能更好”等表述时，改写为：

- 哪个对象保存状态；
- 哪条路径在什么事件上写入；
- 哪条路径何时读取；
- 缺少直接通知时由什么证据替代；
- 成本从哪条高频路径转移到了哪条低频、批量或慢路径；
- 对缓存、时延、内存、进展性或实现复杂度产生什么可观察后果。

## 12. 闭环验收

专题完成时，读者应能回答：

1. 保护对象和正式入口分别是什么；
2. 哪个边界封闭旧参与者集合；
3. 任务存在、进入路径、取得状态和持有对象分别发生在何时；
4. 每项关键状态位于哪里，由谁写、谁读；
5. 当前状态、历史事件、代际和等待债务怎样区分；
6. 本地证据怎样变为共享或全局结论；
7. 完成结果怎样交给等待者、回调或销毁路径；
8. 为什么不会过早推进，什么条件会妨碍最终完成；
9. 异步传播、晚到参与者和多轮交叠为什么不破坏结论；
10. 抽象结论在源码、配置和实验中分别由什么证据支撑；
11. 哪些成本被移除、转移或新增；
12. 什么条件下应继续使用原方案或选择替代机制。
