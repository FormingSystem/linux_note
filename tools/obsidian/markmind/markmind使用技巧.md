# 第1章\_MarkMind的基本导图与正文维护

MarkMind 是 Obsidian 中用于思维导图、大纲及相关标注工作的插件。它适合把已有笔记的层级关系转换为可编辑视图，例如查看一个专题由哪些问题组成；它不会自动证明节点之间的因果关系，也不能代替教材中的解释和引用。

本页从一份小型 basic 导图开始，重点是看清“文件内容—插件视图—导出结果”三者的关系。2026-10-18 检查本工作区插件清单，版本声明为 **3.4.4**；本次只读检查清单和插件代码中的配置入口，未启动 Obsidian 做界面操作、购买授权或修改插件设置。官方功能说明见 [MarkMind 项目 README](https://github.com/MarkMindCkm/obsidian-markmind) 与 [中文用户手册](https://github.com/MarkMindCkm/obsidian-markmind/blob/main/docs/用户手册.md)，菜单及功能可用性应以实际安装版本为准。

## 1.1\_先选数据形式再选显示方式

把普通标题和列表显示成导图，便于继续用文本编辑器维护；自由节点、关联线等更丰富的布局则需要保存额外结构。MarkMind 用不同模式处理这些需求，不能只改一个标签就假定两种数据已经无损转换。

| 模式或设置 | 作用 | 本仓库使用时的关注点 |
| --- | --- | --- |
| `mindmap-plugin: basic` | 以 Markdown 标题、层级列表组织基本导图 | 正文仍能按文本检查和比较，适合从已有层级开始 |
| `mindmap-plugin: rich` | 使用插件的丰富导图数据，官方示例包含 JSON 结构 | 额外布局不是普通列表；不要对数据块运行面向正文的批量改写 |
| `display-mode: outline` | basic 文档的大纲显示选择 | 改变视图入口，不把它当成另一份权威正文 |
| `display-mode: table` | 表格显示入口 | 只适合能用表格理解的层级；不代表所有导图都天然是二维数据 |

本地 3.4.4 代码可以核对 `mindmap-plugin`、`basic`、`rich` 和上述 `display-mode` 配置。官方不同页面对 rich 模式的大纲支持存在表述差异，所以本页只承诺从 basic 路线开始，不推定任意模式之间都可直接切换。

## 1.2\_用一份小文件观察层级怎样成为节点

先在自己的临时笔记区创建 `markmind_trial.md`，不要直接把重要教材整篇转换成 rich 数据。若插件尚未启用，在 Obsidian 中核对安装来源和版本后再按其正常设置启用；本说明不代替用户完成安装或登录。

下面是可以完整复制的练习文件。已有笔记只合并到原有 Front Matter 中，不能在同一文件头再叠加第二块元数据。这里的 `id` 是练习文档身份，应给每份长期保留的笔记使用唯一值；插件选择来自 `mindmap-plugin`，两者用途不同。

````markdown
---
id: personal.markmind_trial
title: "一次构建的证据"
kind: reference
status: draft
domains:
  - tools
mindmap-plugin: basic
---

# 一次构建的证据

- 输入
  - 源码提交
  - 配置与补丁
- 过程
  - 构建命令
  - 首个错误或成功记录
- 结果
  - 产物摘要
  - 实际启动观察
````

保存后用插件提供的导图入口打开这份笔记。预期能看出“输入、过程、结果”三个同级分支，各自拥有两个子项。这里的边表示分类包含关系，不是构建执行的时序；要表达先构建再启动，应另画带动作的流程图。

先在文本中把“产物摘要”改为“本次产物摘要”，保存并检查导图是否反映变化；再在导图中做一次小修改，返回文本查看文件差异。这个往返检查帮助确认当前版本怎样保存编辑，不应只看图上已经显示新文字就关闭文件。若视图没有刷新，先确认打开的是同一个文件及保存状态，再核对插件是否启用和元数据是否被识别。

## 1.3\_大纲和表格先在练习副本中切换

当节点太多时，大纲方便按缩进逐层检查。将练习文件同一块 Front Matter 增加下面一行，再通过当前插件对应入口观察：

```yaml
display-mode: outline
```

需要表格视图时，把该值改为 `table`，不是再添加一个同名键。核对三组父子关系是否仍符合原笔记，再决定是否保留这种显示。回到普通文本时，以文件里实际保存的结构为准，不为恢复外观删除未知的插件数据。

编辑节点时，先选择目标，再使用当前界面提供的编辑、缩进、移动或撤销动作。官方列出的快捷键会受到模式、平台及自定义键位影响，尤其不能把命令面板快捷键当作“立即新建导图”的专用快捷键。第一次使用缩进或拖动后返回文本核对父子关系，避免只改变画面却误认为调整了学习依赖。

## 1.4\_导出副本与权威正文保持关系

本仓库的正文、专题大纲和 Atlas 入口仍按各自职责维护。导图可以帮助整理阅读关系，但不应把教材全文复制到多个插件文件后分别修改。若导图承担专题导航，节点尽量链接真实章节，并在重命名时检查链接去向。

丰富模式的复制为 Markdown、图片或 PDF 导出可能丢失部分布局、关联线或插件交互。先在练习副本中使用当前版本提供的导出入口，再核对节点文字、层级、链接和注释；官方文档中出现的某个导出命令不代表本机所有模式和授权状态都提供它。PDF 标注涉及原文件与标注数据，本页不把它们当成普通导图导出已经覆盖的功能。

导出图片用于阅读，原始可编辑文件仍需保留。用户工作台能适配图片宽度并支持放大全屏，因此优先保持文字和关系完整；必要时按问题拆图，不为固定尺寸删去关键节点。Markdown 中展示图源的通用规则见 [Mermaid 图形约定](../../ai/application/mermaid_require.md)，它与 MarkMind 插件数据格式是不同层。

## 1.5\_怎样确认这次练习已经完成

完成练习至少应看到：文本的三个同级分支被正确识别；一次文本修改能反映到视图；一次视图修改可以在保存后的文件中定位；切换显示没有让子节点归属改变。若执行了导出，再单独检查导出结果。以上是读者可执行的观察步骤，本次文档整理未声称已经替读者完成界面往返测试。

遇到问题时保留插件版本、最小练习文件、操作顺序与实际差异。先用这份小文件区分“插件未识别配置”和“复杂原稿的结构问题”，再处理正式笔记；不要直接删除旧图、插件数据或所有配置来尝试恢复。
