# 红黑约束怎样换来有界高度

## 本章问题

完全平衡会让每次更新付出更高修复成本，完全不平衡又可能退化。红黑树怎样在两者之间取舍？

## 颜色是结构编码

红节点可以理解为与黑色父节点组合成一个多路节点，黑高则表示从当前位置到叶子必须经过的黑色结构层数。颜色不是业务属性，而是用于表达局部结构和修复条件的编码。

红黑树允许左右路径长度不同，但要求各条路径具有一致的黑高，并禁止红节点连续连接。由此，最长路径中的红节点必须被黑节点隔开，最长路径不会无限超过最短路径。

## 更新成本没有消失

插入可能产生连续红节点，系统根据父、叔和祖父的状态选择变色或旋转。删除黑节点可能减少某些路径的黑高，因此需要从兄弟节点和其孩子处重新分配结构预算。删除修复通常比插入复杂，不能只记一套旋转口诀。

这种设计换来的是有界高度，而不是绝对最矮的树。它减少了严格平衡所需的重排次数，却保留稳定的对数级查找路径。

## 本章结论

红黑约束把全局高度目标编码成可局部检查和修复的状态。下一章将这些抽象规则映射到 Linux 的嵌入式节点和调用者接口。
