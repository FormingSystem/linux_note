# 旋转怎样改变形状而保持有序

## 本章问题

如果直接交换节点可能破坏搜索顺序，红黑树凭什么通过局部重排缩短路径？

## 关键字区间

设父节点为 `x`、右子节点为 `y`，并且 `x < y`。`y` 的左子树中所有关键字都位于 `x` 和 `y` 之间。左旋后，`y` 成为局部根，`x` 成为左孩子，中间子树转为 `x` 的右子树。它仍然处在相同关键字区间，所以中序遍历顺序不变。

旋转改变的是父子关系和局部深度，不改变对象身份，也不重新定义比较规则。

## 局部动作的边界

旋转回答“怎样安全改变形状”，但没有回答“什么时候必须改变”。随意旋转可能把一侧变短，却让另一侧变长。系统仍需要一组能够从局部状态判断是否违反全局高度目标的约束。

如果业务节点还保存子树大小、区间最大值等增强字段，旋转后还必须按新的子树归属更新这些派生状态。只修链接而遗漏增强字段，同样会造成错误。

## 本章结论

只要中间子树保持关键字区间，旋转就能保持搜索语义。下一章需要建立一组结构编码，决定何时旋转、何时变色，以及怎样从局部修复得到全局高度边界。
