# 正确的 BST 为什么仍会越来越慢

## 本章问题

二叉搜索树已经规定左侧关键字更小、右侧关键字更大，为什么查找仍可能退化成线性扫描？

## 从正确性到复杂度

按 `10、20、30、40` 连续插入时，每个节点仍满足搜索顺序，但结构逐渐变成只向右延伸的链。查找结果没有错误，从根到最后一个节点的比较次数却随数据量线性增加。

```text
10
  \
   20
     \
      30
        \
         40
```

BST 的有序性只告诉查找下一步走向哪里，没有限制根到叶子的路径长度。因此，平均输入下表现良好不能替代最坏输入下的形状保证。

## 原方案的价值

普通 BST 仍然有价值：它用局部关键字比较维护动态有序集合，插入时不必搬移整个数组，也能支持最小值、相邻元素和范围遍历。问题不是 BST 无用，而是缺少一条约束树形的机制。

## 本章结论

有序性与平衡性是两个不同保证。不利插入顺序可以在保持搜索正确性的同时让路径退化。下一章需要回答：能否改变树形而不破坏关键字顺序？
