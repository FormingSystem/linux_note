# Linux rbtree 的职责与使用者责任

## 本章问题

通用红黑树算法建立了平衡保证，但一个内核索引还需要关键字、对象、锁和生命期。Linux rbtree 到底负责哪些部分？

## 嵌入式节点

Linux 把 `struct rb_node` 嵌入业务对象，而不是为树节点单独分配包装对象。树根只连接节点，调用者通过容器关系找回业务对象。这减少额外分配和间接访问，也让一个业务对象可以明确拥有自己的索引节点。

## 调用者拥有策略

rbtree 不知道业务关键字。调用者负责比较并沿树寻找插入位置，再调用平衡接口维护结构。它也不自动加锁：写者如何串行化、读者如何观察、节点何时能够删除和释放，都取决于具体子系统。

```text
调用者：比较规则 + 插入位置 + 锁 + 对象生命期
                     ↓
rbtree：父子链接 + 颜色状态 + 平衡修复
```

## 结构选择边界

如果数据一次构建且几乎只读，排序数组可能有更好的缓存局部性；等值查找可能更适合哈希表；磁盘和页级索引通常需要多路树减少层数。选择 rbtree 的前提是业务需要动态更新、稳定有序查找以及可接受的局部修复成本。

## 全书结论

红黑树不是颜色规则集合，而是一条完整因果链：BST 提供有序性但可能退化，旋转允许保持顺序地改变形状，红黑约束限制高度，Linux 再把机制嵌入业务对象并把策略责任留给调用者。
