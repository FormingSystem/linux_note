# Linux hlist 的嵌入与删除路径

## 本章问题

抽象链式哈希只说“桶里挂一条链”，但内核对象如何嵌入、已知节点怎样删除、桶头为什么需要保持紧凑？

Linux 常把 `hlist_node` 嵌入业务对象。节点保存 `next`，并用 `pprev` 指向“当前节点所在的前一个链接位置”。删除已知节点时，可以直接改写该链接位置和后继节点的 `pprev`，不必从桶头遍历寻找前驱对象。

```text
桶头.first ──> node A.next ──> node B
                 ↑               ↑
              pprev           pprev 指向 A.next
```

## 职责边界

`hlist` 只组织链接，不负责选择业务键、计算哈希值、决定桶数、提供并发安全或管理对象生命期。这些责任属于具体使用者。

嵌入式布局减少包装分配和间接访问，但要求调用者清楚节点属于哪个对象，以及对象何时仍可能被并发读者访问。

## 本章结论

`pprev` 优化的是已知节点删除路径，桶头紧凑适合大量桶。下一章讨论对象增长后如何扩容，以及并发迁移为何引入新的状态机。
