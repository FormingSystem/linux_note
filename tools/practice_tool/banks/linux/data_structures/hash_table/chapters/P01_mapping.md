# 从全表扫描到候选集合

## 本章问题

设备表中有十万个对象时，为什么不再逐项比较？哈希表所谓“直接定位”究竟减少了哪一段工作？

哈希函数把业务键映射到桶索引，使查找先排除绝大多数不可能对象，再在一个较小候选集合中比较完整键。一次查找至少包含哈希计算、桶定位和对象确认。

```text
业务键 → 哈希函数 → 桶索引 → 候选集合 → 完整键比较
```

桶索引不能证明对象身份，因为键空间通常远大于桶数组，不同键可能产生相同索引。省略完整键比较会把冲突对象误认为目标。

## 原方案价值与新边界

全表扫描简单且不依赖分布假设，小数据量下可能足够。哈希映射用额外桶空间换取候选集合缩减，适合大量等值查询，却不天然提供关键字顺序和范围遍历。

## 本章结论

哈希速度来自缩小候选集合，而不是神奇的一次命中。下一章需要解释冲突为什么必然发生，以及候选集合何时会重新变大。
