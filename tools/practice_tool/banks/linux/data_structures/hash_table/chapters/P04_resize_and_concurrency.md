# 动态伸缩与并发迁移

## 从负载增长推出扩容

对象持续增加而桶数不变时，冲突链变长。扩容需要建立更大的桶数组，并按新掩码重新计算对象位置。此时旧桶不能瞬间消失，因为并发读者可能已经取得旧表或旧节点地址。

## 过渡状态

并发扩容至少涉及旧桶数组、新桶数组、迁移位置、正在访问的读者和等待回收的旧结构。系统必须规定谁推进迁移、读者查哪个表、对象在迁移期间能否重复可见，以及旧表何时安全释放。

`rhashtable` 的价值是组织这些伸缩与并发步骤，而不是让成本消失。常规查询路径获得较稳定的候选集合，扩容、迁移和回收路径承担额外工作。

## 与 RCU 的组合

读多写少时可以利用 RCU 保护读者观察到的旧结构，但写者串行化、对象删除和迁移状态仍需明确。RCU 解决生命期边界，不替代哈希表的业务一致性。

## 全书结论

哈希表是一条从候选缩减到状态治理的因果链：映射缩小候选集合，冲突和负载决定实际成本，hlist 优化内核对象链接，动态伸缩再引入新旧表和并发生命期。
