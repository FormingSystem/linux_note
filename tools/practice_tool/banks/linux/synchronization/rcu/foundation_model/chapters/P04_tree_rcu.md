# Tree RCU 怎样汇聚完成证据

## 分散参与者与全局结论

Tree RCU 不让每个普通读者直接通知一个全局等待者。CPU 或任务形成的静止状态证据先保存在局部状态，再沿 `rcu_node` 层次汇聚，最终形成当前宽限期可以结束的全局结论。

```text
CPU/任务局部证据 → rcu_node 分层汇聚 → 根节点完成 → 回调可执行
```

## 抢占改变状态归属

被抢占的旧读者不能因为暂时离开 CPU 就被视为完成。它需要从仅由本地执行路径观察的状态转入共享登记，使后续调度和宽限期推进仍能找到它。

## 正常路径与慢路径

正常路径利用自然发生的静止状态并按周期汇聚。参与者长时间不推进时，系统才进入远端探测、强制静止状态或 IPI 催促等慢路径。所谓“不主动通知”只描述普通高频路径，不代表系统完全没有通信。

## 全书结论

RCU 从旧地址仍被持有的问题出发，建立有边界的旧读者集合，把成本转移到更新与回收，并通过 Tree RCU 的局部状态和层次汇聚形成安全回收证据。
