# 读侧成本转移到了哪里

## 三个独立动作

RCU 更新不能压缩成一次指针赋值。更新者需要完整构造新对象，以满足可见性要求的方式发布入口，保留旧对象等待宽限期，并在安全点后执行回收。

普通读侧可以避免共同修改全局读者计数，但更新和回收路径要承担发布顺序、旧版本暂存、宽限期推进、回调队列和积压控制。成本没有消失，只是根据读多写少的负载特点重新分配。

## 写者一致性

RCU 协调读者和旧版本生命期，不自动解决两个写者同时修改业务状态的问题。写者仍可能需要锁、序列号或其他串行化方案。

## 对象逃逸

读者若要在读侧临界区外继续持有对象，宽限期本身不够。常见做法是在受保护范围内取得引用计数，随后由引用计数承担更长生命期。

## 本章结论

RCU 的收益依赖读多写少、允许延迟回收和对象不任意逃逸。下一章把抽象完成证据映射到 Tree RCU 的分层状态与通信。
