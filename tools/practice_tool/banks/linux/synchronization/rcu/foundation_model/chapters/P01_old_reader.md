# 入口更新后旧对象为什么仍不能释放

## 一个危险的正确更新

CPU0 从共享入口取得对象 A。CPU1 完整构造对象 B，并把入口从 A 切换到 B。新读者会取得 B，发布动作本身没有错误；但 CPU0 的寄存器、栈或局部变量仍可能保存 A。

```text
CPU0: 读取入口 ─ 得到 A ───────── 使用 A
CPU1:           构造 B ─ 切换入口 ─ 释放 A
                                  ↑ 过早回收
```

入口替换只能约束后来的读取，不能撤销已经发生的地址取得。若立即释放 A，CPU0 随后的访问会落到失效内存。

## 原方案与缺口

读写锁可以让更新者等待全部读者退出，保证简单明确，但每个高频读者都要参与共享同步。RCU 试图减少读侧共同修改，却必须另行证明旧读者已经不再使用 A。

## 本章结论

“入口不再可达”和“对象可以释放”是两个不同状态。下一章需要定义更新者真正需要等待的读者集合。
