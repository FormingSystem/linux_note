# 第1章\_复习调度与训练历史设计

> 本文是目标设计。当前应用中的“复习”和“历史”路由只是边界说明占位页，尚未实现本文的掌握状态、调度、筛选和历史比较。完成度以 [实现状态与版本边界](../implementation_status.md) 为准。

## 1.1\_设计目标

训练评分、掌握程度和复习时间是三类不同状态。系统不能把“部分输出”“稍后复习”和“已掌握”压缩到一个字段，也不能用一次自评永久决定掌握程度。

复习系统首先服务于用户理解和重新输出，不追求用不透明算法替用户宣布“已经学会”。

## 1.2\_状态模型

### 1.2.1\_本次表现

每个已提交训练项记录一次表现：

| 值 | 含义 |
| --- | --- |
| `again` | 无法独立启动关键因果链，需要重建 |
| `hard` | 能输出部分模型，但缺少关键角色、状态或边界 |
| `good` | 能独立输出本轮要求的完整模型 |

表现只描述这一次回答，不直接等于长期掌握。

### 1.2.2\_掌握状态

```text
learning
reviewing
mastered
```

- `learning`：尚未完成首次完整训练，或最近一次为 `again`。
- `reviewing`：已经完成首次训练，但仍在复习周期内。
- `mastered`：最近 3 次独立输出中至少 2 次为 `good`，最近一次不是 `again`，最近一次提交前没有查看参考答案，并且这些输出至少跨越 2 个不同本地日。

系统可以建议进入 `mastered`，但必须允许用户撤回。用户手动标记已掌握不能删除历史低分记录。

### 1.2.3\_调度状态

```text
unscheduled
scheduled
due
snoozed
```

- `unscheduled`：没有下次复习时间。
- `scheduled`：已设置未来复习时间。
- `due`：复习时间已到。
- `snoozed`：用户明确推迟，并保存新的到期时间和推迟原因。

## 1.3\_复习项粒度

复习项使用稳定训练任务 ID，并引用产生它的计划版本。复习可以按以下粒度组织：

- 单个提示问题。
- 单个脱稿输出。
- 单个专业案例。
- 一本专题书或一个章节的知识拓扑重建。
- 一个专题的综合复习。

系统优先安排最小可独立训练单元，避免用户为了复习一个薄弱点重做整个专题。综合复习由用户选择或在多个相关薄弱点同时到期时建议生成。

## 1.4\_基础调度规则

第一版使用可解释的规则，不宣称实现复杂记忆算法：

| 本次表现 | 默认建议 |
| --- | --- |
| `again` | 当天稍后或次日重做 |
| `hard` | 2～3 天后复习 |
| `good` | 7 天后复习 |

连续两次 `good` 后，可以建议延长到 14～30 天；任何一次 `again` 将该任务返回学习中。用户可以覆盖日期、关闭自动建议或选择“稍后决定”。

调度计算保存：

```text
review_item_id
source_session_id
task_id
plan_version
performance
scheduled_at
due_at
snoozed_until
rule_version
```

规则版本必须保存，未来调整算法时不能重写过去建议的来源。

复习时间区分日历日和精确时间：

```text
due_kind: date | datetime
due_date: YYYY-MM-DD          # 仅 due_kind=date
due_at: UTC timestamp         # 仅 due_kind=datetime
timezone: IANA timezone
```

“今天复习”使用用户当前时区的日历日；精确时间以 UTC 保存并同时保留创建时 IANA 时区。跨时区时，日历日任务保持用户选择的日期语义，精确时间任务保持绝对时刻。夏令时造成的不存在或重复本地时间必须在选择时提示并规范化。

## 1.5\_待复习页面

页面按以下顺序组织：

1. 已到期。
2. 今日稍后。
3. 未来 7 天。
4. 未安排但建议复习。

每项显示：

- 专题和任务名称。
- 上次表现。
- 到期时间。
- 预计用时。
- 最近一次训练使用的计划版本。
- 开始复习、推迟、选择日期和查看历史。

批量操作只允许“安排日期”和“推迟”，不能批量标记已掌握。

## 1.6\_复习会话

复习会话是独立会话类型，不能覆盖原训练会话。开始复习时冻结选中的任务和计划版本。

复习默认先要求脱稿输出，再允许查看：

- 上次答案。
- 参考模型。
- 原文依据。
- 历史遗漏点。

如果先展示上次答案，系统必须明确标记本轮不能再用于衡量独立输出。

## 1.7\_训练历史

历史列表至少支持按专题、训练模块、日期、会话状态和计划版本筛选。列表显示：

- 会话开始和结束时间。
- 完成或放弃状态。
- 计划版本。
- 各阶段完成度。
- `again`、`hard`、`good` 数量。
- 是否存在未解决的薄弱项。

历史详情以只读方式展示首次提交和后续修订。再次编辑产生新修订，不修改历史时间线。

## 1.8\_历史比较

只有使用相同任务 ID 的结果才能直接按题比较。计划版本不同时必须显示内容变化标记：

```text
相同题目、相同版本
相同题目、内容已更新
旧版本独有题目
新版本新增题目
```

比较重点：

- 是否能更早启动回答。
- 关键角色和状态是否更完整。
- 因果链缺口是否减少。
- 是否仍依赖提示。
- 方案边界是否更明确。

不能只比较字数或训练时长后宣布进步。

## 1.9\_大厅展示

大厅最多展示：

- 一项“继续最近训练”。
- 三项最紧急待复习任务。
- 最近三次完成训练。

训练会话优先级和复习优先级分别计算；复习到期不能挤掉“继续训练”主入口。没有到期任务时显示下一次计划日期，不制造虚假紧迫感。

## 1.10\_删除与恢复

- 删除训练分类不删除复习项。
- 删除训练模块不删除历史会话。
- 训练任务从新版本移除后，旧计划版本中的复习项仍可执行。
- 永久删除历史前必须展示会影响的复习项数量。
- 恢复历史会话时同步恢复仍有效的复习关系。

第一版本地数据不自动清空回收站。用户主动清空时才永久删除；未来多设备同步必须使用 tombstone 和删除版本，避免其他设备把已删除对象重新创建。

## 1.11\_验收条件

- 同一任务可以同时保存一次表现、一个掌握状态和一个调度状态。
- `again` 不会被展示成“已掌握”。
- 推迟复习保留原到期时间和新的推迟时间。
- 再次训练不会覆盖原答案。
- 不同计划版本比较时明确显示内容差异。
- 删除分类或模块不会删除训练历史。
- 大厅没有到期任务时不显示误导性红色告警。
