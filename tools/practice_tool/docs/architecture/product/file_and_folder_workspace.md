# 第1章\_文件与文件夹工作区设计

## 1.1\_文档职责与评审状态

本文定义回路桌面客户端怎样打开单个文件、打开文件夹、展示资源管理器、恢复窗口状态和执行文件操作。本文处于 **proposed** 评审状态；它不沿用专题电子书、知识源注册、内容包导入或浏览器副本模型。

编辑、保存和实时预览见 [Markdown 编辑与实时预览设计](markdown_editing_and_live_preview.md)，进程与文件服务见 [桌面运行时与文档服务设计](../engineering/desktop_runtime_and_document_services.md)。

## 1.2\_产品模型

回路只提供三个顶层入口：

1. **新建文件**：创建未命名内存缓冲区，第一次保存时选择磁盘位置。
2. **打开文件**：选择一个现有 Markdown，建立单文件窗口，不扫描其父目录。
3. **打开文件夹**：选择一个目录作为当前窗口的单根工作区，在资源管理器中浏览其中的文件和目录。

第一阶段不支持多根工作区，也不定义私有 workspace 文件。单根工作区稳定后，再用独立 ADR 评审多根工作区是否值得引入。

“打开文件夹”不是导入：

- 不复制目录内容到应用数据库。
- 不修改目录结构或生成隐藏配置目录。
- 不在打开瞬间读取所有文件正文。
- 文件树按需枚举，搜索和链接索引在后台增量建立。
- 关闭工作区不会删除、移动或重新打包原目录。

## 1.3\_窗口与工作区状态

一个桌面窗口只有一种模式：

| 模式 | 磁盘授权边界 | 资源管理器 | 工作区索引 |
| --- | --- | --- | --- |
| `empty` | 无 | 不显示 | 无 |
| `single_file` | 用户选择的文件；其父目录只作为相对资源读取边界 | 只显示已打开文件 | 不扫描父目录 |
| `folder` | 用户选择目录的规范化真实根 | 显示根内文件树 | 按需建立 |

窗口恢复数据只保存窗口模式、最近打开项、已打开标签、活动标签、布局和相对位置。它不保存 Markdown 正文副本。最近打开项的绝对路径只能保存在 Main 管理的应用数据目录，不进入 Renderer 持久状态、日志或知识目录。

## 1.4\_打开单个文件

用户通过系统文件选择器、操作系统“打开方式”或命令行打开一个文件。Main 建立只对该文件有效的写能力，并把不透明 `workspace_id` 与 `document_id` 交给 Renderer。

单文件模式遵循最小授权：

- 当前文件可以读取和显式保存。
- 相对图片和附件只能读取当前文件父目录及其子目录内的目标。
- 不枚举父目录，不建立跨目录全文索引。
- 点击同目录的 Markdown 链接时，由 Main 验证后显式打开该目标，并为目标建立新的文件能力。
- `../` 越过父目录、绝对路径、符号链接跳出边界或远程资源不会自动读取。

如果用户希望浏览和维护整个目录，应使用“打开文件夹”，而不是让单文件模式暗中升级权限。

## 1.5\_打开文件夹

用户通过系统目录选择器选择一个根目录。Main 记录该目录的规范路径与文件身份，Renderer 只获得工作区显示名、相对路径和不透明资源 ID。

资源管理器参考成熟代码编辑器的行为：

- 展示文件与目录层级，目录展开时再枚举子项。
- 允许新建、重命名、移动和删除，但每个操作都是显式命令。
- Markdown 文件在内部编辑器打开；图片可以安全预览；其他文件显示类型信息并提供“在系统中显示”。
- 文件过滤、排序和折叠状态属于应用偏好，不写入工作区。
- 默认排除 `.git/objects`、`node_modules` 等高成本目录的监听和内容索引，但资源管理器仍允许用户主动展开。

目录监听只提供变化提示。文件服务在读取、保存、重命名和删除前仍重新验证目标，不能把 watcher 事件当成权限或磁盘真相。

## 1.6\_标签、预览与恢复

每个打开文档占用一个编辑标签。标签显示文件名、必要时显示消歧义相对路径，并用圆点标记未保存状态。窗口和资源管理器显示未保存文件数量。

Markdown 预览是同一文档会话的派生视图，可以：

- 替换当前编辑视图。
- 在侧边与源码并排打开。
- 锁定到某个文档，避免活动标签变化时自动切换。

应用正常重启后恢复上次窗口、文件夹、标签和布局。未保存正文通过恢复备份重新进入 `Dirty`，不能因为窗口被恢复就显示为已经保存。

## 1.7\_文件操作

### 1.7.1\_新建与另存为

未命名文件只存在于内存与恢复备份中。第一次保存或“另存为”必须通过系统对话框选择位置；Main 不接受 Renderer 提供的任意绝对路径。

### 1.7.2\_重命名与移动

文件和目录移动前检查：

- 目标是否已存在、是否越过工作区、是否改变符号链接或挂载边界。
- 被移动文档是否存在未保存编辑器。
- 哪些 Markdown 链接会受影响。

链接更新策略默认 `prompt`，可选 `never` 或 `always`。即使选择自动更新，系统也必须先计算工作区编辑集合，使用每个文件的期望摘要保存；任一文件发生外部冲突时停止剩余写入并显示实际完成范围，不伪装成跨文件原子事务。

### 1.7.3\_删除

删除默认进入操作系统回收站。目标含有未保存编辑器、位于工作区外部、是符号链接目标或无法进入回收站时必须停止并解释；第一阶段不提供绕过回收站的“永久删除”。

## 1.8\_设置与工作区内容

第一阶段设置只有用户级和应用维护的工作区状态级。回路不读取目录内的 `.vscode/settings.json`、脚本、任务、插件清单或其他可执行配置，也不自动创建 `.loop/`。

这意味着陌生目录始终可以安全浏览和编辑，而不存在“信任后才能编辑”的额外门槛。未来若加入终端、任务、可执行插件、AI 代理或从工作区读取命令配置，必须先建立类似 Workspace Trust 的独立安全模型；不得把目录被打开等同于允许执行其中内容。

## 1.9\_安全默认值

- Markdown、HTML、SVG、Mermaid、公式和目录内容一律视为不可信数据。
- 打开文件或文件夹只授予对应读取边界，不授予执行程序、联网或访问任意外部路径的能力。
- 远程图片、样式和脚本默认不加载；外部链接只在用户动作后交给系统浏览器。
- 文件夹中的配置不能改变安全策略、加载 JavaScript 或扩大路径权限。
- 符号链接、junction、reparse point 和挂载点必须显示身份；越过已打开边界需要再次由用户选择。

## 1.10\_验收边界

- 可以从空窗口分别打开一个 Markdown 或一个目录，并且两者权限与 UI 明确不同。
- 打开目录后不复制正文、不写隐藏文件，也不因目录规模一次性读取全部内容。
- 单文件模式不能通过相对链接读取父目录之外的文件。
- 文件夹模式中的文件操作始终受根目录、文件身份和显式命令约束。
- 重启后恢复窗口和未保存草稿，但不改写源文件。
- 删除默认进入回收站；移动和链接更新发生冲突时不静默覆盖。
