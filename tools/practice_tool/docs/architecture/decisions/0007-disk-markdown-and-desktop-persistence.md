# 第1章\_ADR-0007\_采用磁盘正文与分层保存

## 1.1\_状态

`proposed`

若接受，本决策取代 ADR-0002 的 IndexedDB 主存储结论，同时保留本地优先、默认不上传原则。

## 1.2\_背景

回路直接编辑用户选择的 Markdown。把正文复制到数据库会制造磁盘版本、应用副本和内存草稿多份真相；反过来，每次输入就写回源文件会造成不必要 I/O、破坏用户对“保存”的预期，并放大外部编辑冲突和半写入风险。

编辑器需要分别回答四个问题：当前内存是否修改、预览是否追上、异常退出能否恢复、源文件是否已经保存。这四个状态不能压缩成一个 `saved` 布尔值。

## 1.3\_决策

- 磁盘 Markdown 是已保存正文的唯一权威版本，CodeMirror 缓冲区是当前草稿。
- 每次编辑只更新内存和预览修订，不写源文件。
- 源文件默认手动保存；自动保存默认关闭，只提供 `afterDelay`、`onFocusChange`、`onWindowChange` 显式选项。
- 恢复备份在 Dirty 后空闲约 2 秒合并写入，并以约 30 秒最大间隔和窗口生命周期事件补充刷新；不建立逐键日志。
- 关闭单个脏标签询问保存，关闭窗口或应用默认 Hot Exit 并在下次启动恢复为 Dirty。
- 成功保存后才创建限额本地历史；恢复历史先进入内存缓冲区，不直接覆盖磁盘。
- 保存使用文件身份、期望内容摘要、安全写入策略和显式冲突。普通文件优先 safe replace；符号链接、硬链接或无法保持元数据时选择经过验证的替代策略，不能保证则失败关闭。
- 第一阶段使用版本化状态文件、恢复备份目录和历史目录，不引入 SQLite。索引数据库必须由性能数据另行证明。

## 1.4\_替代方案

- 每次按键写源文件：实现直观，但写放大、冲突和用户预期都不可接受。
- 默认延迟自动保存：减少手动操作，但会改变磁盘与 Git 工作区的时机，不能替用户默认选择。
- 只在内存保存到退出：磁盘写入少，但崩溃恢复不足。
- 保存完整编辑日志：恢复精细，但持久化频率、隐私、空间和重放复杂度不值得。
- SQLite 保存正文与草稿：事务强，但重新产生正文副本所有权和原生模块成本。
- 无条件临时文件 rename：常见但会破坏符号链接或硬链接语义，不能作为所有文件的统一答案。

## 1.5\_后果

- UI 必须分别显示 Dirty、Saving、SaveFailed、Conflict、BackupPending 和 BackedUp。
- 硬崩溃可能丢失尚未进入合并备份窗口的最后短时编辑；这是避免每键落盘的明确代价。
- 文件保存需要跨平台故障注入、元数据保持、符号链接与硬链接测试。
- 恢复备份和本地历史包含正文，需要目录权限、空间上限和独立清理确认。
- 删除 IndexedDB 主存储与电子书正文副本后不维护双写或同步层。
