# 第1章\_无障碍\_性能与产品验收标准

## 1.1\_目标

本文件把“操作方便、像 App 一样、支持无障碍、性能良好”等主观要求转换为可重复验证的交付标准。未满足关键验收条件的功能不能仅因页面可见或按钮可点击而视为完成。

## 1.2\_输入与键盘操作

- 仅使用键盘可以完成大厅、训练库、单元详情、完整训练、复习、分类管理和导入导出。
- Tab 顺序与视觉阅读顺序一致。
- 所有按钮、链接、步骤、菜单和对话框控件可获得清晰焦点。
- 不使用只有鼠标拖拽才能完成的操作；拖拽排序同时提供上移和下移。
- 不覆盖浏览器和操作系统通用快捷键。
- 快捷键在设置中可查看并允许关闭。
- 输入框聚焦时，单键训练快捷键不触发。

默认快捷键建议：

| 快捷键 | 操作 |
| --- | --- |
| `Ctrl+Enter` | 提交当前题或确认当前主要动作 |
| `Ctrl+S` | 立即保存当前草稿 |

训练顺序的上一步和下一步第一版只要求可见按钮与标准 Tab 操作，不占用浏览器的 `Alt+Left`、`Alt+Right`。未来增加可配置快捷键时，必须检测浏览器、操作系统和输入法冲突。

## 1.3\_焦点与屏幕阅读

- 路由切换后焦点移动到新页面的 H1 或主内容起点。
- 打开对话框后焦点进入对话框并限制在其内部。
- 关闭对话框后焦点返回触发控件。
- Toast 不抢夺键盘焦点。
- 保存状态、导入进度和错误使用合适的 `aria-live` 区域。
- 当前导航使用 `aria-current`。
- 训练步骤使用有序列表，并明确未访问、当前、进行中和已完成状态；所有阶段入口都可用。
- 图标按钮必须具有可访问名称。
- 拓扑图提供等价的节点和连接文本列表。
- Mermaid 或自定义图形提供标题、说明和键盘可访问的文本替代。

## 1.4\_视觉与响应式

- 产品目标为 WCAG 2.2 AA。
- 文字放大到 200% 时，核心操作不丢失且页面不产生整体横向滚动。
- 支持宽度从 320 CSS 像素开始的窄屏布局。
- 核心可点击目标不小于 44×44 CSS 像素。
- 普通文本对比度至少 4.5:1，大文本至少 3:1，非文本控件和焦点指示至少 3:1。
- 状态不能只依赖颜色；同时使用文字、图标或形状。
- 支持 `prefers-reduced-motion`，关闭非必要动画和滚动过渡。
- 支持 Windows 高对比度和 `forced-colors`。
- 不使用持续闪烁或循环动画表达保存状态。
- 训练正文限制合适行宽；用户可以调整字号、行距和阅读宽度。
- 虚拟键盘出现时，当前输入框和底部主要操作仍可见。
- 中文、日文和韩文 IME 处于组合输入期间，不触发提交、搜索或单键快捷键。

## 1.5\_交互反馈

所有写操作至少具有：

```text
初始
处理中
成功
失败
禁用
```

反馈方式：

| 情况 | 反馈 |
| --- | --- |
| 临时成功 | 不阻塞的 Toast |
| 字段错误 | 字段下方说明，并关联错误文本 |
| 保存失败 | 页面持续状态、重试和导出草稿 |
| 危险操作 | 显示影响范围的确认对话框 |
| 系统不可用 | 页面级错误和恢复入口 |
| 空数据 | 说明原因和一个明确的下一步 |

成功提示不应遮挡下一步操作；错误不能只写入开发者控制台。

## 1.6\_性能目标

性能报告统一记录构建模式、操作系统、CPU、内存、浏览器、数据规模、冷启动或热启动，并至少报告 P50 和 P95。正式验收只使用生产构建，Vite 开发模式的热更新时间不能作为结果。

固定测试数据集至少包含：

```text
1000 个训练单元
1000 条训练历史
100 个用户分类
100 个用户训练模块
10 MB 导入包
单篇 2 MB Markdown 原文
```

以下目标以长期支持环境中的普通开发机和固定测试数据为基线：

- 大厅冷启动首次可交互时间目标不超过 2.5 秒。
- 已缓存后的常规页面切换目标不超过 200 毫秒出现响应。
- 键盘输入到界面更新目标低于 50 毫秒，不被持久化阻塞。
- 自动保存不得执行长时间同步序列化。
- 训练库达到 1000 个单元时仍能在 300 毫秒内完成本地筛选反馈。
- 训练历史超过 1000 条时采用分页、增量加载或虚拟列表。
- 原文读取按文档加载，不扫描或传输整个知识源。
- 导入超过 10 MB 或 10000 个对象时必须显示进度，并允许取消。

硬件基线和浏览器版本由每次发布测试报告记录；不能只发布一个脱离环境的耗时数字。

## 1.7\_可靠性目标

- 自动保存成功后刷新页面，数据保持一致。
- 保存失败不会显示“已保存”。
- 应用异常关闭后恢复到最后成功修订。
- 数据迁移失败进入只读恢复模式。
- 导入失败不改变正式工作区。
- 知识源失联不阻止已冻结训练继续。
- 页面错误边界提供回到大厅，不形成白屏死路。
- 后台更新、训练保存和导入任务互不覆盖状态。

## 1.8\_本地服务与安全

- 本地服务默认只监听 `127.0.0.1`。
- 修改状态的接口需要本机会话令牌。
- 知识源路径解析最终绝对地址并拒绝根目录逃逸。
- 原文读取使用只读接口。
- 错误信息不返回令牌、完整用户答案或不必要的绝对路径。
- Markdown 和导入内容在显示前进行安全处理。
- Git 更新在工作区不干净时拒绝执行。

完整威胁模型、Host/Origin 校验、令牌、规范路径、符号链接和内容渲染要求见 [本地服务安全与威胁模型](local_service_security_and_threat_model.md)。

## 1.9\_统一错误模型

应用、存储、本地服务和导入器统一返回：

```text
error_code
user_message
technical_detail_ref
retryable
recovery_actions
correlation_id
```

- `error_code` 稳定、可测试，不直接展示内部异常类型。
- `user_message` 说明发生了什么和用户可以做什么。
- `technical_detail_ref` 指向本地脱敏诊断，不把堆栈直接显示给用户。
- `recovery_actions` 是固定动作标识，例如重试、导出草稿、回到大厅、恢复备份。
- `correlation_id` 不包含路径、答案或用户信息。

相同错误码在 Toast、页面错误和日志中保持同义。错误翻译不能改变是否可重试和数据是否安全的事实。

## 1.10\_浏览器与平台验收

长期支持矩阵：

| 平台 | 环境 | 浏览器验证 |
| --- | --- | --- |
| Windows | MSYS2 UCRT64 | 当前稳定版 Chromium 系浏览器 |
| Windows | MSYS2 UCRT32 | 当前稳定版 Chromium 系浏览器 |
| Linux | Ubuntu 22.04 | Chromium 和 Firefox 当前稳定版 |

每次发布至少验证：

- 首次安装。
- 普通启动。
- 无知识源启动。
- 配置文件型知识源。
- 创建并恢复训练会话。
- 回到大厅和继续训练。
- 浏览器刷新、后退和前进。
- 导出、清空测试工作区和重新导入。
- 最小卸载和干净卸载边界。
- NVDA + Chromium 完成大厅、训练和对话框关键流程。
- Firefox 完成键盘导航、焦点恢复和 200% 缩放。
- Windows 高对比度模式下关键状态仍可识别。

## 1.11\_功能完成定义

一个功能只有同时满足以下条件才算完成：

1. 正常路径可用。
2. 空状态、加载状态、失败状态和权限或边界状态已实现。
3. 键盘和窄屏可操作。
4. 数据所有权和删除影响明确。
5. 刷新与恢复行为通过验证。
6. 关键业务规则有自动化测试。
7. 用户文档和架构文档已同步。
8. `npm run check:data`、`npm run build` 和 `git diff --check` 通过。

## 1.12\_第一阶段验收清单

本清单是交付门槛，不是当前完成声明。逐项状态和当次验证证据见 [实现状态与版本边界](../implementation_status.md)。当前只完成内容校验、类型检查、生产构建、HTTP 深层路由探测和差异检查；真实浏览器、键盘、NVDA、性能和异常注入验收尚未完成。

### 1.12.1\_大厅与导航

- 大厅存在继续训练、进行中会话、待复习和最近训练。
- 每个训练页始终可以安全回到大厅。
- 浏览器前进和后退保持真实访问历史。
- 所有错误页都有回到大厅入口。

### 1.12.2\_训练会话

- 上一步、下一步、保存草稿和提交是独立操作。
- 所有阶段都可直接进入；未访问、进行中和已完成状态可由文本或图标识别，不能只靠颜色。
- 返回旧步骤修改答案不会清除后续答案。
- 保存失败阻止用户在不知情的情况下离开。

### 1.12.3\_管理

- 分类和模块不使用浏览器 `prompt()`。
- 删除可撤销，永久删除显示影响范围。
- 合并和导入先预览。
- 空状态提供明确的新建入口。

### 1.12.4\_训练体验

- 专题学习、提示提问、脱稿输出和专业案例分别具有明确完成条件。
- 查看答案不自动标记完成。
- 原文不可访问时训练仍可继续。
- 总结页能够回到大厅、复习薄弱项和查看历史。
