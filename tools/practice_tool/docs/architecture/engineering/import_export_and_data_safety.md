# 第1章\_导入导出与数据安全设计

## 1.1\_设计目标

导入导出用于迁移、备份和分享，但不同用途不能共用一个含义模糊的“工作区文件”。系统必须让用户在操作前知道将包含什么、影响什么以及能否撤销。

默认不导出私人答案、本机绝对路径、设备标识和知识源凭据。

## 1.2\_包类型

| 包类型 | 内容 | 默认包含用户答案 |
| --- | --- | --- |
| 训练模板包 | 分类结构、训练模块、训练计划和材料引用 | 否 |
| 工作区包 | 用户分类、模块、草稿和设置 | 否 |
| 训练历史包 | 会话、答案修订、自评和复习状态 | 是 |
| 完整备份包 | 工作区、历史、复习和必要元数据 | 是 |

所有包包含：

```text
format
schema_version
package_type
package_id
exported_at
product_version
content_digest
source_requirements
```

训练模板包只能保存源内相对路径，不得保存导出设备上的知识库绝对路径。

`content_digest` 只验证传输完整性，不能证明发布者身份。界面必须区分：

- 个人未签名包：摘要有效，但来源未验证。
- 官方签名包：摘要、签名和受信发布密钥均验证通过。
- 签名无效或未知签名包：拒绝自动信任，默认不允许导入可执行或富文本扩展。

官方包使用独立发布签名，第一版采用 Ed25519；签名覆盖清单、全部文件摘要、包类型和 Schema 版本。清单保存签名算法和密钥 ID。受信公钥随产品发布并支持轮换、撤销和旧包验证；私钥不进入客户端和仓库。不能把普通 SHA-256 摘要显示成“官方可信”。

## 1.3\_导出流程

```text
选择包类型
    ↓
预览包含与排除的数据
    ↓
显示隐私和知识源提醒
    ↓
生成不可变快照
    ↓
计算摘要
    ↓
保存文件
```

导出期间继续发生的训练修改不进入已经冻结的导出快照。导出失败不留下可被误认为完整备份的目标文件。

包含答案和笔记时必须再次确认，并显示数量和时间范围。第一版只提供未加密本地备份，并明确提示用户自行保管；在加密文件格式、KDF、认证加密、随机数、版本升级和恢复测试形成独立规范前，不提供自制“口令加密”。

未来加密备份至少采用经过评审的 KDF 和认证加密，保存随机盐、算法参数、nonce 和格式版本；口令不写入日志、配置或同步服务，产品也不提供绕过口令的恢复机制。

## 1.4\_导入预览

读取文件后先在临时区域完成解析和 Schema 校验，不能直接写入当前工作区。预览至少显示：

- 包类型和版本。
- 将创建、更新、跳过的对象数量。
- 分类和模块名称冲突。
- 稳定 ID 冲突。
- 缺失或不可访问的知识源。
- 需要重新映射的源 ID。
- 训练计划版本冲突。
- 是否包含答案、笔记或设备相关信息。

用户确认前不得修改正式数据。

## 1.5\_冲突策略

每种对象分别选择：

| 策略 | 行为 |
| --- | --- |
| 跳过 | 保留本地对象 |
| 作为副本 | 生成新 ID 并维护内部引用 |
| 合并 | 仅对支持合并的对象按业务规则合并 |
| 更新 | 相同稳定 ID 且 Schema 兼容时创建新修订 |

“覆盖全部”不是默认选项。训练历史和答案修订不支持无条件覆盖；相同修订 ID 但内容摘要不同视为损坏或冲突。

分类同名不是身份相同。训练模块合并只合并材料和分类关系，训练计划需要重新适配或保留为两个版本。

## 1.6\_知识源重新映射

导入包只声明：

```text
source_id
source_title
source_kind
document_id
relative_path
```

文件系统绝对位置由导入设备重新选择。映射后检查：

1. 目标位于用户明确选择的知识源根目录内。
2. 文档路径没有逃逸。
3. 文档稳定 ID 与引用一致。
4. 不一致时显示冲突，不能只因路径存在就接受。

知识源缺失不阻止导入训练模板，但相关原文入口标记为不可访问。

## 1.7\_事务与回滚

正式导入在单个逻辑事务中完成：

```text
创建导入检查点
    ↓
写入对象和关系
    ↓
校验引用闭包
    ↓
提交事务
```

任一步失败都回滚到检查点。浏览器存储不支持跨全部数据的一次原生事务时，应先导入到新数据库版本，校验成功后原子切换活动版本。

导入完成后生成报告，记录创建、合并、跳过、冲突和知识源缺失项。报告不包含完整用户答案。

## 1.8\_删除与回收

- 普通删除进入回收站。
- 清空回收站前显示分类、模块、会话、复习项和附件数量。
- 永久删除训练历史不能由删除分类或模块间接触发。
- 清除全部本地数据要求输入明确确认文本，并建议先导出完整备份。
- 卸载工具遵循软件所有权登记，不把用户外部知识库作为清理目标。

## 1.9\_文件与输入安全

- 限制导入文件大小和对象数量。
- JSON 解析前检查文件类型和基础结构。
- 拒绝原型污染字段和超深嵌套。
- 不执行导入包中的命令、脚本、HTML 或任意路径。
- Markdown 预览进行安全渲染，不执行内嵌脚本。Mermaid、SVG 和用户富文本使用严格安全模式、CSP 和隔离渲染，不允许任意链接协议、事件属性或外部脚本。
- 解压内容包时检查目录逃逸、重复路径和解压后总大小。
- 本地知识源读取只允许注册根目录内的受支持文档类型。

## 1.10\_隐私与同步

默认行为：

- 数据只保存在本地。
- 不启用遥测。
- 不上传答案、笔记和知识源路径。
- 日志隐藏用户答案和本机绝对路径。

未来多设备同步必须由用户主动启用，并单独说明同步范围、服务端存储、加密、冲突规则和删除传播。未完成这些设计前，不得把导出文件自动上传为“同步”。

本地接口、路径规范化和不可信内容渲染的具体安全要求见 [本地服务安全与威胁模型](local_service_security_and_threat_model.md)。

## 1.11\_验收条件

- 导入确认前正式工作区保持不变。
- 导入失败可以完整回滚。
- 模板包默认不包含答案、笔记和绝对路径。
- 缺失知识源的模板仍可导入并明确标记。
- 相同 ID、不同摘要的数据不会静默覆盖。
- 删除分类和模块不会间接永久删除历史。
- 恶意路径、脚本字段和超限文件被拒绝。
- 完整备份能够在空工作区恢复出相同对象数量和引用关系。
