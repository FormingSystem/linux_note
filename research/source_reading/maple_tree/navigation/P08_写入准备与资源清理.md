# 第8章\_写入准备与资源清理

## 8.1\_先决定由谁持有请求与锁

沿[总索引](P01_Linux_6.12_Maple范围源码阅读索引.md#1.1_从地址查询进入版本证据)读取固定 Linux 6.12.20。高级接口保留调用者 ma_state，位置、请求、写入分类与节点资源是不同状态轴。普通接口会在内部安排临时状态与部分锁操作；高级路径的输入和外围保护则须由调用者建立。教材完整例子见[P41](../../../../knowledge/linux/data_structures/红黑树_rb-tree/P41_Maple写入准备与锁边界.md#41.3_沿S0到S5区分位置与资源)。

VMA 复用状态的简短入口是[vma_find](../source_explanations/include/linux/mm.h.md#1.4_VMA查找复用高级游标)：它转换边界并复用状态，不代表已完成 VMA 锁协议。读写资源与查询位置的两项职责不应混在一个“高级接口更快”的结论里。

## 8.2\_沿S0到S5追踪资源

| 阶段 | 固定入口与状态副作用 | 唯一实现 |
| --- | --- | --- |
| S0 请求 | 调用者构造 index/last；mas_store 返回旧 entry 需结合错误状态 | [写入入口](../source_explanations/lib/maple_tree.c.md#1.13_高级写入与准备兑现) |
| S1 分析 | 写路径定位并决定 store_type、计算当前节点需求 | 同上；内部分类算法未在此全部展开 |
| S2 准备 | mas_preallocate 可能零需求成功；失败保存 ret 后清理、reset | 同上；[节点数量与分配](../source_explanations/lib/maple_tree.c.md#1.14_节点准备与补分配锁边界) |
| S2 补分配 | mas_nomem 在允许睡眠且内部锁模式时放锁分配、重获锁；有资源则置 start 并要求重试 | [补分配协议](../source_explanations/lib/maple_tree.c.md#1.14_节点准备与补分配锁边界) |
| S3 继续或取消 | 保持准备所需的树/请求条件；取消释放状态资源，不发布映射 | [清理](../source_explanations/lib/maple_tree.c.md#1.15_资源清理与批量准备) |
| S4 写入 | store_prealloc 消费准备；store_gfp 内部安排重试和最终清理 | [兑现](../source_explanations/lib/maple_tree.c.md#1.13_高级写入与准备兑现) |
| S5 退出 | mas_destroy 清除剩余资源和相关标志，批量状态还可能重平衡 | [状态清理与 expected_entries](../source_explanations/lib/maple_tree.c.md#1.15_资源清理与批量准备) |

mas_preallocate 经节点数量检查直接分配，不自动借用 mas_nomem 的放锁路径。GFP_KERNEL 与内部自旋锁不能因为接口名含 preallocate 就被视作相容；例子选择外部互斥锁并保持整个准备/兑现保护期。mas_nomem 返回 true 是重试信号，不能被解释成业务写入成功。

## 8.3\_资源与树的退出

mas_destroy 不释放所有业务映射；mtree_destroy/__mt_destroy 才是树销毁入口，前者自行取 ma_lock，后者要求调用者保护。见[锁责任](../source_explanations/lib/maple_tree.c.md#1.16_树销毁的锁责任)。外部锁例子用 __mt_destroy，静态业务对象仍由模块持有。

本批模块经 ARM 前端验证，宿主以明确资源与写入替身检查固定预分配、补分配和重试控制分支。目标 Kbuild/MODPOST/装卸、真实节点分配、批量重平衡和并发没有运行；完整分裂、反向查询、空洞选择也不因本批覆盖了接口声明就被宣称已完成。
