# 第2章\_别名路径怎样成为编号查询记录

`binding0`给出了一个名字，但驱动需要的是“本节点在binding这一组中的编号”。OF核心把路径描述整理为记录，以便消费者查询。本篇解释记录如何产生、读取怎样同步以及查询没有承担哪些分配责任。固定版本见 [总索引](../navigation/P01_OF绑定与别名源码阅读索引.md#1.1_版本与阅读任务)，完整交接见 [编号消费者导读](../navigation/P02_描述身份怎样交给匹配与编号消费者.md#2.2_编号查询的完成点由消费者接住)。

## 2.1\_启动扫描怎样建立节点与编号的关联

`unflatten_device_tree()`在建立节点树后调用`of_alias_scan(early_init_dt_alloc_memory_arch)`。扫描器接收一个分配函数指针，不能把其签名改写成无参数函数或宣称返回别名数量：这个版本真实返回类型是void。上游注释中残留的返回数量说法不能覆盖实际声明。

记录定义位于 [`drivers/of/of_private.h`](https://github.com/nxp-imx/linux-imx/blob/dfaf2136deb2af2e60b994421281ba42f1c087e0/drivers/of/of_private.h)：

```c
/**
 * @brief 仓库补充阅读说明：一个可编号别名的OF内部记录。
 * @note stem为柔性数组，分配时须追加字符串及终止字节的空间。
 */
struct alias_prop {
    struct list_head link;
    const char *alias;
    struct device_node *np;
    int id;
    char stem[];
};
```

`alias`指向原属性名，`np`指向路径查得的节点，`stem`在本记录后方保存去掉数字尾缀的字符串；`link`把它接入全局`aliases_lookup`。这不是一个只有name和phandle的临时字典，也没有给每个设备分配字符设备号。

上游扫描位于 [`drivers/of/base.c`](https://github.com/nxp-imx/linux-imx/blob/dfaf2136deb2af2e60b994421281ba42f1c087e0/drivers/of/base.c)。函数前部寻找`/aliases`及`/chosen`并处理stdout信息；下面只摘录与编号索引直接相关的循环，省略前部控制台分支，不能把片段编译成独立完整函数：

```c
/**
 * @brief 仓库补充阅读说明：of_alias_scan中的别名索引循环片段。
 * @note 外层已取得of_aliases，pp及dt_alloc由函数声明提供。
 */
for_each_property_of_node(of_aliases, pp) {
    const char *start = pp->name;
    const char *end = start + strlen(start);
    struct device_node *np;
    struct alias_prop *ap;
    int id, len;

    if (!strcmp(pp->name, "name") ||
        !strcmp(pp->name, "phandle") ||
        !strcmp(pp->name, "linux,phandle"))
        continue;
    np = of_find_node_by_path(pp->value);
    if (!np)
        continue;
    while (isdigit(*(end-1)) && end > start)
        end--;
    len = end - start;
    if (kstrtoint(end, 10, &id) < 0)
        continue;
    ap = dt_alloc(sizeof(*ap) + len + 1, __alignof__(*ap));
    if (!ap)
        continue;
    memset(ap, 0, sizeof(*ap) + len + 1);
    ap->alias = start;
    of_alias_add(ap, np, id, start, len);
}
```

`pp->value`直接交给路径查询，证明它在这里是字符串而不是phandle cell。数字从末尾向前识别，`kstrtoint(..., 10, ...)`按十进制转换；没有可解析尾缀、找不到节点或分配失败时，当前循环跳过，不会合成一个编号0。规范要求合法非空别名，不能把上述代码当作可处理任意恶意字节的通用字符串解析器。

内部`of_alias_add()`把np和id写入记录，以`strscpy(..., stem_len + 1)`保存stem，随后`list_add_tail()`加入`aliases_lookup`并打印可选调试信息。索引建立在启动阶段，代码没有在这段循环周围取得查询侧的of_mutex；不能因查询使用mutex，就虚构所有初始化写入也在同一把锁中进行。

这里还要保留一个实际实现边界：路径查询取得节点引用后，这段循环的部分continue分支未显式归还引用；成功记录则长期保存np。不能把源码“改良”为每个分支都有put后仍声称是原文，也不能复制这种启动内部路径作为普通消费者的生命周期模板。驱动自行查找节点时仍须遵守 [OF节点引用契约](../../../../knowledge/driver_model/device_tree/设备树+platform开发/P09_OF属性读取与节点引用生命周期.md)。

本路径构建的是启动索引。它不支持据此推导“以后每次查询都会重新读最新aliases属性”；若要依赖运行时重配置，必须另查所选版本的更新与撤销路径。本章教学实验通过重新部署并重启改变静态输入。

## 2.2\_查询只返回已有记录而不分配号码

`of_alias_get_id`接受节点指针和stem，在内部链表中找二者同时匹配的记录。它的成功返回值仅说明找到了id，设备号范围是否合适、是否已被占用、是否允许缺失都由消费者决定。

```c
/**
 * @brief 仓库补充阅读说明：按节点和stem查询已登记的别名编号。
 * @param np 驱动正在处理的描述节点。
 * @param stem 不含尾部数字的组名，例如binding或serial。
 * @return 匹配记录的id，未找到则-ENODEV。
 * @note 使用mutex的可睡眠查询；不分配新id，不改设备名字。
 */
int of_alias_get_id(struct device_node *np, const char *stem)
{
    struct alias_prop *app;
    int id = -ENODEV;

    mutex_lock(&of_mutex);
    list_for_each_entry(app, &aliases_lookup, link) {
        if (strcmp(app->stem, stem) != 0)
            continue;
        if (np == app->np) {
            id = app->id;
            break;
        }
    }
    mutex_unlock(&of_mutex);
    return id;
}
```

先比较stem，再比较节点指针，不是按compatible找同类设备，也不是按probe调用次数计数。找到后立即停止；若某节点在同一stem下出现多个记录，这段实现并没有替调用者诊断“板级命名歧义”。不要用重复指向来暗中表达优先级，应让板级描述与消费者规则清楚对应。

`mutex_lock`意味着调用方不能在不允许睡眠的上下文随意使用它。返回前已经解锁；整数被复制到调用者，后续注册设备号不会自动受到这把锁保护。导出声明为`EXPORT_SYMBOL_GPL`，模块使用还须符合相应许可证与链接规则；正文教学模块声明GPL。

附近的`of_alias_get_highest_id(stem)`用于查该组最高编号，也不是分配器。缺失返回负值与有效编号0必须区分；用`if (!id)`判断查找失败会把真正的第0路误判为缺失。

## 2.3\_把返回值落实到消费者的成功与回退

正文教学驱动允许`-ENODEV`，在每实例state中保存并显示absent；其sysfs对象身份来自设备实例，所以两个缺失编号不会冲突。固定i.MX串口的`imx_uart_probe()`则要求serial别名成功，再检查端口索引范围。两种策略使用同一接口，但服务契约不同。

如果某消费者要以此编号索引数组，必须先确认非负与上界；如果作为minor，必须按设备号分配协议处理占用和失败；如果缺失时动态分配，要在失败与S4移除时归还。OF核心只完成本节查询，不替这些后续动作兜底。

因此检查修改时，至少分别观察“交换路径、删除别名、编号超出消费者范围、第二实例失败、只解绑第一实例”。静态DTC能够验证字节和路径，不能验证消费者是否回退正确。运行期证据仍需在目标内核执行，本文没有将离线结果当作模块加载或串口功能验证。
