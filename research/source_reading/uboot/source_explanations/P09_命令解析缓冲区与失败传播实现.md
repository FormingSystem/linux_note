# 第9章\_命令解析缓冲区与失败传播实现

本篇是 [解析模块导读](../navigation/P09_命令字符串解析与失败边界导读.md) 对应的唯一实现展开；版本身份和原件摘要见该导读，公共上下文见 [总索引](../navigation/README.md)。先阅读 [教材中的缓冲区关系与两种失败时间线](../../../../knowledge/system_software/uboot/P09_命令字符串怎样跨过缓冲区与失败边界.md)，再将同一组对象落到局部变量。下列中文 Doxygen 注释均为仓库补充，代码是标明边界的上游裁剪，不是可独立编译的函数替代品。

## 9.1\_列表包装层何时取得可写副本

上游位置：`common/cli.c::run_command_list`。输入可来自 `common/autoboot.c::autoboot_command` 的零结尾环境字符串，也可来自 `cmd/source.c::image_source_script` 已取得地址和长度的脚本数据。包装层负责取得适合解析器的字符串，它不负责完成这些调用者之前的镜像验证。

```c
/**
 * @brief 仓库阅读说明：根据长度及解析器需求建立列表缓冲区。
 * @param cmd 满足长度约定的有效输入，不是待验证的任意地址。
 * @param len -1 表示零结尾；非负值表示调用者保证可读的字节数。
 * @note buff 的所有权由 need_buff 决定，只有本层分配的副本才释放。
 */
/* 裁剪自 run_command_list：保留决定复制的全部配置分支。 */
int need_buff = 1;
char *buff = (char *)cmd;
if (len == -1) {
    len = strlen(cmd);
#ifdef CONFIG_HUSH_PARSER
    need_buff = 0; /* 此分支依赖 Hush 不改写输入。 */
#else
    need_buff = strchr(cmd, '\n') != NULL;
#endif
}
if (need_buff) {
    buff = malloc(len + 1);
    if (!buff)
        return 1;
    memcpy(buff, cmd, len);
    buff[len] = '\0';
}
/* 中间按配置调用解析器，结果保存到 rcode。 */
if (need_buff)
    free(buff);
return rcode;
```

显式长度使 `need_buff` 保持 1，因此即使没有换行也复制。`len == -1` 才进入免分配判断；负数 -2 等不是另一个约定。去掉 `need_buff` 判断并无条件 `free(buff)` 会释放借来的地址；去掉复制却让 simple 切换行，则可能写只读数据或破坏调用者内容。

解析器选择顺序是 `CONFIG_HUSH_PARSER` → Hush；否则若 `CONFIG_CMDLINE` → simple 列表；两者都不选则调用 `board_run_command`。默认弱实现报告命令不可用并返回 1，平台可以提供实现；不能把这条回退写成必然继续进入 simple。

## 9.2\_单行副本怎样隔离环境变化并限定参数寿命

上游位置：`common/cli_simple.c::cli_simple_run_command`。函数先清除已有 Ctrl-C 状态，再拒绝空指针、空串和长度不小于 `CONFIG_SYS_CBSIZE` 的输入。长度检查后才 `strcpy` 到同样大小的 `cmdbuf`，为末尾零字节留位置。`str` 是下一条待处理文本的游标，`token` 指向本次文本，`sep` 找分隔位置；三者都借用 `cmdbuf`。

```c
/**
 * @brief 仓库阅读说明：在栈副本上切单条命令，并同步借出参数地址。
 * @note finaltoken 在下一轮展开时覆盖；argv 不拥有单独字符串。
 */
/* 裁剪自 cli_simple_run_command：省略前置检查、分隔符扫描与错误累计。 */
strcpy(cmdbuf, cmd);
/* 循环中的 token 与 sep 已由分号扫描选定。 */
token = str;
if (*sep) {
    str = sep + 1;
    *sep = '\0'; /* 本条终止，下一条起点已保存。 */
} else {
    str = sep;
}
cli_simple_process_macros(token, finaltoken, sizeof(finaltoken));
argc = cli_simple_parse_line(finaltoken, argv);
/* argc 非零后才进入 cmd_process；这里省略其分支。 */
```

扫描阶段在单引号之外接受未转义的分号，且检查 `sep != str`。因此不能用这个裁剪臆造“任意连续分号都自动跳过空命令”的规则。本文实验只比较正常非空令牌间的分隔；教学模型刻意没有实现完整的分号扫描。

更重要的是顺序：先切分，再展开，再拆参数，最后才调用 [命令分派实现](P08_命令记录与查找分派实现.md#8.3_两层回调怎样分别返回结果与重复能力)。展开结果不回流到本次分号扫描；`cmd_process` 返回后，下一轮可以重用 `finaltoken`。若命令回调把参数指针保存在长期对象里，后续覆盖和栈退出都会破坏它的有效期。

## 9.3\_展开状态和参数地址怎样从文本中形成

上游位置：`common/cli_simple.c::cli_simple_process_macros` 与 `cli_simple_parse_line`。展开函数的输入是当前 `token`，输出由调用者提供；`inputcnt` 跟踪剩余输入字符数，`outputcnt` 跟踪输出容量。`state` 的 0/1/2/3 分别对应普通文本、等待变量起始括号、变量名和单引号内部；完整转移含义见 [正文状态表](../../../../knowledge/system_software/uboot/P09_命令字符串怎样跨过缓冲区与失败边界.md#9.2_为什么变量展开不能替代执行一个命令列表)。

状态 2 用 `varname_start` 保存输入中的名字起点，遇到结束括号时复制到局部 `envname[CONFIG_SYS_CBSIZE]`，补零并调用 `env_get`。查到的值逐字符复制到输出；值里新出现的 `$` 不作为本次输入重新扫描。状态 3 复制字符并移除外层单引号；转义处理在不处于状态 3 时先移除一层反斜杠。这个状态机只完成该版本的有限展开，不提供完整 Shell 引号或递归求值语义。

```c
/**
 * @brief 仓库阅读说明：输出容量不足时终止字符串并报告截断。
 * @warning 此返回值在单行调用处未被检查，不能推出整条命令被拒绝。
 */
/* 裁剪自 cli_simple_process_macros 的结尾。 */
ret = inputcnt ? -ENOSPC : 0;
if (outputcnt) {
    *output = 0;
} else {
    *(output - 1) = 0;
    ret = -ENOSPC;
}
return ret;
```

输出刚好填满也要腾出末尾零字节，并报告 `-ENOSPC`。直接调用此函数还必须遵守其缓冲区前提；例如容量为零不能当作受支持的“只查询长度”方式。本路径传入的是非零大小的 `finaltoken`，且输入已被单行长度检查约束。没有这些调用上下文，不能把局部数组写成面向任意长外部字符串的验证器。

展开之后，参数函数跳过 `isblank` 认可的空白，把每个词的起点写入 `argv[nargs++]`，再把词尾空白改为 `\0`。这里没有再解释引号的状态，所以保护变量展开和保护带空格参数不是同一项能力。

```c
/**
 * @brief 仓库阅读说明：在原缓冲区切参数，返回数量而非独立字符串。
 */
/* 裁剪自 cli_simple_parse_line 的循环内部，省略空串退出分支。 */
argv[nargs++] = line;
while (*line && !isblank(*line))
    ++line;
/* 若已到字符串结尾，原函数设置 argv[nargs]=NULL 并返回。 */
*line++ = '\0';
/* 当循环因 nargs 达到 CONFIG_SYS_MAXARGS 而结束时： */
printf("** Too many args (max. %d) **\n", CONFIG_SYS_MAXARGS);
return nargs;
```

达到上限的路径返回已有数量，不返回负错误码，而且不能依赖这条退出路径补了 `argv[nargs] = NULL`。后续命令必须按 `argc` 使用参数。正常提前到字符串结尾的路径则会写末尾空指针。若要把超限统一改成拒绝执行，需要同时修改返回契约和调用者判断，单改提示文字没有作用。

## 9.4\_谁决定继续下一条下一行和下一个环境变量

上游位置：`common/cli_simple.c::cli_simple_run_command`、`cli_simple_run_command_list`，以及 `common/cli.c::run_command`、`do_run`。三个循环拥有各自的游标和失败状态：单行处理 `str`，列表处理 `line/next`，`do_run` 处理参数下标 `i`。它们只有在函数返回时才获得内层整体结果。

```c
/** @brief 仓库阅读说明：单行累计失败但继续扫描后续分号命令。 */
/* 裁剪自 cli_simple_run_command 的循环末尾和返回处。 */
if (cmd_process(flag, argc, argv, &repeatable, NULL))
    rc = -1;
if (had_ctrlc())
    return -1; /* 用户中断是提前退出分支。 */
/* 循环继续，最终： */
return rc ? rc : repeatable;
```

`rc` 一旦变为 -1 就不因下一条成功而清零；`repeatable` 则由分派层累积。空参数文本同样记失败并 `continue`。因此“任一失败”和“是否可重复”是两项状态，返回时失败优先。

列表层把换行改为零后，仅对非空行调用单行函数；若结果小于零，设 `rcode=1` 并 `break`。没有末尾换行的最后一行由循环后的 `if (rcode == 0 && *line)` 补执行，失败后不会再执行它。虽然接口收 `flag`，实际两处单行调用都传 **0**；上下文标志没有沿这条路径继续传播。

`run_command` 在 simple 分支把单行结果 -1 映射到 1，其余映射到 0。这样 `do_run` 才能用通常的非零失败判断逐个环境变量：

```c
/** @brief 仓库阅读说明：每个参数是环境变量名，失败阻止后续变量。 */
/* 裁剪自 do_run；原函数先要求 argc >= 2。 */
for (i = 1; i < argc; ++i) {
    char *arg = env_get(argv[i]);
    if (arg == NULL) {
        printf("## Error: \"%s\" not defined\n", argv[i]);
        return 1;
    }
    if (run_command(arg, flag | CMD_FLAG_ENV) != 0)
        return 1;
}
return 0;
```

`CMD_FLAG_ENV` 表示这次执行来自环境变量上下文，不是“把所有分号失败都变成停止”的开关。在 Hush 的 `run_command` 包装分支，它还用于加入 `FLAG_CONT_ON_NEWLINE`；simple 单行没有因此改变上述失败循环。`run` 的记录由 `cmd/nvedit.c` 在相应配置下登记，复用上一模块介绍的记录机制。

## 9.5\_重复能力怎样回到交互循环并受解析器配置约束

上游位置：`common/cli.c::run_command_repeatable` 和 `common/cli_simple.c::cli_simple_loop`。非 Hush 的重复包装直接返回单行 -1/0/1；Hush 分支把解析失败转成 -1，成功返回 0，因此这里不能把 simple 的重复策略外推为所有配置完全相同。

```c
/**
 * @brief 仓库阅读说明：空回车重用保存文本，结果决定能否继续保存。
 * @note 下列只保留常规输入路径，超时重启和 Ctrl-C 分支见原件。
 */
/* 裁剪自 cli_simple_loop；lastcommand 是静态数组。 */
flag = 0;
if (len > 0)
    strlcpy(lastcommand, console_buffer, CONFIG_SYS_CBSIZE + 1);
else if (len == 0)
    flag |= CMD_FLAG_REPEAT;
/* len == -1 的中断提示分支不调用下句。 */
rc = run_command_repeatable(lastcommand, flag);
if (rc <= 0)
    lastcommand[0] = 0;
```

清空首字符即可让保存字符串成为空串；这不是释放堆内存，因为数组静态存在。下一次空回车尝试的是空字符串，不能把旧参数地址复活。如果把 `rc <= 0` 误改成 `rc < 0`，成功但不可重复的命令文本会被保留，这才会改变交互行为；单纯改变普通 `run_command` 的归一化结果不能替代这个位置的判断。

还要留意此版本包装层的配置写法：`run_command` 使用 `CONFIG_IS_ENABLED(HUSH_PARSER)`，`run_command_repeatable` 和列表包装使用 `CONFIG_HUSH_PARSER` 条件。本文固定 proper 的所选配置讨论，不把宏写法差异抹平后推断所有 SPL 配置也具备同样路径。Hush 的控制结构、局部变量和环境变量区别见已保存的官方命令行文档；没有核对其内部状态机时，不为它套用本篇的 `cmdbuf/finaltoken` 所有权图。
