# 第9章\_命令字符串解析与失败边界导读

[命令解析正文](../../../../knowledge/system_software/uboot/P09_命令字符串怎样跨过缓冲区与失败边界.md) 已经比较分号与换行的失败行为。本导读按 [固定版本总索引](README.md) 追踪 U-Boot v2022.10 中实际承载文本、参数和执行结果的对象。这里的主要入口是 `common/cli.c` 与 `common/cli_simple.c`；命令登记和回调分派沿用 [上一模块](P08_命令注册与分派导读.md)，不重新展开。

## 9.1\_从输入来源沿存储所有权读到调用结束

先选定 simple 配置，再从输入来源进入，而不要把每个名字带 `run` 的函数排成一条必经调用链。自动启动字符串与脚本镜像都可能进入 `run_command_list`；`run` 命令的回调却通过 `run_command` 逐个处理环境变量。Hush 在公共包装层分支，不能把它画成 simple 的后续步骤。

| 阅读问题 | 保存状态的实际对象及消费者 | 唯一实现说明 |
| --- | --- | --- |
| 包装层能否修改调用者字符串 | `need_buff` 决定 `buff` 是借用地址还是堆副本 | [列表缓冲区](../source_explanations/P09_命令解析缓冲区与失败传播实现.md#9.1_列表包装层何时取得可写副本) |
| 执行命令后原环境可能变化怎么办 | 栈上 `cmdbuf` 维护当前行；`str/token/sep` 指向该数组 | [单行工作副本](../source_explanations/P09_命令解析缓冲区与失败传播实现.md#9.2_单行副本怎样隔离环境变化并限定参数寿命) |
| 展开后的字符和参数存在哪 | `finaltoken` 保存展开结果；`argv` 指向其内部；`state` 控制扫描 | [展开与切分](../source_explanations/P09_命令解析缓冲区与失败传播实现.md#9.3_展开状态和参数地址怎样从文本中形成) |
| 下一条、下一行、下一个变量由谁决定 | 单行 `rc`、列表 `rcode`、`do_run` 的循环各自决定推进 | [失败传播](../source_explanations/P09_命令解析缓冲区与失败传播实现.md#9.4_谁决定继续下一条下一行和下一个环境变量) |
| 空回车为什么有时不再执行 | 静态 `lastcommand` 保存字符串；交互返回值决定保留还是清空 | [重复与配置分支](../source_explanations/P09_命令解析缓冲区与失败传播实现.md#9.5_重复能力怎样回到交互循环并受解析器配置约束) |

按这个顺序阅读，可以在每一次返回时回答“哪些地址仍有效、哪一层还有待执行的文本”。错误返回不包含自动回滚；前面的命令如果已经修改环境或设备，解析器的局部 `rc` 不会撤销那些动作。
