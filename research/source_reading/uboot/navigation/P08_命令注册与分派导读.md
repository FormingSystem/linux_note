# 第8章\_命令注册与分派导读

[命令正文](../../../../knowledge/system_software/uboot/P08_命令名怎样找到镜像里的实现函数.md) 以已经拆好的 argc/argv 为入口，建立名字、记录和回调的关系。本模块沿 [固定版本总索引](README.md) 定位 U-Boot v2022.10 的构建选择、记录生成和调用路径，暂不深入解析器的字符状态机。

## 8.1\_先沿一个真实命令连接构建与运行

echo 的完整阅读顺序是配置项 → 目标文件 → 登记宏 → 记录区 → 匹配 → 回调。`main_loop` 在运行环境已准备后组织预启动、自动启动和交互入口，但具体是否进入交互循环还受配置和前面的控制流影响，不能从存在 `cli_loop` 调用就断言每次启动都出现提示符。

| 当前问题 | 状态或记录在哪里 | 唯一实现入口 |
| --- | --- | --- |
| 命令为什么进了当前镜像 | `cmd/Kconfig`、`cmd/Makefile` 选择对象，`cmd/echo.c` 提供记录 | [登记宏与构建选择](../source_explanations/P08_命令记录与查找分派实现.md#8.1_登记宏如何生成当前版本的命令记录) |
| 输入名字匹配谁 | 链接生成的 `cmd` 记录区 | [完整匹配与唯一缩写](../source_explanations/P08_命令记录与查找分派实现.md#8.2_查找为何先考虑完整匹配再接受唯一前缀) |
| 回调成功为何还可能不可重复 | `cmd_rep` 输出 `newrep`，分派层与调用者累积状态结合 | [结果与重复能力](../source_explanations/P08_命令记录与查找分派实现.md#8.3_两层回调怎样分别返回结果与重复能力) |

默认命令回调签名以本版 `include/command.h` 为准。官方开发文档有些示例使用了不同的参数写法或示例标识，复制时必须与当前结构声明核对，不能把描述性示例当作已经编译通过的新增命令。本次宿主实验验证的是精简分派模型，尚未执行完整 U-Boot 构建或目标命令。

## 8.2\_当前原件与旧稿的版本差异

旧稿的整数 `repeatable`、`cmd_tbl_t` 和直接调用 `cmd` 的片段保留其历史版本含义；本版改为 `struct cmd_tbl` 和 `cmd_rep` 交接。新增说明使用当前固定上游原件，不将厂商 2017 SDK 的近似代码冒充同一提交。
