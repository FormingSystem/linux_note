# 第10章\_自动引导选择与交互退路导读

本模块连接 [正文的策略推导](../../../../knowledge/system_software/uboot/P10_自动引导如何选择命令与保留维护入口.md) 与 [固定版本总索引](README.md)。关注“何时选命令、何时查输入、命令返回后去哪里”；命令解析和镜像装载不是这一层自动完成的保证。

## 10.1\_沿同一状态周期定位写入者与消费者

主循环、环境和静态策略变量运行在同一 CPU 的顺序路径中；控制台提供输入，实际命令产生自己的副作用。读源码时先确定普通自动引导还是受限执行，再检查两者不同的返回合同。

| 阶段 | 状态落点与协作 | 唯一实现说明 |
| --- | --- | --- |
| A0～A1 | 当前环境/控制树 → 局部 `s` 与静态 `stored_bootdelay` | [环境选择及控制树覆盖](../source_explanations/P10_自动引导选择与执行门实现.md#10.1_A0与A1_环境和控制树怎样形成候选) |
| A2～A3 | 延时/输入结果决定是否执行；输入分支可写静态 `menukey` | [短路、按键和菜单位置](../source_explanations/P10_自动引导选择与执行门实现.md#10.2_A2与A3_特殊延时如何决定是否读取输入) |
| A4 | 返回、Ctrl-C 恢复、菜单、CLI 或不可返回的错误路径 | [受限帮助器与CLI返回](../source_explanations/P10_自动引导选择与执行门实现.md#10.3_A4_受限执行与CLI返回怎样改变退路) |

先读 `main_loop` 的顺序，再分别展开 `bootdelay_process` 和 `autoboot_command`，最后从返回点追到 `cli_loop` 与外层循环。不能按“bootdelay”名字把输入等待放错位置，也不能按“secure”名字补出认证实现。

## 10.2\_证据与验证边界

版本为上游 v2022.10、提交 `4debc57a3da6c3f4d3f89a637e99206f4cea0a96`。`common/main.c`、`common/autoboot.c`、`common/cli.c`、`common/cli_simple.c` 和 `common/board_r.c` 的原件已在前面模块保存；本次另用以下文件核对环境后端、延时契约和配置入口。

| 上游相对路径及本地原件 | SHA-256 |
| --- | --- |
| [env/Kconfig](../upstream/v2022.10/env/Kconfig) | `62b4d9ac523fd3fb557f896c9f98447d2f5ba94f18aadd9b09804095e8a43390` |
| [doc/usage/environment.rst](../upstream/v2022.10/doc/usage/environment.rst) | `1f57ac81b9fd5c6eea5b4596230b6ee52bcb66c9c14da33e44f7eea19703eaf7` |
| [include/autoboot.h](../upstream/v2022.10/include/autoboot.h) | `7cb3ae2f0bf949257e7fc4e2553b954e24ed225586573f2c98823b1781c19eb5` |

正文宿主模型只比较延时和已有输入，不包含串口计时、口令验证或存储持久化。本次以 `-std=c11 -Wall -Wextra -Werror` 编译并执行正文模型，核对有输入、无输入以及错误改成 `delay > 0` 的对照。另从原件直接提取 `autoboot_command`、`abortboot_single_key`、`cli_process_fdt`，以宿主桩运行 14 个分支用例，覆盖空命令、特殊延时、Ctrl-C 恢复、菜单键时机及控制树覆盖。但桩返回的“按键”和“执行结果”不是目标板观察。本文没有把配置文档当作真实板恢复路径的成功记录。
