# 第1章\_ARM32链接布局与启动交接阅读索引

本页把 [从链接布局到启动阶段的交接](../../../../knowledge/system_software/uboot/P01_从链接布局到启动阶段的交接.md) 中的 S0～S5 落到固定版本源码。正文回答为什么要分阶段以及状态怎样交接；本索引负责版本、阅读顺序与文件位置；[实现说明](../source_explanations/P01_ARM32链接布局与启动实现.md) 承担唯一的裁剪代码解释。

## 1.1\_固定来源与验证边界

来源为 [U-Boot 官方项目镜像](https://github.com/u-boot/u-boot)，标签 `v2022.10` 解引用提交 `4debc57a3da6c3f4d3f89a637e99206f4cea0a96`。本地 `upstream/v2022.10/` 按上游相对路径保存原始文件；从固定提交取得文件并记录 SHA-256，没有修改其许可证、注释或代码。可从 [固定提交树](https://github.com/u-boot/u-boot/tree/4debc57a3da6c3f4d3f89a637e99206f4cea0a96) 追溯。

解释范围是通用 ARM32 主脚本、SPL 脚本和 `crt0.S` 路径，具体分支随配置变化。未宣称某块板选择了这些脚本，未构建完整 U-Boot，也未进行烧写、串口或目标 RAM 实测。链接语法实验使用独立教学材料，不能当作此 U-Boot 源码已经启动成功的证据。

## 1.2\_沿状态交接定位源码

先确认构建选出的脚本，再把布局与运行消费者对上。若直接从函数名猜职责，很容易把“记录目标位置”和“实际复制字节”混为一谈。

| 阅读问题 | 上游相对位置 | 精确讲解入口 |
| --- | --- | --- |
| 实际选择哪个脚本，谁展开宏 | `Makefile`、`scripts/Makefile.spl` | [脚本选择与预处理](../source_explanations/P01_ARM32链接布局与启动实现.md#1.1_先确定实际使用哪份脚本) |
| S2～S4 共享哪些边界 | `arch/arm/cpu/u-boot.lds`、`arch/arm/lib/sections.c` | [复制内容与阶段数据](../source_explanations/P01_ARM32链接布局与启动实现.md#1.2_把输出布局分成复制内容与阶段数据) |
| 谁在 S2 复制，谁在 S3 修正 | `arch/arm/lib/relocate.S` | [复制与重定位循环](../source_explanations/P01_ARM32链接布局与启动实现.md#1.3_复制区间与重定位记录不是同一段数据) |
| BSS 在哪一步才清零 | `arch/arm/lib/crt0.S` | [BSS 条件路径](../source_explanations/P01_ARM32链接布局与启动实现.md#1.4_谁清_BSS_要沿_crt0_的条件分支判断) |
| 条目如何形成连续数组 | `include/linker_lists.h`、`include/command.h` | [链接列表协议](../source_explanations/P01_ARM32链接布局与启动实现.md#1.5_链接列表怎样从声明变成有边界的数组) |
| S0 的 GD 空间怎样准备 | `common/init/board_init.c` | 先查保留区计算，再查初始化；不要把 GD 清零当成全部 BSS 清零 |
| S1 与 S5 各有哪些初始化工作 | `common/board_f.c`、`common/board_r.c` | 对照各自序列与配置，区分准备目标和运行后期子系统 |
| SPL 的构建和执行有何差异 | `arch/arm/cpu/u-boot-spl.lds`、`common/spl/spl.c`、`doc/develop/spl.rst` | 先读 [正文 SPL 对照](../../../../knowledge/system_software/uboot/P01_从链接布局到启动阶段的交接.md#1.6_把_SPL_放回同一个交接模型_而不是删掉所有复杂功能)，再查选中的分支 |

后面三行只提供模块阅读任务，不在导航里复制函数体。`doc/arch/arm64.rst` 是核对架构边界的材料，不把它与 ARM32 REL 循环拼成一条调用链；设备模型文档用于区分驱动声明、绑定和探测。
