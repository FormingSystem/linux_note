# 第14章\_页缓存的数据有效性与修改交接

读写分派已经交付file、位置和缓冲；本模块继续追踪普通缓存后端怎样找到内容、等待填充并接纳修改。场景与练习见 [页缓存正文](../../../../knowledge/kernel_subsystems/vfs/P15_address_space_folio与页缓存.md#15.1_为什么缓存应跟随文件而不是一次打开)，固定源码身份见 [总索引](P01_Linux_6.12_VFS源码阅读索引.md#1.1_先固定源码身份与运行证据)。

## 14.1\_把共享缓存与单次请求分开追踪

C0选mapping，C1查找或创建并取得本次持有，C2建立可用内容或可修改范围，C3复制实际数据，C4接纳和报告结果，C5归还本次资源。folio引用、成员关系、锁、有效位、脏位与写回位是多组状态，不能合并成一个完成枚举。

```mermaid
flowchart LR
    file["file.f_mapping与f_ra"] -->|"共享缓存和本次访问历史"| mapping["address_space<br/>i_pages、a_ops、invalidate_lock"]
    mapping -->|"C1查询或发布"| folio["folio引用、mapping/index与独立状态位"]
    folio -->|"C2填充或准备修改"| ops["read_folio或write_begin/end"]
    ops -->|"C3实际复制"| iter["iov_iter及kiocb.ki_pos"]
    iter -->|"C4复制量或接纳量"| result["结果和缓存修改"]
    result -->|"C5配对归还"| folio
```

pagecache索引由inode关联的mapping共享，f_ra历史归具体file；重新open不会复制整个缓存。实现表把查询、完成和修改拆开阅读，避免从一个函数名猜完整责任。

## 14.3\_将重试和短进度放回请求周期

```mermaid
sequenceDiagram
    autonumber
    participant R as 缓存读请求
    participant X as mapping.i_pages
    participant F as folio及填充者
    R->>X: C1查找并取得引用
    alt 无项
        R->>X: 预读或竞争发布
        X-->>R: 成功或EEXIST后重新查询
    end
    alt 数据尚未有效
        R->>F: C2检查归属和锁，填充或等待
        F-->>R: 完成后检查有效性，截断则重新查询
    end
    alt 获得可用批次
        R->>R: C3重新读取size并复制
        R->>R: C4保留已经复制的正进度
    else 无批次且错误
        R->>R: C4有进度则保留，否则报告错误
    end
    R->>F: C5逐项归还本次引用
```

写路径用准备/复制/结束协议替换C2～C4，资源由具体结束方法按约定归还；不能把读路径的批次folio_put直接照搬到写调用者。Dirty与Writeback组合留给下一模块追踪，不在本页凭一个状态图推断持久化。
