# 第2章\_描述符请求与托管释放

一次 get 返回描述符，看起来只交出了一个地址，实际还交出了请求占用、对象引用和已经尝试完成的方向配置。本页按它们建立与撤销的次序阅读。版本来自 [总索引](../navigation/P01_Linux_6.12_GPIO源码阅读索引.md#1.1_版本身份与阅读路线)，先修关系见 [请求交接导读](../navigation/P02_线路对象怎样完成请求与退出.md#2.2_查找保护怎样交接给请求持有)。中文 Doxygen 是仓库补充，C 函数体来自该固定版本。

## 2.1\_查找为何必须交接到请求后才能返回

上游相对位置：`drivers/gpio/gpiolib.c`，`gpiod_find_and_request()`。公共 get 路径把 device/fwnode、功能名和 index 交到这里。源码把查找和 `gpiod_request()` 放在同一个全局 SRCU 作用域内；取得普通请求后才离开并进行配置。

```c
/**
 * @brief 在查找保护内取得请求，再配置；仅对本次已经取得的请求执行失败put。
 * @note 仓库补充的中文阅读说明；下方为上游源码，裁剪处另有标注。
 */
struct gpio_desc *gpiod_find_and_request(struct device *consumer,
					 struct fwnode_handle *fwnode,
					 const char *con_id,
					 unsigned int idx,
					 enum gpiod_flags flags,
					 const char *label,
					 bool platform_lookup_allowed)
{
	unsigned long lookupflags = GPIO_LOOKUP_FLAGS_DEFAULT;
	const char *name = function_name_or_default(con_id);
	/*
	 * scoped_guard() is implemented as a for loop, meaning static
	 * analyzers will complain about these two not being initialized.
	 */
	struct gpio_desc *desc = NULL;
	int ret = 0;

	scoped_guard(srcu, &gpio_devices_srcu) {
		desc = gpiod_find_by_fwnode(fwnode, consumer, con_id, idx,
					    &flags, &lookupflags);
		if (gpiod_not_found(desc) && platform_lookup_allowed) {
			/*
			 * Either we are not using DT or ACPI, or their lookup
			 * did not return a result. In that case, use platform
			 * lookup as a fallback.
			 */
			dev_dbg(consumer,
				"using lookup tables for GPIO lookup\n");
			desc = gpiod_find(consumer, con_id, idx, &lookupflags);
		}

		if (IS_ERR(desc)) {
			dev_dbg(consumer, "No GPIO consumer %s found\n", name);
			return desc;
		}

		/*
		 * If a connection label was passed use that, else attempt to use
		 * the device name as label
		 */
		ret = gpiod_request(desc, label);
	}
	if (ret) {
		if (!(ret == -EBUSY && flags & GPIOD_FLAGS_BIT_NONEXCLUSIVE))
			return ERR_PTR(ret);

		/*
		 * This happens when there are several consumers for
		 * the same GPIO line: we just return here without
		 * further initialization. It is a bit of a hack.
		 * This is necessary to support fixed regulators.
		 *
		 * FIXME: Make this more sane and safe.
		 */
		dev_info(consumer, "nonexclusive access to GPIO for %s\n", name);
		return desc;
	}

	ret = gpiod_configure_flags(desc, con_id, lookupflags, flags);
	if (ret < 0) {
		gpiod_put(desc);
		dev_err(consumer, "setup of GPIO %s failed: %d\n", name, ret);
		return ERR_PTR(ret);
	}

	gpiod_line_state_notify(desc, GPIOLINE_CHANGED_REQUESTED);

	return desc;
}
```

`gpiod_not_found()` 只识别 `-ENOENT`，加上 `platform_lookup_allowed` 才启用平台表 fallback。它不会把 Provider 尚未就绪之类错误统一转成另一种查找。配置失败发生在请求成功以后，因此此时调用 put 合理；反过来，busy 表示别人的占用，本次不能替别人 put。

非独占分支是固定稳压器等历史使用场景的特例。源码在 busy 且指定该 flag 时直接返回描述符，跳过后续配置，并标有 FIXME/hack；不能把它推广为多个任意 Consumer 可以独立修改同一线路。调用者若用这个分支，必须理解所属框架自己的共享协议。

## 2.2\_原子占用怎样与Provider请求及对象引用配合

`gpiod_request_commit()` 先取得受保护的 chip，再用原子位操作竞争同一描述符。这个原子操作关闭的是两个普通请求都看见空闲的窗口，并不把后面所有回调和内存分配组成原子事务。

```c
/**
 * @brief S3竞争REQUESTED后调用可选request并建立标签；错误出口按实际源码只清位。
 * @note 仓库补充的中文阅读说明；下方为上游源码，裁剪处另有标注。
 */
static int gpiod_request_commit(struct gpio_desc *desc, const char *label)
{
	unsigned int offset;
	int ret;

	CLASS(gpio_chip_guard, guard)(desc);
	if (!guard.gc)
		return -ENODEV;

	if (test_and_set_bit(FLAG_REQUESTED, &desc->flags))
		return -EBUSY;

	/* NOTE:  gpio_request() can be called in early boot,
	 * before IRQs are enabled, for non-sleeping (SOC) GPIOs.
	 */

	if (guard.gc->request) {
		offset = gpio_chip_hwgpio(desc);
		if (gpiochip_line_is_valid(guard.gc, offset))
			ret = guard.gc->request(guard.gc, offset);
		else
			ret = -EINVAL;
		if (ret)
			goto out_clear_bit;
	}

	if (guard.gc->get_direction)
		gpiod_get_direction(desc);

	ret = desc_set_label(desc, label ? : "?");
	if (ret)
		goto out_clear_bit;

	return 0;

out_clear_bit:
	clear_bit(FLAG_REQUESTED, &desc->flags);
	return ret;
}
```

注意两个容易从函数名猜错的细节：`gpiod_get_direction()` 在这里用于刷新软件观察，返回值没有被检查为本次请求失败；`desc_set_label()` 却会返回错误并走清位出口。若 Provider request 已成功而标签失败，这个 commit 出口没有调用 Provider free。本页如实记录代码，不补出一个不存在的自动撤销过程，也不把此边界扩大为所有请求都会泄漏。

外层 `gpiod_request()` 负责引用交接。模块引用先取得；commit 失败时放回模块引用，成功才增加登记对象引用。

```c
/**
 * @brief 请求成功保留module和gdev引用，失败不建立本次长期gdev持有。
 * @note 仓库补充的中文阅读说明；下方为上游源码，裁剪处另有标注。
 */
int gpiod_request(struct gpio_desc *desc, const char *label)
{
	int ret = -EPROBE_DEFER;

	VALIDATE_DESC(desc);

	if (try_module_get(desc->gdev->owner)) {
		ret = gpiod_request_commit(desc, label);
		if (ret)
			module_put(desc->gdev->owner);
		else
			gpio_device_get(desc->gdev);
	}

	if (ret)
		gpiod_dbg(desc, "%s: status %d\n", __func__, ret);

	return ret;
}
```

`VALIDATE_DESC` 对可选 NULL 描述符与错误指针有专门处理，因此不要把该内部函数的所有输入都按有效普通请求推演。对有效 desc，初始 `-EPROBE_DEFER` 只覆盖未成功取得模块引用的路径；commit 还可能返回 busy、无设备或 Provider 的错误，不能把一切失败统称为延迟重试。

## 2.3\_托管请求怎样补上设备退出动作

上游相对位置：`drivers/gpio/gpiolib-devres.c`。`devm_gpiod_get()` 只是把 index 0 交给下面的 get-index 包装。包装先完成普通 get，再为这次持有登记设备资源动作；它没有另写一套线路查找算法。

```c
/**
 * @brief 普通请求成功后登记devres；记录分配失败时立即put刚取得的描述符。
 * @note 仓库补充的中文阅读说明；下方为上游源码，裁剪处另有标注。
 */
struct gpio_desc *__must_check devm_gpiod_get_index(struct device *dev,
						    const char *con_id,
						    unsigned int idx,
						    enum gpiod_flags flags)
{
	struct gpio_desc **dr;
	struct gpio_desc *desc;

	desc = gpiod_get_index(dev, con_id, idx, flags);
	if (IS_ERR(desc))
		return desc;

	/*
	 * For non-exclusive GPIO descriptors, check if this descriptor is
	 * already under resource management by this device.
	 */
	if (flags & GPIOD_FLAGS_BIT_NONEXCLUSIVE) {
		struct devres *dres;

		dres = devres_find(dev, devm_gpiod_release,
				   devm_gpiod_match, &desc);
		if (dres)
			return desc;
	}

	dr = devres_alloc(devm_gpiod_release, sizeof(struct gpio_desc *),
			  GFP_KERNEL);
	if (!dr) {
		gpiod_put(desc);
		return ERR_PTR(-ENOMEM);
	}

	*dr = desc;
	devres_add(dev, dr);

	return desc;
}
```

记录中保存的是 `gpio_desc *`，释放回调如下。其参数 `res` 指向保存指针的内存，所以需要先解引用 `struct gpio_desc **`，再 put 其中的描述符。

```c
/**
 * @brief 设备资源清理取出已保存的desc并交给普通put路径。
 * @note 仓库补充的中文阅读说明；下方为上游源码，裁剪处另有标注。
 */
static void devm_gpiod_release(struct device *dev, void *res)
{
	struct gpio_desc **desc = res;

	gpiod_put(*desc);
}
```

普通请求成功而 devres 分配失败时，包装自己 put，不会等待设备退出，因为这次动作根本没有登记。非独占请求还检查同一个 device 是否已经托管相同描述符，避免重复登记；这不是一般 GPIO 共享保证。

设备 probe 回滚和解绑可以触发 devres 清理，但该记录不知道私有线程、工作项或硬件业务何时停止。驱动必须先让这些使用者退出，再允许描述符被释放。其他 fwnode 包装可能采用不同的记录分配顺序，不能把这里“先 get 后 alloc”推广到全部 devm 接口。

## 2.4\_释放撤销占用而不是恢复寄存器快照

上游相对位置：`drivers/gpio/gpiolib.c`，`gpiod_free_commit()` 和 `gpiod_free()`。普通 put 最终走到这组释放动作。先观察哪些操作确实存在，再推断释放后的保证。

```c
/**
 * @brief 可用chip上的普通释放清请求语义和标签，外层放引用；未无条件重设方向或电平。
 * @note 仓库补充的中文阅读说明；下方为上游源码，裁剪处另有标注。
 */
static void gpiod_free_commit(struct gpio_desc *desc)
{
	unsigned long flags;

	might_sleep();

	CLASS(gpio_chip_guard, guard)(desc);

	flags = READ_ONCE(desc->flags);

	if (guard.gc && test_bit(FLAG_REQUESTED, &flags)) {
		if (guard.gc->free)
			guard.gc->free(guard.gc, gpio_chip_hwgpio(desc));

		clear_bit(FLAG_ACTIVE_LOW, &flags);
		clear_bit(FLAG_REQUESTED, &flags);
		clear_bit(FLAG_OPEN_DRAIN, &flags);
		clear_bit(FLAG_OPEN_SOURCE, &flags);
		clear_bit(FLAG_PULL_UP, &flags);
		clear_bit(FLAG_PULL_DOWN, &flags);
		clear_bit(FLAG_BIAS_DISABLE, &flags);
		clear_bit(FLAG_EDGE_RISING, &flags);
		clear_bit(FLAG_EDGE_FALLING, &flags);
		clear_bit(FLAG_IS_HOGGED, &flags);
#ifdef CONFIG_OF_DYNAMIC
		WRITE_ONCE(desc->hog, NULL);
#endif
		desc_set_label(desc, NULL);
		WRITE_ONCE(desc->flags, flags);

		gpiod_line_state_notify(desc, GPIOLINE_CHANGED_RELEASED);
	}
}

void gpiod_free(struct gpio_desc *desc)
{
	VALIDATE_DESC_VOID(desc);

	gpiod_free_commit(desc);
	module_put(desc->gdev->owner);
	gpio_device_put(desc->gdev);
}
```

commit 只有在 chip 仍可用且请求位存在时才调用可选 free 回调和清理这些标志。它没有清 `FLAG_IS_OUT`，也没有调用 direction-input 或 set-0；因此不能承诺释放后成为输入、低电平，或恢复到启动状态。具体 free 回调可能另有动作，必须沿 Provider 继续读。

芯片已撤销的防护路径也不能按普通清标志过程描述：guard 看到 NULL 时不再调用旧 Provider，外层仍按持有协议放下引用。上层必须只释放自己有效持有的请求；把 stale 指针再次 put 不会因为函数名叫 free 就自动合法。

请求、配置和释放的完整实现依据分别是固定源码 [gpiolib.c请求区](https://github.com/nxp-imx/linux-imx/blob/dfaf2136deb2af2e60b994421281ba42f1c087e0/drivers/gpio/gpiolib.c#L2315)、[查找区](https://github.com/nxp-imx/linux-imx/blob/dfaf2136deb2af2e60b994421281ba42f1c087e0/drivers/gpio/gpiolib.c#L4320) 和 [devres包装](https://github.com/nxp-imx/linux-imx/blob/dfaf2136deb2af2e60b994421281ba42f1c087e0/drivers/gpio/gpiolib-devres.c#L112)。回到 [失败位置导读](../navigation/P02_线路对象怎样完成请求与退出.md#2.3_把失败位置和清理范围逐一对应)，可以用相同 S2～S7 检查每个错误出口是否只清理了自己取得的状态。
