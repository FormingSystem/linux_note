# 第3章\_逻辑值怎样变成方向与电平

Consumer 要求“断言 reset”时，公共层不能直接把 1 写进数据寄存器：active-low 会反相，开漏可能需要停止驱动，Provider 还可能走可睡眠总线。本页把这几步按真实源码连起来。版本与配置见 [阅读索引](../navigation/P01_Linux_6.12_GPIO源码阅读索引.md#1.1_版本身份与阅读路线)，动作的生命周期位置见 [S4到S5导读](../navigation/P02_线路对象怎样完成请求与退出.md#2.4_从方向配置走到运行和设备退出)。所有函数来自 `drivers/gpio/gpiolib.c`，中文 Doxygen 为仓库补充。

## 3.1\_输入方向成功以后为什么仍可能返回失败

`gpiod_direction_input()` 不只调用一次方向回调。它先验证 Provider 的能力组合，完成方向步骤后更新软件标志，再尝试 bias 配置；后一步有自己的失败返回。因此返回负值并不等于本次操作完全没有生效。

```c
/**
 * @brief 输入方向步骤成功后先清输出标志，再设置bias；后一步失败不回滚前一步。
 * @note 仓库补充的中文阅读说明；下方为上游源码，裁剪处另有标注。
 */
int gpiod_direction_input(struct gpio_desc *desc)
{
	int ret = 0;

	VALIDATE_DESC(desc);

	CLASS(gpio_chip_guard, guard)(desc);
	if (!guard.gc)
		return -ENODEV;

	/*
	 * It is legal to have no .get() and .direction_input() specified if
	 * the chip is output-only, but you can't specify .direction_input()
	 * and not support the .get() operation, that doesn't make sense.
	 */
	if (!guard.gc->get && guard.gc->direction_input) {
		gpiod_warn(desc,
			   "%s: missing get() but have direction_input()\n",
			   __func__);
		return -EIO;
	}

	/*
	 * If we have a .direction_input() callback, things are simple,
	 * just call it. Else we are some input-only chip so try to check the
	 * direction (if .get_direction() is supported) else we silently
	 * assume we are in input mode after this.
	 */
	if (guard.gc->direction_input) {
		ret = guard.gc->direction_input(guard.gc,
						gpio_chip_hwgpio(desc));
	} else if (guard.gc->get_direction &&
		  (guard.gc->get_direction(guard.gc,
					   gpio_chip_hwgpio(desc)) != 1)) {
		gpiod_warn(desc,
			   "%s: missing direction_input() operation and line is output\n",
			   __func__);
		return -EIO;
	}
	if (ret == 0) {
		clear_bit(FLAG_IS_OUT, &desc->flags);
		ret = gpio_set_bias(desc);
	}

	trace_gpio_direction(desc_to_gpio(desc), 1, ret);

	return ret;
}
```

有 `direction_input` 却没有读取能力会返回 `-EIO`。没有方向回调时，框架允许固定输入设备，但若有 `get_direction` 就用它验证当前确为输入；没有这个查询能力才按固定输入条件继续。`FLAG_IS_OUT` 的更新点在方向步骤成功之后、bias 结果之前，调试时必须把返回错误和已经发生的状态改变同时记录。

## 3.2\_逻辑输出怎样选择主动驱动或释放线路

输出先解释逻辑值，再决定电气行为。active-low 只改变逻辑到物理的映射；open-drain/open-source 再决定对应物理值应主动驱动还是释放。两组 flags 属于不同语义轴，不能把“低有效”直接等同于“开漏”。

```c
/**
 * @brief 先转换逻辑极性并检查IRQ用途，再尝试硬件电气模式或方向模拟。
 * @note 仓库补充的中文阅读说明；下方为上游源码，裁剪处另有标注。
 */
int gpiod_direction_output(struct gpio_desc *desc, int value)
{
	unsigned long flags;
	int ret;

	VALIDATE_DESC(desc);

	flags = READ_ONCE(desc->flags);

	if (test_bit(FLAG_ACTIVE_LOW, &flags))
		value = !value;
	else
		value = !!value;

	/* GPIOs used for enabled IRQs shall not be set as output */
	if (test_bit(FLAG_USED_AS_IRQ, &flags) &&
	    test_bit(FLAG_IRQ_IS_ENABLED, &flags)) {
		gpiod_err(desc,
			  "%s: tried to set a GPIO tied to an IRQ as output\n",
			  __func__);
		return -EIO;
	}

	if (test_bit(FLAG_OPEN_DRAIN, &flags)) {
		/* First see if we can enable open drain in hardware */
		ret = gpio_set_config(desc, PIN_CONFIG_DRIVE_OPEN_DRAIN);
		if (!ret)
			goto set_output_value;
		/* Emulate open drain by not actively driving the line high */
		if (value) {
			ret = gpiod_direction_input(desc);
			goto set_output_flag;
		}
	} else if (test_bit(FLAG_OPEN_SOURCE, &flags)) {
		ret = gpio_set_config(desc, PIN_CONFIG_DRIVE_OPEN_SOURCE);
		if (!ret)
			goto set_output_value;
		/* Emulate open source by not actively driving the line low */
		if (!value) {
			ret = gpiod_direction_input(desc);
			goto set_output_flag;
		}
	} else {
		gpio_set_config(desc, PIN_CONFIG_DRIVE_PUSH_PULL);
	}

set_output_value:
	ret = gpio_set_bias(desc);
	if (ret)
		return ret;
	return gpiod_direction_output_raw_commit(desc, value);

set_output_flag:
	/*
	 * When emulating open-source or open-drain functionalities by not
	 * actively driving the line (setting mode to input) we still need to
	 * set the IS_OUT flag or otherwise we won't be able to set the line
	 * value anymore.
	 */
	if (ret == 0)
		set_bit(FLAG_IS_OUT, &desc->flags);
	return ret;
}
```

以 active-low 的开漏 reset 为例，逻辑 1 变为物理 0，模拟路径主动拉低；逻辑 0 变为物理 1，模拟路径调用输入方向以释放输出驱动，由外部上拉形成高电平。这个值依赖电路上拉，输入方向本身没有制造高电平。

`set_output_flag` 在模拟释放成功后重新设置 `FLAG_IS_OUT`，保留输出用途；这正是软件方向与当前硬件方向可以不同的源码证据。IRQ 检查则要求“作为 IRQ 使用”与“IRQ 已使能”两位同时存在才拒绝输出，不能删掉其中一个条件后解释为源码原义。

| 当前条件 | 路径中的真实动作 | 不能过度推出的结论 |
| --- | --- | --- |
| 硬件接受开漏配置 | 进入bias与raw输出提交 | 并非所有Provider都需要方向模拟 |
| 不接受开漏且物理值为1 | 切输入，成功后标为输出用途 | 输入并不保证线上已变高，仍依赖电路 |
| 不接受开漏且物理值为0 | 进入bias与raw提交 | 公共层并未额外锁住其他线路寄存器 |
| 普通推挽请求 | 调用push-pull配置后继续 | 该配置返回值在此未检查，不是所有配置错误都传播 |

## 3.3\_raw提交怎样交给Provider并记录结果

逻辑路径最后交给 raw commit 的已经是物理值。raw 输出入口直接调用它，跳过上一节的逻辑反相及开漏/开源选择。因此“raw只少一次反相”不足以描述它的全部行为差异。

```c
/**
 * @brief 按物理值调用方向输出或固定输出set，成功后记录输出用途。
 * @note 仓库补充的中文阅读说明；下方为上游源码，裁剪处另有标注。
 */
static int gpiod_direction_output_raw_commit(struct gpio_desc *desc, int value)
{
	int val = !!value, ret = 0;

	CLASS(gpio_chip_guard, guard)(desc);
	if (!guard.gc)
		return -ENODEV;

	/*
	 * It's OK not to specify .direction_output() if the gpiochip is
	 * output-only, but if there is then not even a .set() operation it
	 * is pretty tricky to drive the output line.
	 */
	if (!guard.gc->set && !guard.gc->direction_output) {
		gpiod_warn(desc,
			   "%s: missing set() and direction_output() operations\n",
			   __func__);
		return -EIO;
	}

	if (guard.gc->direction_output) {
		ret = guard.gc->direction_output(guard.gc,
						 gpio_chip_hwgpio(desc), val);
	} else {
		/* Check that we are in output mode if we can */
		if (guard.gc->get_direction &&
		    guard.gc->get_direction(guard.gc, gpio_chip_hwgpio(desc))) {
			gpiod_warn(desc,
				"%s: missing direction_output() operation\n",
				__func__);
			return -EIO;
		}
		/*
		 * If we can't actively set the direction, we are some
		 * output-only chip, so just drive the output as desired.
		 */
		guard.gc->set(guard.gc, gpio_chip_hwgpio(desc), val);
	}

	if (!ret)
		set_bit(FLAG_IS_OUT, &desc->flags);
	trace_gpio_value(desc_to_gpio(desc), 0, val);
	trace_gpio_direction(desc_to_gpio(desc), 0, ret);
	return ret;
}

int gpiod_direction_output_raw(struct gpio_desc *desc, int value)
{
	VALIDATE_DESC(desc);
	return gpiod_direction_output_raw_commit(desc, value);
}
```

有 `direction_output` 时，由 Provider 一起处理方向和初值，避免公共层先开输出、再补值造成不必要窗口；具体无毛刺保证仍由硬件和回调顺序决定。没有该回调的固定输出设备可走 set 路径，必要时先用 get-direction 验证。这里 `set` 返回 void，因此 raw commit 没有从该回调取得总线错误的通道；返回成功不能当成额外的物理回读确认。

## 3.4\_运行时setter沿用逻辑语义却不返回写错误

方向建立以后，普通 set 仍需要处理 active-low 和单向驱动模拟。下面先展示共用的转换路径，再展示两种调用上下文入口。`nocheck` 的含义是调用前的描述符检查在外层，并不意味着没有极性和电气语义。

```c
/**
 * @brief 普通与可睡眠入口复用逻辑转换；两者都不向调用者返回写错误。
 * @note 仓库补充的中文阅读说明；下方为上游源码，裁剪处另有标注。
 */
static void gpiod_set_value_nocheck(struct gpio_desc *desc, int value)
{
	if (test_bit(FLAG_ACTIVE_LOW, &desc->flags))
		value = !value;
	if (test_bit(FLAG_OPEN_DRAIN, &desc->flags))
		gpio_set_open_drain_value_commit(desc, value);
	else if (test_bit(FLAG_OPEN_SOURCE, &desc->flags))
		gpio_set_open_source_value_commit(desc, value);
	else
		gpiod_set_raw_value_commit(desc, value);
}

void gpiod_set_value(struct gpio_desc *desc, int value)
{
	VALIDATE_DESC_VOID(desc);
	/* Should be using gpiod_set_value_cansleep() */
	WARN_ON(desc->gdev->can_sleep);
	gpiod_set_value_nocheck(desc, value);
}

void gpiod_set_value_cansleep(struct gpio_desc *desc, int value)
{
	might_sleep();
	VALIDATE_DESC_VOID(desc);
	gpiod_set_value_nocheck(desc, value);
}
```

普通入口的 `WARN_ON(desc->gdev->can_sleep)` 提醒调用者违反 Provider 约束，不能替它创建线程或把当前上下文变得可睡眠；可睡眠入口的 `might_sleep()` 也是上下文检查，不是派发工作任务。`include/linux/gpio/driver.h` 对 `can_sleep` 的契约要求 get/set 会睡眠时必须设置，典型是慢总线扩展器。

前文的方向函数返回 int，调用者可以处理其报告的错误；这里两个 setter 返回 void，不能写成 `ret = gpiod_set_value_cansleep(...)` 再据 ret 判断总线成功。open-drain/source 的内部提交和 Provider 若遇错误，必须按各自实现追踪诊断，不能从这个调用签名发明一条同步错误通道。
