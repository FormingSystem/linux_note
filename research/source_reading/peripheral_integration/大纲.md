# 第1章\_组合外设的资源与事件交接阅读大纲

设备树能够指明连接，实际驱动仍要按正确顺序推进电源、GPIO、总线和中断状态。本专题为已经读过 [组合外设应用](../../../knowledge/driver_model/device_tree/P06_从供电复位到SDIO无线设备枚举.md) 的读者定位固定Linux版本中的兑现路径，不替代GPIO、pinctrl、regulator和串口核心的通用专题。

## 1.1\_从应用阶段进入执行者和状态落点

例如，模块没有枚举时应先查上电之前的执行者，不能直接跳到工作期中断；报文尾部丢失时则要追发送器完成条件，不能只查GPIO初始配置。阅读时先固定这类现场，再用同一组应用阶段定位对象、调用者和失败回退。下面的路径帮助选择调查入口，不要求读者把四种外设都装到同一块板上。

```mermaid
flowchart LR
    A["应用问题与W/C/E/T阶段"] -->|"选定版本及目标分支"| B["总阅读索引"]
    B -->|"找出执行者和状态归属"| C["资源与事件交接导读"]
    C -->|"定位当前交接的唯一实现"| D["pwrseq / OV5640 / PCA953x / i.MX UART"]
    D -->|"检查正常路径与失败边界"| E["回到连接实验及目标验证"]
```

箭头是阅读依赖，不表示这四种设备在同一条硬件流水线上。

## 1.2\_保持实现证据与板上验证的边界

所有实现固定到NXP发布提交，配置为条件性分析；当前目标内核配置和真实接线没有在本轮运行验证。离线DTS实验验证引用关系，源码核对验证所选分支，仪器与设备协议测试才补齐物理输出证据。新增实现标题只拥有本设备的交接分支，不复制通用框架算法。
