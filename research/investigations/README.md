# 第1章\_问题调查入口

本目录接收尚未形成稳定知识结论的问题、假设、故障现象和调查记录。新建笔记先记录问题边界、环境、证据和下一步验证，再根据调查结果归入知识、工程、平台、实验或参考资料。

## 1.1\_调查记录要求

- 明确问题和不确定点。
- 记录软件版本、硬件平台和复现环境。
- 区分事实、推测和结论。
- 保存关键日志、调用链、测试方法和反例。
- 形成稳定结论后，将结论写入唯一权威正文，并由调查记录链接到该正文。

## 1.2\_先选择调查记录还是历史核对源

调查记录服务于一个尚未闭合的问题：读者应能看见证据如何支持、限制或推翻假设。历史核对源则保留旧稿，方便追踪知识点的去向；保留它不等于认可其中全部结论，也不应把旧代码直接当作当前可构建示例。

## 1.3\_怎样让调查结束而不抹去来路

新增记录时，可以从四段正文开始：观察到了什么、哪些条件能够重复它、目前有哪些竞争解释、下一次检查怎样区分这些解释。日志应同时保留操作入口和最早错误，成功与失败都写清版本及配置，不能只留下最后一行摘要。

结论稳定后，把可复用机制放入知识正文，环境差异放入平台或工程记录，可复现实验放入 labs；调查页保留问题、关键证据、被否定的假设及准确去向。不要再复制一份完整权威教程，也不要为使记录显得完成而删除未解决问题。涉及旧稿时按知识点核对迁移位置，保留原始版本；导航更新或自动检查通过不代表旧稿已完成事实审查。
