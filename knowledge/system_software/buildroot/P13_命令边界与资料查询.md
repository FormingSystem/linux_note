# 第13章\_命令边界与资料查询

本篇供读完前面流程后查找命令、目录与错误线索。表中行为按 **Buildroot 2025.02** 核对；它不是一段应从上到下连续执行的脚本，尤其不要为了“试一下命令”清理仍需保留的构建现场。

默认在Linux宿主的Buildroot源码根目录操作。下面变量指向前章已有外部树和一套输出；实际选择其他配置时，两者仍须对应：

```sh
br_ext="$PWD/../lesson_external"
br_out="$PWD/../br_out_disk_lesson_2025_02"
```

完整机制由 [前一章的维护流程](P12_让多套配置和版本升级保持可追溯.md) 收束；固定归档、摘要及原件位置见 [资料基线](../../../research/source_reading/buildroot/SOURCE_BASELINE.md)。

## 13.1\_配置与构建命令的作用范围

同一个make目标会受当前.config、外部树和阶段标记影响。**指定一个包名并不等于无条件从头构建它**；普通make也只构建已选择的系统组成，不保证内核、引导器和所有格式都被启用。

| 要做的事 | 命令 | 关键边界 |
| --- | --- | --- |
| 查看当前版本入口 | `make O="$br_out" help` | 以本版本目标为准，不由名字猜接口 |
| 列出配置 | `make O="$br_out" BR2_EXTERNAL="$br_ext" list-defconfigs` | 包括已接入外部树的入口 |
| 在新输出载入磁盘配置 | `make O="$br_out" BR2_EXTERNAL="$br_ext" lesson_disk_defconfig` | 会改变配置；跨变体使用新O目录 |
| 编辑顶层配置 | `make O="$br_out" menuconfig` | 生成/修改该输出的.config |
| 保存项目defconfig | `make O="$br_out" savedefconfig BR2_DEFCONFIG="$br_ext/configs/lesson_disk_defconfig"` | 覆盖指定输入文件；省略位置时不要假定总写到源码根defconfig |
| 完整构建及更新镜像 | `make O="$br_out"` | 按阶段状态执行，不是每次无条件全量重建 |
| 显示更完整命令 | `make O="$br_out" V=1` | 会实际执行构建；日志捕获应保留失败状态 |
| 取得所选源码 | `make O="$br_out" source` | 下载完成不等于构建、许可检查或完全离线验收 |
| 查询解析变量 | `make O="$br_out" printvars VARS='GNU_TARGET_NAME BINARIES_DIR'` | 本版本printvars要求非空VARS；不把输出当作Shell代码执行 |
| 取得包信息 | `make -s --no-print-directory O="$br_out" show-info` | JSON来自构建元数据，不能代替目标文件扫描 |
| 生成SDK归档 | `make O="$br_out" sdk` | 归档在images，默认名称含目标tuple和_sdk-buildroot；解包后按第三章重定位 |
| 收集许可材料 | `make O="$br_out" legal-info` | 查看legal-info中的README警告和清单，不等于所有发布义务已完成 |
| 生成依赖图 | `make O="$br_out" graph-depends` | 需要对应宿主图形工具；结果位于该输出graphs目录 |

保存defconfig的路径及查找规则见 [固定Makefile](../../../research/source_reading/buildroot/2025.02/Makefile)，包与查询目标见 [make使用说明](../../../research/source_reading/buildroot/2025.02/docs/manual/make-tips.adoc)。第十二章已经给出SDK与外部树的区别，不能把一份项目输入目录直接叫作已构建SDK。

## 13.2\_包阶段与清理命令会改动什么

以下用已经建立的lesson_crc包作实例。先保存失败日志和输入，再决定重建起点；补丁改变后只重跑编译阶段，可能继续使用未重新打补丁的旧源码。

| 命令 | 从哪一层起作用 | 不应据此推断 |
| --- | --- | --- |
| `make O="$br_out" lesson_crc` | 构建并安装包及其必要依赖 | 不保证最终rootfs镜像已重新生成 |
| `make O="$br_out" lesson_crc-source` | 取得包源码 | 不保证网络一定再次访问，也不保证源码已编译 |
| `make O="$br_out" lesson_crc-extract` | 进入源码展开阶段 | 已完成标记可能使它跳过 |
| `make O="$br_out" lesson_crc-patch` | 走到补丁阶段 | 不代表无条件再打一遍补丁 |
| `make O="$br_out" lesson_crc-rebuild` | 重新执行编译及安装流程 | 不是clean加全量构建，不重新展开归档 |
| `make O="$br_out" lesson_crc-reconfigure` | 从配置阶段重新执行后续流程 | 不自动重建全部反向依赖 |
| `make O="$br_out" lesson_crc-reinstall` | 重新执行安装流程 | 不保证源码变化已编译 |
| `make O="$br_out" lesson_crc-dirclean` | 删除该包构建目录 | 不卸载已安装文件，不必重新下载有效缓存 |
| `make O="$br_out" lesson_crc-show-depends` | 列出直接构建依赖 | 不等于完整递归依赖 |
| `make O="$br_out" lesson_crc-show-recursive-depends` | 列出递归构建依赖 | 不等于运行时所有动态库的实际解析结果 |
| `make O="$br_out" lesson_crc-show-rdepends` | 列出直接反向依赖 | 查到列表不等于这些包已自动重建 |

包修复完成后，执行完整 `make O="$br_out"` 更新文件系统和交付物。标准通用包接口没有一个可任意套用的 `<pkg>-clean` 目标；也不要用 `toolchain-dirclean` 假装能正确重置整条工具链依赖。工具链/ABI等系统性变动使用新O目录。依据：[包目标](../../../research/source_reading/buildroot/2025.02/docs/manual/package-make-target.adoc)、[重建范围](../../../research/source_reading/buildroot/2025.02/docs/manual/rebuilding-packages.adoc)。

| 整体清理命令 | 本版本实际范围 | 执行前应保存什么 |
| --- | --- | --- |
| `make O="$br_out" clean` | 删除build、host、target、images、staging等构建输出，保留.config；通常保留下载缓存 | 未导出的子组件配置、临时源码修改、失败现场与需要保留的交付物 |
| `make O="$br_out" distclean` | 在clean之外删除配置、外部树记录及源码树下dl等；默认output还会整体移除 | 同上，并确认共享源码树下载目录的影响 |

自定义DL_DIR不一定是源码树下dl，不能把distclean描述成“无论缓存在哪里都会删除”，也不能因指定O就断言它只接触O目录。精确范围以 [Makefile的clean与distclean](../../../research/source_reading/buildroot/2025.02/Makefile) 为准。

BusyBox等Kconfig组件还有专用编辑/写回目标。`busybox-menuconfig`修改构建中的配置，`busybox-update-config`写回所选项目配置文件；**保存后再清理**。普通包不一定有menuconfig，U-Boot等组件也受所用配置基础设施约束。完整步骤在 [11.7节](P11_沿失败交接点定位构建与运行问题.md#11.7_修复要回到构建输入并验证没有丢失)。

## 13.3\_目录与产物应该由谁消费

表中路径相对br_out。下载目录可另行配置，不默认位于O目录内部；images也只有本次所选格式，不保证一定出现sdcard.img、zImage或SPL。

| 路径或文件 | 主要内容与消费者 | 边界 |
| --- | --- | --- |
| `.config` | 本次顶层配置，供Buildroot解析 | 不包含所有外部源码和板材料 |
| `.br2-external.mk`等 | 当前输出的外部树入口记录 | 不是外部树内容备份 |
| `build/` | 包源码、构建文件与stamp | 临时编辑可能被重新同步/展开覆盖 |
| `host/` | 宿主工具、交叉工具及目标sysroot相关内容 | 其中程序不都运行在目标CPU上 |
| `staging/` | 指向目标开发sysroot的入口 | 头文件和开发库用于编译，不是完整运行根文件系统 |
| `target/` | 安装后的目标目录树 | 缺少最终镜像元数据等处理，不能直接当作可部署根 |
| `images/` | 所选内核、文件系统、磁盘及SDK等产物 | 文件存在不证明是本次成功生成 |
| `images/lesson_delivery/` | 本专题脚本整理的交付目录 | 属于教学项目约定，不是Buildroot默认固定目录 |
| `legal-info/` | 声明驱动的源码、许可及清单收集 | 缺项和准确性须继续核对 |
| `graphs/` | 已执行相关图形目标产生的结果 | 不自动等于性能或正确性验收 |

两个教学启动入口应成对使用：run_qemu.sh读取无分区rootfs.ext4并使用root=/dev/vda；run_qemu_disk.sh读取lesson_disk.img并使用root=/dev/vda1。二者都由QEMU直接加载Image，不经过实体板BootROM和U-Boot。具体布局及只读校验见 [第十章](P10_从文件系统镜像到存储布局与部署验证.md)。

## 13.4\_从症状选择第一项检查

这里给出首个区分动作，避免把一个症状压成唯一原因。完整诊断仍需保留失败命令、输入身份和前面的日志。

| 症状或疑问 | 先核对什么 | 接着阅读 |
| --- | --- | --- |
| 下载失败或摘要不同 | 实际URL、后端、状态码、取得内容和.hash；代理不是源码镜像站 | [11.2.1](P11_沿失败交接点定位构建与运行问题.md#11.2.1_网络代理和源码镜像不是同一项配置) |
| 缺少host工具 | 宿主前置要求，还是包应构建的host依赖 | [11.2.2](P11_沿失败交接点定位构建与运行问题.md#11.2.2_缺少宿主工具和缺少目标依赖要分别处理) |
| 编译器找不到 | 命令中的真实路径、tuple、宿主可执行性及之前工具链阶段是否成功 | [第四章](P04_沿编译链接与运行边界定位失败.md) |
| 镜像空间不足 | 宿主空间、文件系统容量、FAT镜像、分区大小分别核对 | [11.3](P11_沿失败交接点定位构建与运行问题.md#11.3_镜像存在为什么仍不能直接进入启动排查) |
| 固件找不到内核 | 加载命令、设备/分区、文件名、返回值、字节数与格式 | [11.4.1](P11_沿失败交接点定位构建与运行问题.md#11.4.1_固件要消费的格式和地址必须同时成立) |
| 没有控制台输出 | 观察路径、接线/电平、时钟、控制台选择与启动条件 | [11.4](P11_沿失败交接点定位构建与运行问题.md#11.4_控制台上的阶段线索怎样形成候选原因) |
| 无法挂载根或执行init | 设备、分区、文件系统支持、根定位，再查init和解释器 | [11.4.2](P11_沿失败交接点定位构建与运行问题.md#11.4.2_找到根设备和执行init是两次不同交接) |
| 程序存在却不能执行 | 权限、架构、ELF/脚本解释器、动态库及实际镜像 | [11.5](P11_沿失败交接点定位构建与运行问题.md#11.5_应用报告找不到文件时到底在找谁) |
| BusyBox命令缺失或修改丢失 | applet、PATH、安装链接，配置是否写回输入 | [11.7](P11_沿失败交接点定位构建与运行问题.md#11.7_修复要回到构建输入并验证没有丢失) |
| 新文件怎样进入镜像 | 先判断属于应用安装、静态overlay还是元数据 | [第五章](P05_从安装目录到可验证的根文件系统.md) |
| 固定版本为何仍有字节差异 | 时间、路径、工具、随机数据及是否真的重新构建 | [12.5](P12_让多套配置和版本升级保持可追溯.md#12.5_版本固定以后怎样证明可复现) |

另有三个常见命令误区：

- `make -n`存在带加号配方、递归调用等执行例外，不作为只读保证，反例见 [11.8](P11_沿失败交接点定位构建与运行问题.md#11.8_让反例检验诊断是否跳了步骤)。
- 本版本已有包内并行构建，BR2_JLEVEL控制相关并行度；顶层多包并行是另一项实验功能，需要BR2_PER_PACKAGE_DIRECTORIES等条件。不能只加 `-j` 就宣称完成正确加速，见 [common-usage的Top-level parallel build](../../../research/source_reading/buildroot/2025.02/docs/manual/common-usage.adoc)。
- 更新rootfs使用完整make进入既定流程；不要把内部阶段名拼成一个不存在的通用target-rootfs接口，也不要用任意板的写盘命令修复未知启动错误。

## 13.5\_资料入口与版本用途

先根据所用版本找依据，再利用外部资料扩展。在线Stable手册会随发布变化；本专题的长期证据是已登记摘要的2025.02归档及裁出的原件，不靠一个带年份的PDF文件名确定身份。

| 资料 | 用途和边界 |
| --- | --- |
| [本仓库固定资料基线](../../../research/source_reading/buildroot/SOURCE_BASELINE.md) | 2025.02原件、章节依据与实际验证限制 |
| [Buildroot官方文档入口](https://buildroot.org/docs.html) | Stable/Nightly的HTML、PDF和文本入口，使用前确认版本 |
| [官方发布与归档](https://buildroot.org/download.html) | 版本、摘要/签名入口及维护期信息，不能据目录名推定适用性 |
| [官方源码仓库](https://gitlab.com/buildroot.org/buildroot/) | 提交、标签、源码历史与问题追踪；按固定身份阅读 |
| [官方支持入口](https://buildroot.org/support.html) | 邮件列表、历史讨论、IRC/Matrix及问题追踪的当前入口 |
| [Bootlin的Buildroot课程](https://bootlin.com/training/buildroot/) | 独立机构的课程、讲义和实验材料；不是一部另有其名的Buildroot官方书籍 |
| [Mastering Embedded Linux Programming第三版](https://www.packtpub.com/en-us/product/mastering-embedded-linux-programming-9781789530384) | Frank Vasquez与Chris Simmonds，2021；覆盖系统工程，其示例版本另行核对 |
| [Embedded Linux Systems with the Yocto Project](https://www.informit.com/store/embedded-linux-systems-with-the-yocto-project-9780133443318) | Rudolf J. Streif，2016；学习另一套构建体系，不能作为Buildroot接口依据 |

2026-10-18核对官方支持页时，IRC位于OFTC，问题追踪指向GitLab，补丁仍经邮件列表接收。旧站点、视频教程或旧版书中的联系方式与命令可能已经变化；遇到具体问题时先带上版本、完整命令、最小复现输入和首次具体错误，再查当前入口，不承诺社区响应时限。

本目录原有 [buildroot_manual_v2025.pdf](buildroot_manual_v2025.pdf) 保留作为历史附件；仅凭文件名不能证明它对应2025.02，本轮没有用它覆盖固定归档的证据。厂商教程同样应核对板修订、存储介质、BSP版本和实际命令消费者，再决定能否用于当前实验。
