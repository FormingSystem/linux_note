
## 1.10\_kref\_与锁的组合

```text

2. get 前锁保护 lookup。
3. put 前是否还能访问字段。
4. remove/unlink 与最后 put 的顺序。
5. kref_put_mutex()

8. 锁顺序、死锁、睡眠上下文。
```

本章可以承接第 8 章 lookup，也可以为第 10 章 RCU 做对比。

## 1.11\_kref\_与\_RCU

正文：[kref 与 RCU](P10_kref_与_RCU.md)。

定位：专门讲 RCU 查找路径和 kref 生命周期的组合。

重点：

```text
1. RCU 保护读侧遍历，不自动给对象引用。
2. kref 保护拿到引用后的对象生命周期。
3. kref_get_unless_zero() 在 RCU lookup 中的角色。
4. release 前从 RCU 可见结构中删除对象。
5. kfree_rcu() / synchronize_rcu() 与对象内存释放。
6. struct kref 所在内存必须撑过 grace period。
```

本章不要展开 RCU 全体系，只讲 kref 需要的部分。

## 1.12\_kref\_refcount\_t\_kobject\_的边界

正文：[kref、refcount_t 与 kobject 的边界](P11_kref_refcount_t_kobject_的边界.md)。

定位：做概念对比，避免把几个层次混起来。

建议把原来的 “kref 不是 kobject” 扩成边界章节：

```text
1. atomic_t：底层原子计数工具。
2. refcount_t：引用计数安全原语。
3. kref：对象生命周期引用计数封装。
4. kobject：设备模型对象，不只是引用计数。
5. device/class/bus：driver core 的类型化对象和总分结构。
6. device_release/class_release 不是裸 kref 的 my_refobj_release。
7. 为什么不要为了引用计数强行引入 kobject。
```

这章只做对比，不展开 kobject 全体系；重点是避免把裸 kref 示例对象套到 driver core 框架对象上。

## 1.13\_典型错误模式与调试线索

正文：[典型错误模式与调试线索](P12_典型错误模式与调试线索.md#12.1_本章导读_把错误模式归类排查)。

定位：错误清单，不再大段重复前文原理。

建议按 bug 类型组织：

```text
1. 少 get：异步路径 UAF。
2. 少 put：对象泄漏。
3. 多 put：提前 release / refcount underflow。
4. put 后访问：UAF。
5. handoff 后再 get：窗口已经错过。
6. lookup 后无保护 get：悬挂指针。
7. release 里重新发布对象：复活已销毁对象。
8. release 不脱链：全局结构留下悬挂指针。
9. 把 kref 当锁：字段竞争仍然存在。
10. 重复 kref_init：破坏已有引用关系。
```

本章可以加入：

```text
KASAN
KCSAN
lockdep
refcount warning
WARN_ON(!list_empty(...))
```
