# 第1章\_Linux\_对象生命周期集成专题大纲

## 1.1\_从单项机制到组合退出

读者先学[kref框架边界](../kref/P11_kref_refcount_t_kobject_的边界.md#11.1_本章导读_先分清对象层次)、[业务接纳与活动排空](../kref/P30_状态观察与活动接纳模板.md#30.1_LIVE不是一张永久通行证)以及[devres退出依赖](../devres/P02_托管资源与使用者退出.md#2.3_时序与控制流)。本专题的问题是：旧文件仍打开时，怎样结束绑定资源，又保留必要的软件会话？

```mermaid
flowchart LR
    A["引用维持存储"] -->|"不能代替业务接纳"| B["关门与活动登记"]
    B -->|"最后活动形成排空证据"| C["绑定资源先退出"]
    C -->|"依赖私有对象的回调已结束"| D["归还绑定期私有份额"]
    D -->|"旧文件各自结束后"| E["私有对象及桥接最终回收"]
```

| 阅读阶段 | 本篇实际入口 | 得到的结论与下一步 |
| --- | --- | --- |
| 分清拥有对象 | [四条生命线](P01_kobject_device_devres_kref_生命周期集成.md#1.1_必须分开的四条生命线) | 外壳、绑定、资源、会话不是同一计数；继续查退出关系 |
| 组合退出依赖 | [devres清理时机](P01_kobject_device_devres_kref_生命周期集成.md#1.4_devres_何时释放)与[异步接纳](P01_kobject_device_devres_kref_生命周期集成.md#1.5_为什么异步路径不能只_get_device) | 回调也可能持ctx地址；排空之后还要安排绑定份额的归还 |
| 检验旧使用者 | [文件与映射](P01_kobject_device_devres_kref_生命周期集成.md#1.7_文件描述符和_mmap_带来的长生命周期) | 旧文件可保留软件状态，映射访问还需独立协议 |
| 运行组合模型 | [T0～T6与完整C](P01_kobject_device_devres_kref_生命周期集成.md#1.9_完整停机状态机) | 六条顺序轨迹比较资源结束和引用最后归还，再用练习检查误用 |

版本证据分别进入[kref设备导读](../../../../research/source_reading/kref/navigation/P08_device引用与资源退出导读.md#8.1_读者任务与版本)和[devres索引](../../../../research/source_reading/devres/navigation/P01_Linux_6.12_devres源码阅读索引.md#1.1_固定版本与阅读任务)。本篇只组合契约，不复制上游函数体；模型不代替真实锁、映射撤销或目标驱动验证。
