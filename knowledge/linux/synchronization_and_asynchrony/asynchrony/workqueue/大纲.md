# 第1章\_Linux\_工作队列专题大纲

## 1.1\_专题定位

设备事件现场需要快速返回，而后处理可能需要睡眠。专题先建立线程工作队列的最小使用协议，再从“事件不丢、同一回调不重入、旧工作可等待结束”推导其状态与执行资源。主线采用普通线程队列；Linux 6.12 的 WQ_BH 软中断执行模型作为明确分支，不能据工作队列这个名字推断允许睡眠。

沿同一个采样设备逐步增加多生产者、执行中重排、额度限制、内存压力和停止条件。源码事实固定到 NXP linux-imx Linux 6.12.20，不把旧版取消状态或过期参数解释带入当前实现。

## 1.2\_因果学习链

```mermaid
flowchart LR
    A["触发现场不能继续执行"] --> B["把工作描述与执行者分离"]
    B --> C["pending防止同一work重复入队"]
    C --> D["逻辑队列与共享池之间需要独立账本"]
    D --> E["worker pool维持执行能力"]
    E --> F["flush/cancel证明代际完成"]
    F --> G["unbound、rescuer与回收前进"]
    G --> H["热插拔、电源与对象拆除"]
```

1. [工作队列](P01_工作队列.md)：从采样后处理建立线程执行、提交与门控；留下内部如何协调的问题。
2. [异步执行的抽象状态机](P02_异步执行的抽象状态机.md)：依赖最小使用协议，推导事件与执行登记分离，用完整 C 模型观察重排，再建立 S0～S8。
3. [cmwq 对象层次与状态所有权](P03_cmwq对象层次与状态所有权.md)：依赖抽象状态，把各角色落到 work、wq、pwq、pool 与 worker；为投递路线建立地址地图。
4. [work 投递、激活与 pending 合并](P04_work投递激活与pending合并.md)：追踪 queue、active/inactive 和跨 pool 约束。
5. [worker 并发管理与执行循环](P05_worker并发管理与执行循环.md)：解释 worker 睡眠补偿、manager 和工作函数调用边界。
6. [flush、cancel 与颜色代际](P06_flush_cancel与颜色代际.md)：区分等待已有代际、取消一个 work 和永久停止生产者。
7. [unbound、rescuer 与回收前进性](P07_unbound_rescuer与回收前进性.md)：解释 affinity pod、WQ_MEM_RECLAIM 和 mayday/rescuer。
8. [CPU 热插拔、电源管理与生命周期](P08_CPU热插拔电源管理与生命周期.md)：把冻结、CPU 上下线、销毁顺序和诊断收束为工程闭环。
