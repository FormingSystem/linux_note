# 第1章\_Linux\_工作队列专题大纲

## 1.1\_专题定位

工作队列不是一个“把函数扔给线程”的薄包装，而是由 work 状态、workqueue 属性域、pool_workqueue 并发账本、worker pool、kworker、flush 代际和 CPU 生命周期共同组成的异步执行系统。本专题从“触发现场不能继续做慢工作”的缺口出发，逐步推导投递、合并、激活、执行、同步取消和回收前进性。

## 1.2\_因果学习链

```mermaid
flowchart LR
    A["触发现场不能继续执行"] --> B["把工作描述与执行者分离"]
    B --> C["pending防止同一work重复入队"]
    C --> D["pwq管理并发与inactive状态"]
    D --> E["worker pool维持执行能力"]
    E --> F["flush/cancel证明代际完成"]
    F --> G["unbound、rescuer与回收前进"]
    G --> H["热插拔、电源与对象拆除"]
```

1. [工作队列](P01_工作队列.md)：常用 API、属性、delayed work 和 remove 基线。
2. [异步执行的抽象状态机](P02_异步执行的抽象状态机.md)：从事件保存与执行分离推导 S0～S8。
3. [cmwq 对象层次与状态所有权](P03_cmwq对象层次与状态所有权.md)：解释 work、wq、pwq、pool 与 worker 的多对多映射。
4. [work 投递、激活与 pending 合并](P04_work投递激活与pending合并.md)：追踪 queue、active/inactive 和跨 pool 约束。
5. [worker 并发管理与执行循环](P05_worker并发管理与执行循环.md)：解释 worker 睡眠补偿、manager 和工作函数调用边界。
6. [flush、cancel 与颜色代际](P06_flush_cancel与颜色代际.md)：区分等待已有代际、取消一个 work 和永久停止生产者。
7. [unbound、rescuer 与回收前进性](P07_unbound_rescuer与回收前进性.md)：解释 affinity pod、WQ_MEM_RECLAIM 和 mayday/rescuer。
