# 第1章\_等待队列与完成量专题大纲

## 1.1\_专题定位

等待机制必须同时回答三个问题：业务条件保存在哪里，等待者怎样安全地从运行态进入队列，生产者又怎样把“条件可能成立”传播回调度器。等待队列保存等待者而不保存事件；completion 在 simple waitqueue 之外增加 `done` 令牌。两者共享调度唤醒，却不是同一种业务状态。

## 1.2\_因果学习链

```mermaid
flowchart LR
    A["条件暂不成立"] --> B["朴素检查后睡眠会丢唤醒"]
    B --> C["先登记和设状态，再重检"]
    C --> D["生产者先改条件，再wake"]
    D --> E["exclusive额度与长队列成本"]
    E --> F["completion用done保存提前完成"]
    F --> G["swait、拆除与选型边界"]
```

1. [等待队列](P01_等待队列.md#1.3_标准条件等待)：从单槽采样对象建立条件观察、消费重检、生产与停止；再看接口、任务状态和poll边界。
2. [completion 完成量](P02_completion_完成量.md#2.1_completion_解决什么问题)：保存提前完成；用C模型区分令牌、观察与广播，并推导轮次和取消责任。
3. [条件等待的统一状态机](P03_条件等待的统一状态机.md#3.5_逐个关闭检查睡眠窗口)：在持久条件、同步、通知匹配和寿命前提下，用S0～S7比较四个事件到达窗口；区分等待内循环与退出清理。
4. [wait_event 入队与唤醒调用链](P04_wait_event入队与唤醒调用链.md)：映射 `prepare_to_wait_event()`、`schedule()`、`__wake_up_common()` 和 `finish_wait()`。
5. [独占等待、批量唤醒与公平性](P05_独占等待批量唤醒与公平性.md)：解释非独占/独占waiter、惊群与长队列成本；bookmark仅作为分段设计推演，不是固定6.12.20实现。
6. [completion 令牌状态与调用链](P06_completion令牌状态与调用链.md#6.3_S0到S6周期)：把done、swait与任务状态对齐，比较完成者先到、等待者先到及超时边界。
7. [swait、生命周期、调试与选型](P07_swait生命周期调试与选型.md#7.2_不能机械替换)：区分简化队列与两种广播接口，再按真实依赖组织退出与诊断。

Linux 6.12.20 的版本化入口见[等待与完成量源码总阅读索引](../../../../../research/source_reading/waiting_notification/navigation/P01_Linux_6.12_等待与完成量源码总阅读索引.md#1.1_版本边界与阅读任务)。

## 1.3\_完成标准

- 能分别指出业务条件、等待项、任务状态和调度器 runnable 状态保存在哪里。
- 能说明“先登记再重检”怎样关闭丢唤醒窗口。
- 能解释 wake 只是传播条件可能变化，不等于直接交付业务资源。
- 能区分普通 waitqueue、swait 和 completion 的状态与适用边界。
