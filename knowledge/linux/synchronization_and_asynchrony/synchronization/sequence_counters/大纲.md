# 第1章\_序列计数器专题大纲

## 1.1\_专题定位

序列计数器用“读者先复制、最后验证、失败重试”替换读侧加锁，适合写少读多且快照可以安全丢弃的标量状态。它不是一种轻量万能锁：写者串行化、奇偶代际、内存顺序、不可回滚副作用和对象生命周期缺一不可。

## 1.2\_因果学习链

默认先具备[锁的资格与上下文模型](../locks/P03_锁的统一状态与通信周期.md#3.2_它不是单一状态机)；这里改变的是读者取得一致快照的办法，不重讲锁的基本用法。先用单副本证明接受条件，再分别修补访问顺序、读者打断写者及配置差异，最后审查寿命与代价。普通、latch 和关联锁分别使用 S、L、A 阶段编号，避免把同一计数在不同协议中的含义混用。

```mermaid
flowchart LR
    A["读锁稳定快照但需要读侧记账"] -->|短标量能否复制后验证| B["P01 可重试候选与使用契约"]
    B -->|仅写后加版本为何漏检| C["P02 奇偶窗口与接受证明"]
    C -->|真实机器如何维持证明顺序| D["P03 接口与内存顺序"]
    D -->|同CPU读者会阻止写者继续| E["P04 双副本latch"]
    E -->|回到单副本，外部锁及RT怎样协作| F["P05 关联类型与进展补偿"]
    F -->|验证失败也不能撤销失效访问| G["P06 寿命、回绕与选型"]
```

1. [seqcount/seqlock读重试快照](P01_seqcount_seqlock_读重试快照机制.md)：从成对参数更新进入完整初始化/更新/读取协议，先限定可重试数据和读者上下文；下一篇解释为什么这个协议成立。
2. [一致快照的证明模型](P02_一致快照的证明模型.md)：从共享读锁成本和坏快照反例推导奇偶代际、S0～S6与完整C交错枚举；把顺序和写者串行的前提留给下一篇落实。
3. [seqcount读写路径与内存顺序](P03_seqcount读写路径与内存顺序.md)：把前章顺序前提映射到固定版本acquire取证、写窗口与retry，逐项区分raw变体；仍未解决同CPU读者阻止写者继续的问题。
4. [seqcount_latch双副本状态机](P04_seqcount_latch双副本状态机.md)：从NMI自等待推出调用者双副本，用完整C模型区分同CPU暂停与跨CPU交错；最低位选副本，完整计数证明候选资格。
5. [关联锁变体与实时性边界](P05_关联锁变体与实时性边界.md)：回到单副本的外部锁，区别配置相关的指针、检查和RT功能补偿；仍不能由锁关联推出对象寿命。
6. [生命周期、误用诊断与选型](P06_生命周期误用诊断与选型.md)：用合法引用取得、完整C回绕反例、重试成本与检查器覆盖，决定继续用seqcount、latch还是改用其他协议。

版本化实现从 [Linux 6.12 序列计数器源码总阅读索引](../../../../../research/source_reading/sequence_counters/navigation/P01_Linux_6.12_序列计数器源码总阅读索引.md#1.1_版本边界与阅读任务)进入。
