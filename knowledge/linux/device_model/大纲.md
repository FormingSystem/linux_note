# 第1章\_Linux\_设备模型专题大纲

本专题承接[驱动框架入门](../../driver_model/fundamentals/framework_model/大纲.md)，围绕同一份驱动服务两个实例时的登记顺序、失败和撤销展开。前四章先推导职责，再落到固定 Linux 状态地址；后续按对象、绑定、外部入口及依赖逐步检验这些职责。不要把“模块已装载”“设备已登记”“已成功绑定”“对象仍有引用”合成一个成功标志。

## 1.1\_因果阅读地图

```mermaid
flowchart LR
    A[两个实例与一份驱动] -->|到达顺序不固定| B[两集合及后来者查找]
    B -->|加入删除并发与失败| C[引用协调与回滚职责]
    C -->|找到状态地址及写入者| D[Linux登记与绑定过程]
    D -->|加入固件描述和用户入口| E[分别解释对象与可见服务]
    E -->|加入资源及功能依赖| F[停止服务并安全撤销]
    F -->|按状态寻找证据| G[接口选择与排错]
```

## 1.2\_实验与跨专题依赖

第二章的[到达顺序模型](P02_设备模型抽象机制推演.md#2.2_用一个完整程序交换到达次序)可在普通 C11 环境中运行，只验证串行登记规则。进入真实探测前，完成[错误指针与资源失败](../error_handling/error_pointer/大纲.md)，沿其完整模块观察登记成功而探测失败的区别。对象属性与字符入口的基础实验沿驱动框架复用，不在本专题复制另一份教程。

第十一章进入 class/sysfs 的五篇完整分支后，回到第十二章。资源回收的详细机制由[devres 教材](../object_lifetime/devres/大纲.md)承担，设备模型侧解释它在绑定周期中的位置；文件打开、回调和引用的寿命也不能由设备绑定状态代替。

源码基线为 NXP 官方 [`linux-imx`](https://github.com/nxp-imx/linux-imx) 仓库发布标签 `lf-6.12.20-2.0.0`、提交 `dfaf2136deb2af2e60b994421281ba42f1c087e0` 对应的 Linux 6.12.20；本地工作树位置不属于长期证据。主要目录是 `drivers/base/`、`include/linux/device.h`、`include/linux/kobject.h`、`lib/kobject.c`、`fs/sysfs/` 与 `drivers/of/`，统一身份见 [Linux 源码阅读基线](../../../research/source_reading/linux/SOURCE_BASELINE.md)。
