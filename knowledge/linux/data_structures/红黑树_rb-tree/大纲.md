# 第1章\_红黑树学习路线大纲

这组笔记的主线是：

```mermaid
flowchart LR
    concept["P01 层级、路径与子树"] -->|"需要在程序中访问"| repr["P16 表示与完整 C 实验"]
    repr -->|"限定左右位置"| binary["P02 二叉树"]
    binary -->|"先固定访问次序"| visit["P17～P19 三种深度优先遍历"]
    visit -->|"改为同层等待"| breadth["P20 层序队列与容量"]
    breadth -->|"比较等待状态和查询条件"| query["P21 递归状态与基本查询"]
    query -->|"按值排除子树"| bst["P03 搜索树"]
    bst -->|"移走键仍要保持连接"| erase["P22 删除与子树回接"]
    erase -->|"检查全局次序和路径成本"| verify["P23 验证与高度边界"]
    verify -->|"同样数据出现长路径"| balance["P04/P05 退化与旋转"]
    balance -->|"把局部重排纳入平衡规则"| multi["P06/P07 多路模型与红黑表示"]
    multi -->|"落实到接口和内存布局"| kernel["P08～P12 Linux rbtree"]
    kernel -->|"页大小和区间管理增加约束"| wider["P13～P15 多路树与 Maple"]
```

默认依赖顺序是 P01 → P16 → P02 → P17 → P18 → P19 → P20 → P21 → P03 → P22 → P23 → P04～P15。P16 拆出普通树表示；P17～P21 拆出原二叉树长章的四种遍历和基本查询，保留各自手工推演与完整实验。P22/P23 继续承接搜索树的删除与验证。追加编号保持原章节身份，按此依赖阅读即可。

当前章节已经把红黑树理论、Linux 6.12 `rbtree` 源码实现、cached / augmented / RCU / 验证场景基本串完。后续不再单独新增“红黑树插入修复”“红黑树删除修复”的纯理论章节，因为这些内容已经分别被第 6、7、10、11 章覆盖。

## 1.2\_以后写作边界

第 13 章只做扩展和对照，不再重复前面已经讲过的内容。

已经由前文覆盖的内容：

```text
树、二叉树、BST 基础：P01、P16、P02、P17～P21、P03、P22/P23
平衡动机和旋转：第 4-5 章
2-3-4 树的查找、插入、删除：第 6 章
红黑树性质、黑高、插入 / 删除修复目标：第 7 章
Linux rbtree 的工程实现：第 8-12 章
Maple Tree 和 VMA 场景：第 6.10、12.8 节，并由第 14、15 章继续
```

第 13 章只保留四个重点：

```text
1. 为什么从红黑树继续看 B 树 / B+ 树；
2. B 树和 B+ 树的结构差异；
3. 为什么 B+ 树适合页级索引和范围查询；
4. 红黑树、2-3-4 树、B 树、B+ 树在工程场景里的选择边界。
```

第 14 章是一个工程澄清章节，重点不是重新实现 Maple Tree，而是说清楚：

```text
Maple Tree 主要替代的是 VMA 管理中的 rbtree / linked list / vmacache；
它不是整个内核里所有 rbtree 的替代品；
它也不是公平调度从 CFS 走向 EEVDF 的原因。
```

第 15 章开始进入 Linux 6.12 Maple Tree 源码，但只做源码地图和 API 分层，不把 `mas_store()`、节点分裂、gap 更新、VMA 修改路径全部塞进同一章。

第 15 章保留六个重点：

```text
1. Maple Tree 相关源码文件各自负责什么；
2. struct maple_tree、struct maple_node、struct ma_state 的结构语义；
3. mtree_*()、mt_*()、mas_*()、vma_iter_*() 的分层关系；
4. mm_struct.mm_mt 和 vma_iterator 如何接入 VMA 管理；
5. vma_lookup()、find_vma()、find_vma_intersection() 的语义差异；
6. 后续继续拆查找、写入、gap search、mmap / munmap / mprotect 源码的章节边界。
```
