# 第8章\_高级应用

前七章建立了 list_head 的连接与所有权模型。现在打开一个真实子系统，看到 next、prev 或 list 成员，是否可以直接调用 list_add？还不够：子系统通常在连接之外维护长度、锁、回调和引用。绕过它的接口，可能只接好了指针，却漏掉共同状态。

本章是应用阅读参考，以固定版本的实际成员定位为主，不复制等待、网络、分配器或设备模型的完整课程。

版本身份见[链表源码索引](../../../../research/source_reading/linked_list/navigation/P01_Linux_6.12_链表源码阅读索引.md#1.1_版本和阅读任务)，各子系统位置汇总在[模块导读](../../../../research/source_reading/linked_list/navigation/P02_拓扑修改与发布边界导读.md#2.4_读子系统时不要只找next)。

## 8.1\_等待队列保存的不只是任务地址

等待队列解决“条件尚未满足时，怎样登记等待者并在状态变化后通知”的问题。固定版本的 wait_queue_head 有 lock 和 head，wait_queue_entry 有 flags、private、func 与 list_head 类型的 entry。head/entry 管理成员关系，func 决定唤醒动作，private 通常连接相应等待对象。

因此，等待队列既不是普通调度就绪队列，也不只是把 task 指针串起来。应使用 `DECLARE_WAIT_QUEUE_HEAD` 或 `init_waitqueue_head`，再使用等待/唤醒协议；旧稿的 INIT_WAITQUEUE_HEAD 不是本基线接口。wait_queue_t 也不应继续当作当前类型名，本版本使用 wait_queue_entry_t 等定义。

源码定位 include/linux/wait.h，机制主线进入[等待队列](../../synchronization_and_asynchrony/synchronization/waiting_notification/P01_等待队列.md)。本章只确认连接成员与附加状态，不能把一次 list_add 当成完成条件检查、任务状态切换和防丢唤醒。

## 8.2\_网络队列还有长度和专用锁

sk_buff 表示网络包的缓冲描述，sk_buff_head 是包队列头。后者有指向 sk_buff 的 next/prev、qlen 和 lock；这些布局与专用接口协作。不能因为结构看起来双向循环，就绕过 skb_queue_* 系列只改两个连接。

例如 `skb_queue_head_init` 建立空队列状态，`skb_queue_tail` 是对应的尾部入队接口。带双下划线的内部变体通常要求调用者提供相应保护，不能按名称相近随意替换。分配一个 skb 指针变量不等于已经分配包对象，旧稿对未初始化 skb 直接访问成员的片段没有运行前提。

本版本还可能在不同使用场景复用某些连接存储；看见一个可用的 list 成员，也不能同时让相同存储承担另一种队列关系。阅读 include/linux/skbuff.h 时应一起查节点布局、长度更新、锁和出队后的所有权，而不是只搜索 next。

## 8.3\_分配器把不同层级的空闲关系分开

对象缓存负责批量提供同类型对象。一个 slab 是承载多个对象的内存块；“哪些 slab 还有空间”与“这个 slab 内哪个对象空闲”是不同的问题。

固定版本 mm/slab.h 的 struct slab 包含 slab_list 及 freelist 等不同表示，kmem_cache 的 list 又可用于缓存集合关系。不能把所有空闲对象都想成统一的 list_head，更不能向未经分配的 cache 指针写一个假想 free_list 成员。具体的每 CPU、每节点组织和配置差异属于分配器协议。

读源码时先给关系命名：本条链串的是缓存、slab，还是对象？再追踪头保存在哪里、哪个锁或原子状态管理它、分配时怎样转移所有权。这个步骤比对着“Slab 用链表”一句话寻找相似字段可靠。

## 8.4\_设备集合在链表之上叠加引用

设备模型的内部 device_private 保存 knode_parent、knode_driver、knode_bus、knode_class 等不同关系；它们是 klist_node，不是旧稿假设的 device.dev_list。klist_node 内部又有 list_head、kref 和所属 klist 信息，为迭代与对象持有提供封装。

驱动应使用设备模型提供的遍历、取得和归还接口，不从外部直接改私有节点。一个 device 同时属于父设备、总线和类关系，也说明为何不同关系需要不同节点，以及为何从一个集合删除不代表对象立刻消失。

具体例子可回到[class 与 sysfs](../../device_model/class_sysfs/大纲.md)的创建、分类和注销周期；源码字段位于 drivers/base/base.h 与 include/linux/klist.h。仅依据“所有设备串成表”推断热拔插回收，仍会遗漏文件、请求和其他引用。

## 8.5\_读到新容器时的迁移练习

选择上面任一个场景，写出节点类型、头的位置、额外状态、修改接口、使用者和释放条件。若只写出了“有 next/prev”，说明还没读到能够修改它的程度。

以网络队列为例：头是 sk_buff_head，长度是 qlen，锁也保存在头里，操作应经过匹配的 skb 队列协议，出队后的包由具体调用方规则处理。以等待队列为例：连接的 entry 只登记等待者，还需要条件与回调；因此两者不能互换 API。
