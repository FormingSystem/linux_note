# 第1章\_Linux\_MMIO\_顺序专题大纲

## 1.1\_阅读入口

从“配置设备后启动，最后等它完成”这一轮操作进入。先修是[CPU普通内存顺序与同步域](../../synchronization_and_asynchrony/synchronization/memory_ordering/P03_Linux_SMP屏障与顺序域.md#3.1_先按同步域分类)；本专题只建立CPU访问设备时新增的约束。

```mermaid
flowchart LR
    A["寄存器不是普通变量"] -->|"确定地址空间与访问宽度"| B["访问器及默认映射契约"]
    B -->|"有序仍不等于送达"| C["posted write与安全读回"]
    C -->|"送达仍不等于工作完成"| D["C模型分开四个阶段"]
    D -->|"加入共享缓冲与多CPU"| E["DMA门铃和同锁写顺序"]
```

| 阅读阶段 | 解决的问题 | 继续追问 |
| --- | --- | --- |
| [参与者与地址](P01_MMIO_访问顺序与屏障.md#1.1_先区分三种顺序问题) | 编译器、桥和设备分别可能延迟什么？ | 怎样表达合法设备访问？ |

| [送达与完成模型](P01_MMIO_访问顺序与屏障.md#1.4.1_用完整C模型分开送达和完成) | I0～I3为何不是同一个完成点？ | DMA和锁加入后哪些保证还成立？ |

本专题讨论 CPU—设备访问；CPU—CPU 内存顺序由[内存顺序专题](../../synchronization_and_asynchrony/synchronization/memory_ordering/大纲.md)维护。

设备自己访问共享缓冲时，继续[DMA映射与所有权](../dma/大纲.md)；本专题不代替设备寄存器手册，也不把读回某个安全寄存器推广成所有设备通用的操作。
