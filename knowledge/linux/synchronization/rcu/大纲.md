# 第1章\_RCU\_专题大纲

## 1.1\_专题定位

本专题不按“概念、API、字段”平铺，而是复现 RCU 机制被问题逐步逼出来的过程：先看到锁方案的正确性和扩展瓶颈，再自行推出多版本、发布边界和 GP；掌握最小使用协议后，分别解决非抢占式 CPU 证明与抢占式任务跟踪，最后进入完整 Tree RCU 子系统、回调、变体、应用和验证。

```mermaid
flowchart LR
    A["P01<br/>锁方案的价值与缺口"]
    B["P02<br/>推演发布边界与GP"]
    C["P03<br/>最小API使用闭环"]
    D["P04<br/>RCU与kref生命周期组合"]
    E["P05-P06<br/>非抢占式CPU证明"]
    F["P07-P08<br/>抢占式任务债务"]
    G["P09-P10<br/>现实约束与统一总图"]
    H["P11-P21<br/>Tree RCU实现纵深"]
    I["P22-P24<br/>实现家族与私有域"]
    J["P25-P28<br/>应用、类型、验证与选择"]

    A -->|"为什么不能只靠读写锁"| B
    B -->|"抽象动作怎样落到API"| C
    C -->|"裸指针怎样变成长持有"| D
    D -->|"先固定对象销毁协议"| E

    F -->|"加入idle、乱序和慢路径"| G

```

默认阅读顺序就是文件编号。P03、P04 不再被放到子系统源码之后：先会正确使用和描述对象生命周期，才能判断后续源码到底在保护哪一个时间窗口。P05/P06 与 P07/P08 成对出现，每种模式都先讲具体反例和证明，再讲字段与调用链。

## 1.2\_阶段一\_从现实问题到最小使用闭环

### 1.2.1\_为什么需要RCU

[为什么需要 RCU](P01_为什么需要_RCU.md)以互斥锁、读写锁和“只原子换指针”三种方案为同一场景基线，解释共享写热点、旧指针 UAF 和成本转移。

- 前置：基本锁、缓存一致性和指针概念。
- 本篇解决：RCU 为什么值得存在，正确性成本被移到了哪里。
- 留给下一篇：如果不看 Linux API，怎样从约束推出完整机制。

### 1.2.2\_抽象机制推演

[RCU 抽象机制推演](P02_RCU_抽象机制推演.md)用路由版本更新的代码现场，依次推出不可见构造、发布边界、旧 reader 集合、GP 和退休结果交付。

- 前置：P01 的锁方案与对象删除问题。
- 本篇解决：GP 等谁；已排队但尚未读取入口的未来 reader 为什么不属于旧集合。
- 留给下一篇：这些抽象动作对应哪些 Linux API，裸指针究竟是什么。

### 1.2.3\_通用API与最小闭环

[RCU 通用 API 与最小使用闭环](P03_RCU_通用API与最小使用闭环.md)给出完整 reader、同步 writer、异步 writer、模块退出代码，并明确 `rcu_dereference()` 返回同一对象地址，不复制对象。

- 前置：P02 的发布和 GP 边界。
- 本篇解决：接口顺序、同步/异步回收、晚到 reader、指针逃逸和第二入口误用。
- 留给下一篇：需要把对象或子块带出读区时，谁继续提供生命期。

## 1.3\_阶段二\_RCU与对象所有权组合

[RCU、kref 与复合对象生命周期](P04_RCU_kref与复合对象生命周期.md)不再把 `kref` 当 RCU 内建适配。它先区分 RCU、kref 和对象模块三方职责，再给出三种不能互相套用的完整代码模型：

1. 单个 RCU 对象在读侧内取得长期 kref；
2. 共享入口持有一份跨 GP 的发布引用；
3. 一个 RCU 版本根拥有多个分别带 kref 的分散数据块，GP 后由根逐块 `put`。

- 前置：P03 已经掌握 RCU 临时访问范围。
- 本篇解决：RCU 如何与 kref “牵手”、为什么二者彼此无感、谁是唯一销毁出口、读多时怎样避免逐块 get/put。
- 留给下一篇：不依赖对象地址和引用计数，RCU 自己怎样证明旧 reader 已经结束。

## 1.4\_阶段三\_非抢占式Tree\_RCU

### 1.4.1\_问题与证明模型

[非抢占式 Tree RCU 的问题与证明模型](P05_非抢占式_Tree_RCU_问题与证明模型.md)固定 CPU0 writer、CPU1 旧 reader、CPU2 晚到 reader 的现场，穷举 GP 开始瞬间的 CPU 状态。

- 前置：P02 的时间边界与 P03 的使用协议。
- 本篇解决：`rcu_read_lock()` 为什么不必登记 reader 身份；一次合法 QS 为什么能排除该 CPU 上的既有旧 reader；未来 reader 为什么无需等待。
- 留给下一篇：QS 债务实际存在哪里，怎样从本地状态传播到根并唤醒 writer。

### 1.4.2\_源码同步机制

[非抢占式 Tree RCU 源码同步机制](P06_非抢占式_Tree_RCU_源码同步机制.md)把同一周期划分为 S0～S10，映射到 `rcu_state.gp_seq`、`rcu_node.qsmask`、`rcu_data.cpu_no_qs`、scheduler、context tracking 与 callback completion。

- 前置：P05 的 CPU 证明不变量。
- 本篇解决：GP 请求、初始化、CPU 感知、QS 锁存、异步上报、树形清位、cleanup 与等待者唤醒的完整源码链。
- 留给下一篇：若旧 reader 能在临界区内被换出，单靠 CPU QS 为什么失效。

## 1.5\_阶段四\_抢占式Tree\_RCU

### 1.5.1\_问题与任务跟踪模型

[抢占式 Tree RCU 的问题与任务跟踪模型](P07_抢占式_Tree_RCU_问题与任务跟踪模型.md)让已取得 `old_obj` 的任务被高优先级任务抢占，并在另一 CPU 恢复。

- 前置：P05/P06 的 CPU 债务模型。
- 本篇解决：为什么必须把“CPU 债务”和“任务债务”拆开；债务怎样在 context switch 时从本地执行现场转入共享登记；为什么 PREEMPT_RCU 不等于允许主动睡眠。
- 留给下一篇：任务字段、链表边界和最终 unlock 怎样兑现这次状态归属转移。

### 1.5.2\_源码同步机制

[抢占式 Tree RCU 源码同步机制](P08_抢占式_Tree_RCU_源码同步机制.md)追踪 `task_struct.rcu_read_lock_nesting/rcu_blocked_node`、叶节点 `blkd_tasks/gp_tasks`、CPU `qsmask` 和 `rcu_report_unblock_qs_rnp()`。

- 前置：P07 的两类债务和迁移场景。
- 本篇解决：GP 开始前后被抢占的任务如何纳入；CPU 位已清时任务为何仍阻塞节点；迁移后的 unlock 怎样回到原叶节点并恢复树形传播。
- 留给下一篇：CPU user/idle、缓存一致性、内存乱序和长时间不报告如何完善两种基础模式。

## 1.6\_阶段五\_现实约束与统一全景

### 1.6.1\_硬件与运行约束

[RCU 机制完善：硬件与运行约束](P09_RCU_机制完善_硬件与运行约束.md)用共享写热点、抢占迁移、EQS、分层汇聚、迟延参与者和内存乱序逐个检验朴素模型。缓存一致性、访问原子性和 release/acquire 的完整教程留在各自权威专题，本篇只保留 RCU 特有因果和链接。

### 1.6.2\_统一状态与通知总图

[Tree RCU 统一状态与通知总图](P10_Tree_RCU_统一状态与通知总图.md)在读者已经分别理解非抢占和抢占模式后，把每任务、每 CPU、每节点和全局状态放进一条端到端周期，比较正常报告、共享状态观察、FQS、IPI、boost、callback 与唤醒路径。

P09 的问题是“真实环境又击穿了哪些假设”；P10 的问题是“成熟 Tree RCU 把新增状态和通信放在什么位置”。

## 1.11\_完整性验收

读完默认主线后，读者应能不靠口号回答：

1. writer 在什么时刻封闭 `old_obj` 的未来 reader 集合；
2. 已排队但尚未读取入口的任务为何不属于当前 GP；
3. 非抢占式模型为何按 CPU 等一次有效 QS，抢占式模型为何还要登记具体任务；
4. CPU 本地 QS、叶节点清位、父节点汇聚与根完成之间允许哪些异步窗口；
5. `synchronize_rcu()` 的等待对象保存在哪里，谁最终唤醒它；
6. RCU 与 kref 为什么彼此无感，单对象和多块旧照为什么有不同销毁顺序；
7. FQS、IPI、stall 与 boost 解决的是活性还是安全性；
8. 对一个真实对象，如何画出入口、临时访问、长期引用、回调和唯一最终销毁出口。

横向专题：[seqcount/seqlock](../sequence_counters/P01_seqcount_seqlock_读重试快照机制.md)、[kref 与 RCU](../../object_lifetime/kref/P10_kref_与_RCU.md)、[Linux 内存顺序](../../memory_ordering/大纲.md)。
