# 第1章\_驱动框架学习地图

从已会装载的 Hello 与字符节点进入本单元。我们沿“多个实例如何复用代码 → 登记与绑定怎样分开 → 对象如何变得可见 → 小服务如何发布字符入口”前进；这里的框架基础是进入完整设备模型的桥梁。

## 1.1\_四个问题怎样接起来

```mermaid
flowchart LR
    a["前言：实例和操作为什么分开"] -->|"需要知道关系存放在哪"| b["P01：对象关系与绑定周期"]
    b -->|"缩小到一个可见属性"| c["kobject：创建、读取与拆除"]
    c -->|"改为一般字符服务"| d["misc：共享分派与文件引用"]
    b -->|"进一步研究依赖与热拔插"| e["设备模型专题"]
```

## 1.2\_前置与后续入口

模块构建按[工程四章](../../../../engineering/build/kernel_modules/大纲.md)，错误路径按[错误指针单元](../../../linux/error_handling/error_pointer/大纲.md)。两份可编译模块和只读观察脚本在[实验材料](../../../../labs/kernel/driver_entries/materials/README.md)；操作与解释均在上述正文。

完成 misc 后，沿[文件操作教材](../../file_operations/大纲.md#1.1_沿对象寿命逐步增加约束)用三个完整实验追踪打开上下文、请求位置和映射引用。这一步补足旧打开者的基本寿命模型，再进入硬件可撤销时的设备模型。

需要组合对象属性与字符入口时，沿[class 与 sysfs 分支](../../../linux/device_model/class_sysfs/大纲.md#1.1_从分类观察到可控数据入口)先区分类对象与节点，再用同一实例的两个回调观察校验、同步和撤销。

进一步沿[设备模型专题](../../../linux/device_model/大纲.md)研究依赖、匹配与热拔插，沿[生命周期集成](../../../linux/object_lifetime/integration/P01_kobject_device_devres_kref_生命周期集成.md)分清对象、绑定、资源和打开者。版本源码从[总阅读索引](../../../../research/source_reading/driver_entries/navigation/P01_Linux_6.12_驱动入口源码阅读索引.md)进入；不把参考资料中的字段列表当作主线阅读顺序。
