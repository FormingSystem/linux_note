# 第1章\_设备树与平台驱动阅读入口

设备树把板上的资源与连接表达为固件描述，平台驱动模型负责把设备实例和驱动接起来。二者相互协作，却不是同一个机制：没有设备树也可以注册 platform_device，有设备树节点也不保证一定创建 platform_device。

本目录以 C 读者为对象，先用无硬件的设备/驱动配对建立模型，再用离线 DTS 实验学习编码，最后进入各类资源与引用生命周期。完整顺序、每章前提和跨专题入口见 [专题大纲](大纲.md#1.1_沿描述怎样成为可用资源逐步阅读)。

## 1.2\_实验与平台材料怎样使用

P01、P02 提供平台模块的最小例子；P03、P04、P07、P08 提供可在主机离线编译的 DTS；P06、P09 提供依赖目标内核构建环境的 consumer 模块。正文分别说明执行前提、预期结果与未完成的硬件验证，不能把离线编译通过当成目标板已运行。

板上 GPIO、复用、供电与时钟连接要以具体 SoC 和原理图为准。需要 i.MX6ULL 的完整 LED 文件接口时，进入 [字符设备 LED 与设备树实验](../../../labs/platforms/nxp/imx6ull/drivers/P01_LED点灯/P03_字符设备_LED与设备树完整实验.md)；通用字符设备机制由其专题维护。目录中的历史专题文章作为补充入口列在大纲中，默认学习顺序沿 P01～P09，避免先把某一厂商的编码当成全平台规则。
