# 第1章\_2026-08-02\_Windows\_x86\_64\_实际结果

## 1.1\_环境

| 项目 | 值 |
| --- | --- |
| OS/目标 | Windows x86-64 MinGW/LLVM 默认目标 |
| GCC | `gcc.EXE 14.2.0 (x86_64-posix-seh-rev0)` |
| Clang | `clang 18.1.8` |
| 选项 | `-O0/-O2 -S -fno-asynchronous-unwind-tables -fno-ident` |

## 1.2\_GCC\_14.2\_O2

普通两次读取被合并为一次 Load 后加倍：

```asm
plain_sum:
    movl shared(%rip), %eax
    addl %eax, %eax
    ret
```

ONCE 形式保留两次 Load：

```asm
once_sum:
    movl shared(%rip), %eax
    movl shared(%rip), %edx
    addl %edx, %eax
    ret
```

普通轮询只在循环前读取一次，读取为 0 后循环中没有内存访问：

```asm
plain_poll:
    movl shared(%rip), %eax
    testl %eax, %eax
    je .L6
    ret
.L6:
    jmp .L6
```

ONCE 轮询在循环回边重新读取：

```asm
.L8:
    movl (%rdx), %eax
    testl %eax, %eax
    je .L8
```

## 1.3\_Clang\_18.1\_O2

Clang 得到相同机制结论，但第二次 ONCE 读取直接作为 `addl` 的内存操作数：

```asm
plain_sum:
    movl shared(%rip), %eax
    addl %eax, %eax

once_sum:
    movl shared(%rip), %eax
    addl shared(%rip), %eax
```

`plain_poll()` 同样在循环前只读取一次；`once_poll()` 的循环条件直接比较内存：

```asm
.LBB3_1:
    cmpl $0, shared(%rip)
    je .LBB3_1
```

## 1.4\_结论边界

本次结果证实：在这两个编译器和选项下，普通表达式的读取会被合并/寄存器化，实验版 ONCE 形式保留所需访问实例。

它没有证明：

- ONCE 是 acquire 或 release；
- 另一个 CPU 会立即观察到写入；
- 访问在任意宽度和对齐下不撕裂；
- 普通竞态符合业务协议。
