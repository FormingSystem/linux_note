# 第1章\_i.MX6ULL\_LED实验阅读路线

这组三篇实验沿同一颗低有效 LED 逐步回答三个问题：寄存器中的一个位怎样影响引脚，Linux 如何分配这些硬件责任，以及自定义文件接口怎样在设备解绑时停止访问硬件。板级接线以实际原理图为前提；GPIO1_IO03 是文中的条件示例，不代表所有 i.MX6ULL 板都接有同一颗灯。

## 1.1\_从硬件条件走到软件交接

```mermaid
flowchart LR
    A[数据位还不足以点灯] -->|补时钟 方向 复用 电气条件| B[寄存器与资源归属]
    B -->|映射不等于拥有硬件| C[设备树连接已有提供者]
    C -->|标准LED接口已经可用| D[按学习需求增加字符设备]
    D -->|旧文件跨过解绑| E[分离硬件可用期与对象寿命]
```

| 顺序与章节 | 进入时已经知道 | 本章解决的问题 | 留给下一步的问题 |
| --- | --- | --- | --- |
| [第一章：寄存器、ioremap 与共享位更新](P01_LED点灯+ioremap.md) | C 的位运算和普通变量 | 本地寄存器/PAD 表、硬件关系图、共享读改写交错；运行完整宿主 C 模型 | 谁统一管理真实控制器和线路 |
| [第二章：设备树连接 GPIO LED](P02_LED点灯+dts.md) | 映射与资源所有权不同 | 用标准 gpio-leds 接入板级描述，理解逻辑极性、引脚宏、部署与分层观察 | 若自定义文件协议，如何处理打开文件与解绑 |
| [第三章：字符设备与解绑完整实验](P03_字符设备_LED与设备树完整实验.md) | GPIO 描述符与字符设备打开实例 | 完整命令解析、模块、设备树、构建及跨解绑用户程序；沿 S0～S5 解释锁与引用 | 若增加异步闪烁、PWM 或按键，须新增取消/事件与硬件能力合同 |

只需要标准点灯时，可以在第二章完成目标；第三章用于学习驱动接口与生命周期，不是所有 LED 都必须采用的产品设计。材料在 [materials](materials) 中，正文同时保留当前单元的完整代码与命令。

## 1.2\_区分主机观察与目标板证据

第一章的 C 模型只修改宿主变量，展示位更新与输入边界，不执行真实 MMIO。第二、三章的部署和用户操作需要匹配目标内核、实际 DTB 和已核定接线；正文没有把静态源码检查、模型输出或历史日志写成开发板实测。

本组硬件字段以 NXP `IMX6ULLRM` Rev.1 为依据，软件接口以 NXP Linux 6.12.20 的固定提交 `dfaf2136deb2af2e60b994421281ba42f1c087e0` 为依据。必要地址、字段、协议和状态交接已经在正文给出，原件与源码链接承担追溯职责。

通用原理继续阅读 [GPIO 专题](../../../../../../knowledge/driver_model/gpio/大纲.md)、[字符设备专题](../../../../../../knowledge/driver_model/character_device/大纲.md) 与 [kref 对象持有](../../../../../../knowledge/linux/object_lifetime/kref/大纲.md)。本组保留 i.MX6ULL 的接线与寄存器约束，不把平台实验复制成另一套通用教程。
