# 第1章\_i.MX6ULL按键Input实验路线

前置 [按键中断与唤醒实验](../P03_KEY_LED_interrupt/大纲.md) 已经解释边沿、稳定状态和电源交接。这一组继续追踪状态怎样离开硬件驱动，经过 Input core 与每个打开实例的独立队列，到达用户程序；再用初始已按住、重复、丢失和设备退出检验这条链。

## 1.1\_先形成事件来源\_再建立可信的用户副本

```mermaid
flowchart LR
    A[GPIO逻辑状态已确认] -->|替换驱动内部翻灯动作| B[注册Input并上报状态]
    B -->|不同程序消费速度不同| C[evdev各客户端独立队列]
    C -->|打开时没有完整旧历史| D[查询当前状态再读增量]
    D -->|队列失步或设备断开| E[重同步或明确退出]
```

| 章节 | 依赖与当前问题 | 完成后能够解释 | 尚不能据此保证 |
| --- | --- | --- | --- |
| [第一章：从稳定按键到Input事件](P01_从稳定按键到Input事件.md) | 已知安静期限、代次和退出交接；现在把状态交给公共接口 | 逻辑极性、初始报告、能力声明、工作中上报以及devres逆序停止 | 实际板级电气、完整PM协议、用户永不丢事件 |

第一章提供完整自写运行态模块及设备树，第二章提供完整目标 Linux 用户程序；[materials](materials) 便于取用，正文保留代码和操作解释。只需要通用硬件按键与系统唤醒时，可使用前置组的标准 gpio-keys，不必采用教学模块。读取器可观察两者，但同一个 GPIO 不能同时绑定两个消费者。

## 1.2\_把模型检查与板级观察分开

本组按 NXP Linux 6.12.20 固定提交 `dfaf2136deb2af2e60b994421281ba42f1c087e0` 核对接口。实际函数控制流桩验证人为安排的状态与错误分支，ARM 前端检查验证相应头文件下的语法；它们都没有执行真实 evdev ABI、IRQ 并发和开发板电气。旧日志保留在第二章，仍属于旧配置的历史观察。

通用机制、复杂输入设备和源码证据分别从 [Input专题](../../../../../../knowledge/driver_model/input/大纲.md) 与 [Input源码索引](../../../../../../research/source_reading/input/navigation/P01_Linux_6.12_Input源码阅读索引.md) 继续。本实验保留板级约束和完整程序，不把通用机制重新维护成另一套权威正文。
